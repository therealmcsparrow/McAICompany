# Playbook: feedback

**Help:** argument is exactly `help` or `--help` → do the **Type:** step below first; then read `documentation/commands/feedback.md` (plugin root = two folders above this skill's base directory) and reply with its usage, options, what it does and an example, in the language of `aico:pipeline` §1.6; change nothing, start nothing, and stop.

**Type:** run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" company-type check-playbook feedback` first; exit not 0 → show its output line and stop.

Run with `aico:pipeline`. No Plan or Ship Gate: nothing is built or shipped. Read-only: no builders.

1. Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" company-type pick support account-manager product-manager`; the one slug it prints triages the reports into clusters in `.company/work/<slug>/feedback-report.md` (`pick` refused → show its line and stop). Run `check-role <slug>` before the dispatch. If a cluster looks security-related, stop and ask the CEO in a form whether to start `incident` (only when the `playbooks` type line lists it; else tell the CEO to handle it outside this run).
2. Cost numbers: for the last 3 runs in `.company/ledger/` (newest first) run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" ledger report <run>` from the repo root. Keep two lines apart: **spend** (`in + cache_write + out`) and **cache read**, each per shipped AC. Never add them. A run with no ledger or `not reconciled` is named as such, never guessed. Put the lines in `feedback-report.md` under `## Cost`.
   Speed: list `.company/ledger/*.jsonl`, newest first, and skip every file whose name starts with `brainstorm-`, `replay-` or `baseline-`. For the newest remaining one run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" ledger scorecard <run>` (no `--baseline`); `<run>` is the file name without `.jsonl`, only if it matches `^[a-z0-9][a-z0-9-]{0,63}$`. If it prints `no ship record`, try the next file, up to 3 tries in all. Put the last line printed, unchanged, under `## Speed` in `feedback-report.md`, as a plain sentence under a real heading. `no ship record`, `no ledger` or an error is quoted as it is, never guessed. It never stops the run.
   Plan check: run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" plan-check-verdict verdict --runs <N>`, with `<N>` = `plan_check.runs` from the run's §1.7 `get` JSON when it is a whole number from 3 to 50, else 5 (digits only, never from report or Handoff text). Put the one line printed, unchanged, under `## Plan check` in `feedback-report.md`, as a plain sentence under a real heading. An error is quoted as it is, never read as a pass, and never stops the run.
   Model: run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" ledger model-verdict` (no arguments). Put the one line printed, unchanged, under `## Model` in `feedback-report.md`, as a plain sentence under a real heading. It never stops the run; an error is quoted as it is, never read as a pass.
   Parallel: run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" ledger parallel-verdict` (no arguments). Put the one line printed, unchanged, under `## Parallel` in `feedback-report.md`, as a plain sentence under a real heading. It never stops the run; an error is quoted as it is, never read as a pass.
   Low path: run node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" ledger low-path-verdict --runs 10 (fixed). Put both lines printed, unchanged, under ## Low path in feedback-report.md, as plain sentences under a real heading. It never stops the run; an error is quoted as it is, never read as a pass.
   Cited: run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" cited report --runs 10` (fixed). Put every line printed, unchanged, under `## Cited` in `feedback-report.md`, as plain lines under a real heading. `keep` Roles are never removal candidates; only the CEO decides a removal, from the `never cited` lines. It never stops the run; an error is quoted as it is, never read as a pass.
3. `aico:product-manager` (`check-role product-manager` first): read the clusters, the `## Cost` lines and the success metric in `.company/project.md`, rank the top 5, and propose a fix or feature for each.
   **→ Brief Gate** (the CEO picks in a form, `multiSelect`)
4. Lessons: each lesson from the reports or the run is filed with `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" lessons accept --role <role> --class <mechanical|judgement> --target <target> --text <text>`, only after the CEO accepts that one lesson. A failure a script could catch (`mechanical`) proposes a check: target `check: <script|lint|test> <name>`. A failure that needs a reader's call (`judgement`) goes to the ruleset or review skill: target `standard: .company/standards.md`, `standard: skills/review/SKILL.md` or `standard: skills/review/references/<name>.md`. Lessons never go to CLAUDE.md, AGENTS.md or an agent prompt; the script refuses those targets.
5. You (the Lead) tell the CEO which runs of the `work:` type line Playbooks to start (`fix` and `feature` for software). Never start them yourself.
