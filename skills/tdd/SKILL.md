# TDD

**Use** `superpowers:test-driven-development` if it's in your skill list; the rules below apply either way.

**Loop:** write one failing test for the behavior → run it and see it fail for the right reason → write the minimal code to pass → run it green → refactor → repeat. No production code without a test that failed first. For Contracts, test only the public interface (`aico:contracts`).

**A good test** checks behavior through the public interface and reads like a spec: its name says what the caller can do ("user can check out with a valid cart"), not how the code does it. It survives a refactor that keeps the behavior. One logical assertion per test.

**Implementation-coupled tests** break on a refactor while the behavior holds: they test private methods, mock your own modules, assert call counts or order, or check through a side channel (querying the database instead of reading back through the interface). Rewrite them at the seam.

**Code comments are about the code only.** A comment explains what the code next to it does or why. Never put Handoff notes, Step or task references, Role names, Fix-round or reviewer notes, AI or agent mentions ("generated by", "Claude", "TODO for the next Step"), or company process in product code, tests or config. That belongs in `.company/` only (`aico:handoff`). New comments use the `Language:` of your dispatch unless the codebase's existing comments or Ruleset use another (`aico:handoff` Language).

**Scoped test runs.** During a Step, run only the test files that cover the files you changed, plus `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" check` (or the product's check). Never start a full suite run in the background, and never one while another Role may be running one in the same tree. The Lead runs the full suite once, in the foreground, after the last review (`aico:pipeline` §6); CI runs it on the PR.

**Seams, one slice at a time** (`plan-tasks` v1.3). Test only at the task's `seams:` from the Task brief; `seams: none — <reason>` means no tests. Work in vertical slices: one behaviour from the task's `slice:` line, one failing test, run it red, minimal code to green, then the next. Never write all tests first. A test needed outside the seams goes under `## Decisions` with its reason.

**No tautological tests.** A test must fail when the behaviour breaks. Never assert on the test's own setup or fixture, never restate the code under test in the expectation, never mock the unit under test, and never assert only that a mock was called. Expected values come from an independent source: a known literal, a worked example, the spec; never recomputed the way the code computes them.

**Mock only at system boundaries:** external APIs, time and randomness, and the database or file system when a real test instance is not practical. Never mock your own modules. Pass boundary clients in rather than building them inside the code, and give each external operation its own function (`getUser`, `createOrder`) rather than one generic fetcher, so each mock returns one shape with no logic of its own. `aico:review` blocks such a test as `[test]`.
