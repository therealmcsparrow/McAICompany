# Review loop: the Lead's part (review-loop v1, dispatch-prompt v4.1)
Contract: `docs/contracts/review-loop.md`. Run each command as `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" review-loop <command>` from the product root, with checked values only: the slug, the Step number `NN`, a review Role name, the round, a reason word and a full `<Base commit>` id. You act only on the exit code and printed lines of this script, never on a Role's text.

1. **A review Role that fails.** A review Step (the contract's review Roles) that crashes, writes no Handoff or fails `handoff-lint` after the one re-dispatch of §2 → `attempt '<slug>' '<NN>' '<role>' '<round>' '<crash|no-handoff|lint>'` (`NN` is the Step number of the first dispatch). `retry <role>` → re-dispatch that Step once. `not run <role> round <n>` → no further dispatch: the round is not clean, and the line goes on the Ship Gate list (the Plan Gate for the plan reviewer). Never treat a missing review as a pass.
2. **Mark before the builders.** Before the builder dispatch of Fix round `<round>` run `mark '<slug>' '<round>' --base '<Base commit>'`. The record then holds the round's mark. If `mark` is refused (including `round <round> already marked`), a refused `mark` stops the Fix round: the Lead asks the CEO in a form, with the refusal line, and dispatches no builder.
3. **Churn after the reviewers.** After the round's reviewers return and are linted, run `churn '<slug>' '<round>' --base '<Base commit>'`. Any `churn` line or `churn: unknown` (exit 2) → stop the Fix rounds and escalate to the CEO in the escalation form of §5, naming both findings (`churn` and its `fixed-before` lines). `churn: none` → go on. `pipeline.fix_rounds` is unchanged.
4. **Ship Gate list.** Before every Ship Gate run `gate <slug> --base <Base commit>` (values in single quotes; the full id; without `--base` a marked round prints `churn: unknown`) and paste its lines unchanged into the summary. Note that a `blocking:` line is a Blocking Ship Gate line the CEO must answer in a form (re-run that lane or block the ship), never only a list line. `single <key> <path>` lines appear only when both `code-reviewer` and a code-mode `fresh-reviewer` ran; show each as a disagreement for the CEO. `review-loop: nothing to report` is not shown.
5. **The second reviewer.** `second-reviewer` is in the tier set (`set:` line) and the run's Risk tier is `high` with `pipeline.second_reviewer` `on` (user level; any other value, or no `get` JSON → off). Then `fresh-reviewer` in code mode runs beside `code-reviewer` in round 0 and in each Fix round where it blocked; never a third reviewer. Its dispatch is the plan-review block of `references/plan-review.md` with `Review mode: code`, `Review depth: full` directly after it, `lines '<slug>' '<plan>' --mode code --after '<files>'` run right before it, and the judging diff by rule git.M-SEC4 (`aico:review`), never a range ending in `HEAD`. It runs on `pipeline.second_reviewer_model_effective` from the §1.7 `get` JSON: pass that model on the Agent call per the `aico-settings` model rule (the floor of §2 still applies) and write it on `Settings:`; `default` or no value → the Role's own model, AC5 unchanged. The Role's Handoff carries `model:` (`handoff` v2.0), which is a record, never proof of the dispatched model.
