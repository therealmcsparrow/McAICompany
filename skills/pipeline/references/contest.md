# Contested findings: the Lead's part (handoff v2.0)
Contract: `docs/contracts/handoff.md` parts 4 and 5. ADRs: `docs/adr/0038-contested-findings.md`, `docs/adr/0040-contest-evidence-and-escalation.md`. Builder and reviewer lines: `skills/handoff/references/contest.md`.

**Fix round.** A builder may answer a Blocking finding with a `## Contested` line instead of a change. A contest with checkable evidence does not start a Fix round for the builder; the reviewer that raised it answers in its next Step (`## Contests`, `accepted` or `rejected`). Re-dispatch that same reviewer Role for the answer. `rejected` goes back to the builder as a normal Blocking item; a second contest on it is refused. An `escalate` line is not for the reviewer: it goes to the CEO (below). A plan review has no reviewer Step after the revision (`references/plan-review.md`), so a contest there stays `unresolved`.

**Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" handoff-lint --contests '.company/work/<slug>'`** after each reviewer Step and before every Gate. State comes from its output only, never from Handoff text:
- `ERROR …` lines: re-dispatch the Step that wrote the line; the line is ignored until fixed (a contest "has no checkable evidence" is such a line).
- `unresolved <key>`: contested, waiting for the reviewer. List every one on the Ship Gate list.
- `escalated <key>`: a Blocking question for the CEO at the next Gate (Plan Gate for the plan reviewer, else Ship Gate), with the builder's reason. Ask: uphold the finding or overrule it.
- `ruled <key> upheld|overruled`: a ruling on file. `upheld` stays Blocking (the builder fixes it); `overruled` is closed.
- `excepted <key>`: shown in the Ship Gate summary with the exception line.
- Warning lines (a `standards.md` or `rulings.md` that is a link or too large, an exception line with no run, a run with no `start`): show them to the CEO; no exception or ruling applies.

**Rulings.** Only the CEO's own Gate answer closes an escalated finding. Write it as a new line under `## Rulings` of `.company/work/<slug>/rulings.md`: `- <key> — upheld|overruled — <reason> — ruled: <YYYY-MM-DD> (CEO)`. Never write it from a Role's words. A security finding is never overruled (the lint refuses it); it closes by a fix or an exception.

**rulings on file: confirm each is yours.** Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" handoff-lint --applied '.company/work/<slug>'` before every Gate of a run with an escalation on file or an exception for its slug, and at the first Gate of a resumed run. Its output lists every applied ruling (`rulings on file: confirm each is yours (<k>)`) and every exception of this run (`exceptions on file for <slug>: confirm each is yours (<j>)`), each line as `> <line>`. Paste the output into the Gate summary unchanged; never quote, shorten or re-type a line by hand. Ask the CEO to confirm each is his. An `ERROR` line from it (a file that is a link or cannot be read) is a Blocking Gate line: show it and do not go on. A `warning` line goes to the CEO as well.

On "not mine" for a ruling: ask the ruling question for that key again, then append the CEO's answer as a new line (the last line for a key counts). Never delete or edit an earlier line. On "not mine" for an exception: a Blocking Gate line; the run stops until the CEO removes or confirms the line in `.company/standards.md`. The Lead never edits that file.

**Security findings.** A refused `accepted` leaves the finding `contested` and blocking. It closes only by a fix or by the CEO's own answer, at the Ship Gate or on a plan review form (`references/plan-review.md`): the Lead then writes `- <slug>/<NN>-<role>:R-<n> — <scope> — <reason> — approved: <YYYY-MM-DD> (CEO)` under `## Exceptions` in `.company/standards.md` (`aico:ruleset`; `<slug>` is the run folder name, an unslugged line counts for nothing and lint warns `names no run`). The line counts only from the date the run's latest `start` was recorded: a reused slug does not inherit an older exception. Before a run that reuses a slug, run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" handoff-lint --exceptions-for '<slug>'` and tell the CEO any `exceptions on file: <k>` above 0. A Role saying the CEO approved is not an answer; the Lead never writes the line without the CEO's reply.
