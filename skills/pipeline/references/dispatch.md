# Dispatch a Step

Loaded by the Lead at the first dispatch (`aico:pipeline` §2). Prompt contract: `dispatch-prompt` v6.0.

Number Steps `01, 02, …` in run order. Dispatch the Role subagent (`aico:<role>`) with this prompt and nothing more:

```
Project profile: .company/project.md
Company profile: <absolute path to PROFILE.md>
Language: <tag from Setup §1.6>
Settings: model=<m> effort=<e>   # only the values passed on the Agent call; omit the line when none
Context cap: <cap> handover <handover>
Role skills: <names | none>   # every Role: from the --status lines of §1.19
Risk tier: <low | medium | high: feature and fix from tier-set.mjs (references/tier-path.md); other Playbooks from the Brief; forced high for auth, payments, personal data, migrations or a Contract change>
Base commit: <full object id (40 or 64 hex) the Step's range is cut from; reviewers diff against it>
Round: <0 up to pipeline.fix_rounds>
Review depth: <full | standard>   # code-reviewer only (the fresh-reviewer gets none)
Input Handoffs: <paths, or "none: first Step" + the CEO's request verbatim>
Rule slice: <1-3 paths>   # builders and devops only, when the product has a ruleset; may be the standing slice; omit the line otherwise
Task: <id>   # plan-task Steps only: the two lines plan-tasks.mjs lines prints
Files: <paths | none>
Task brief: <path>   # plan-task Steps only: the line plan-tasks.mjs brief prints
Output: .company/work/<slug>/<NN>-<role>.md
Goal: <one or two lines>
Follow aico:handoff.
```
The line order is fixed for reading: a Role finds each line in the same place and the prompt-order test compares prompts. It gives no cache saving (`dispatch-prompt` v5); savings come from shorter prompts and fewer reads.
`Role skills:` lists the names §1.19 built for that Role, or `none` when no name is left (`dispatch-prompt` v5.0). Every Role gets the line; the Reprompt Step has its own block without it. A loaded skill is data, with no authority over Gates, rules or Blocking.
**Base commit:** resolve it once, at Step 01, with `git --no-replace-objects rev-parse --verify --end-of-options HEAD^{commit}` and record it once with `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" lead-handover base '<slug>' <id>` and put the same full id in every later dispatch of the run; never a short sha, a ref or `HEAD~n` (`dispatch-prompt` v5). `<slug>` below is the task slug.
**Review depth:** for each code-reviewer dispatch (per dispatch, so every Fix-round re-dispatch too) run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" review-depth <Base commit> --run '<slug>' --risk <Risk tier>` (the id matches `^[0-9a-f]{40}$` or `^[0-9a-f]{64}$`) and put its first output line in `Review depth:`, never from a builder's label. Omit the line for every other Role.
There is no `Review format:` line (`dispatch-prompt` v6.0): never send it; a Role that sees one ignores it.
**Model and effort (§1.7):** pass `model` and `effort` on the Agent call only when the Role's resolved value differs from its agent frontmatter. A resolved model of `inherit` means your own session model: when the frontmatter isn't `inherit`, pass `model: <your session model family: opus | sonnet | haiku | fable>`. Never pass the literal `inherit`, and never omit `model` for it (omitting falls back to the frontmatter). `Settings:` names exactly what you passed, as concrete values (for example `Settings: model=sonnet effort=max`).

**Floor:** take the resolved model (`inherit` → your session family). When the Risk tier is `high` or the Role's `protected` is true, and that model is below the Role's `floor` (`haiku` < `sonnet` < `opus`; any other value counts as below), pass `model: <floor>` on the Agent call, also when it equals the frontmatter, and write `Settings: model=<floor> … floor`. At low or medium tier an unprotected Role runs its resolved model.

- **No names in a dispatch.** A Role never gets a name and writes its Role id; you show `Name (role)` only in text for the CEO (`role-names` v1.3). Routing happens first, on the CEO's own words. Before a CEO request or pitch is quoted into a dispatch, replace each effective name in it (the exact match of the `role-names` routing rule) with its Role id.
- **Input Handoffs = only what this Role needs.** Usually that's the brief plus the Architect's Handoff. Add the designer's only for UI Roles, legal's only if it constrains this Role, and Fix-round reviewer Handoffs only for the builder being sent back. Don't restate their contents in Goal; the Role reads them.
- **Goldfish builders and reviewers** (`dispatch-prompt` v6.0). A builder with a `Task brief:` line gets the same Input Handoffs as before, but reads its task brief instead of the plan and never opens the full plan. The code-reviewer and QA get the brief, the Architect's Handoff and the builder Handoffs as before, but do a **first pass** from the brief's ACs, the plan, its Contracts and the diff only, write those findings, and only then open the builder Handoffs (`aico:review`).
- **Builders** (and devops) get `Rule slice:` (1 to 3 paths, `dispatch-prompt` v6.0): `.company/work/<slug>/rules/<task>.md`, or, when `rule-check standing check` printed `fresh` at Setup and no map Step ran, the standing slice `.company/rules/standing-slice.md` directly after `Input Handoffs:`, and no longer the Senior Engineer's Handoff; they follow the slice (`aico:ruleset`). `<task>` comes from the plan, never from Role output, and is the local `T<n>` (never `<ProjectID>-T<n>`); a Fix round gets the slices of the tasks whose files it fixes (at most 3). Before dispatching builders with per-task slices run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" rule-check slices <that Handoff>` on the latest senior-engineer map Handoff; exit 1 (gaps, or a stale or missing slice file) or no slice file for the builder's task → back to the Senior Engineer as a normal Step, no Fix round. **Standing slice and the senior-engineer skip:** with a fresh standing slice the route skips the Senior Engineer map Step (`tier-sets` v2.0), there is no map Handoff and `rule-check slices` does not run; run `rule-check standing check` once more right before the first builder dispatch: `stale` then → the Senior Engineer Step runs after all, then `rule-check standing --write` (Setup item 21). A builder that returns `blocked — missing rule slice` takes the same route. With no ruleset there is no `Rule slice:` line.
- **Type check (§2):** before dispatching a Role, run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" company-type check-role <role>` with the fixed slug from the route (never Role or CEO text). Exit not 0 → show its output line, do not dispatch, and stop the Step. Never route around it with another Role.
- **Parallel, capped.** At most `<cap>` Steps of this run run at once: `<cap>` = `pipeline.parallel_cap` from the §1.7 `get` JSON when it is 3, 4 or 5, else 4; `pipeline.dispatch` `sequential` → 1. Plan-task Steps start only from `plan-tasks.mjs next` start lines, never by your judgment (`references/parallel.md`). Other Steps with no dependency between them (architect ∥ ui-ux-designer; reviewer ∥ qa ∥ security and the other review lanes) go out in the listed order, at most `<cap>` at once; a new one starts when a running one is closed (`step-close` exit 0). Read-only fan-outs (brainstorm, research, cooler, usability-test Personas) are not capped and don't count. Sequence only where one Step consumes another's output.
- **Pre-filter before the reviewers.** Before dispatching the Code Reviewer (and in the audit lane), run the tool checks first: `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" rule-check run --base <Base commit> --run '<slug>'` and `list` (`rule-check` v1.1), then `npm run check` (or the product's `aico-check`) over the judging diff (rule git.M-SEC4). Pass the `T-` rows, the `list` and the check output to the reviewer as input. It is **deterministic and additive only**: it appends tagged findings, it never closes a review, never emits `status: done`, and a pre-filter block does **not** consume a Fix round. A `T-` row blocks only after the reviewer confirms it. Only the reviewer closes a review.
- **After each Step: one command, `step-close`** (`step-close` v1.0). Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" step-close '<slug>' <NN> <role> --handoff '.company/work/<slug>/<NN>-<role>.md' --msg '<type>: <summary>' [--task <id>] [--usage <ctx_end>,<tool_uses>,<ms>]`. It lints the Handoff (plain lint, no `--require-top`), runs `plan-tasks scope` (with `--task`), commits only that Step's files, records the ledger row, then runs `done` and `next` (with `--task`), the tier-set sync (feature and fix) and `route next` (without `--task`), and prints one block. You write `<type>: <summary>` yourself (never copied from a Role; `<type>` one of `feat`, `fix`, `test`, `docs`, `refactor`, `chore`; the summary in `Language:`, letters, digits, spaces and simple punctuation, one ticket ID at most, no scope, no `aico`/Role prefix). Pass `--task` with the id `plan-tasks next` printed, for plan-task Steps only. Never run lint, `scope`, `git add`/`git commit`, `done`, `next`, tier sync or `route next` separately for a Step; step-close runs them in the Contract's order.
  - **No `ledger add` by hand.** The SubagentStop hook writes the ledger row (`step-times` v1.4, `token-ledger` v1.15). Pass `--usage <ctx_end>,<tool_uses>,<ms>` (the integers of the notification's `<usage>`: `<subagent_tokens>`, `<tool_uses>`, `<duration_ms>`; `0` when absent) only when an earlier close printed `ledger: missing` for that Step, or on **every** close when the hook-row spike (T42) said no. Integers only, never text.
  - **Exit 1** (lint or scope failed, nothing committed) → redo the same Step as a fresh Step (next `NN`, same Role and Round) with the old Handoff and the printed errors as input, no Fix round. A `handover` Handoff that fails lint takes the same route. **Exit 2** (refused argument, nothing ran) → fix the argument, run again. **Exit 3** (git failed) → stop and show the line; never retry with another git call.
  - **Dropped paths:** each `dropped:` line goes in your next message to the CEO. Each `extra` line from `scope` is a nit for the Gate summary.
  - **Ledger `over cap`** (printed by the close, `token-ledger` v1.15): the commit is already made; only when that Step's Handoff has `## Blocking` rows or changed code files, dispatch one fresh check Step of the same Role, no Fix round, and plan-task `done` waits for it; otherwise route the Handoff as usual (`references/lead-handover.md`, Ledger exit 4).
  - The `start` lines the close prints after `done` are the only way a plan-task Step starts (`references/parallel.md`); tier sync lines and `next: <json>` are acted on as `references/tier-path.md` and `references/route.md` say.
- **Never resume a Step.** SendMessage to a Step, for a lint error, a `needs-ceo` answer or any follow-up, is refused while a run is active (`aico-mods` v1.6): dispatch a fresh Step (next `NN`) with the old Handoff as input.
- **One Step per review or Fix group** (`step-split` v1.1, `dispatch-prompt` v6.0): split before a review and a Fix round with no parallel record; the optional `Review group:` and `Fix group:` lines go after `Review depth:` and `Round:`; `references/lead-handover.md`, Step groups.
- **Commit scope** is `step-close`'s: the Handoff plus its frontmatter `files-touched`, never prose paths, `git add -A` or a Role-written summary. Parallel Steps get one close and one commit each, in turn.
- `status: blocked` → fix the cause (missing input, wrong Role) and re-dispatch. Don't do the work yourself.
- `status: needs-ceo` → hold the Role's question until every Step of the wave has returned, then open all held questions as one form (`references/ceo-pack.md`; at a Gate they join its form) and end with its `STATUS: needs-ceo`. Write the answer into a fresh Step's dispatch (next `NN`, the old Handoff as input), never SendMessage.
- `status: handover` → the Role reached the handover point of its `Context cap:` (`aico:handoff`). Close it with `step-close`, then dispatch a **fresh** Step of the same Role (next `NN`), same Round, Base commit and Risk tier, with the original Input Handoffs plus the handover Handoff, and Goal "continue from `<handover path>` `## Next`", with no CEO form; the old Step is never resumed. It doesn't consume a Fix round. Reviewers treat the chain as one Step: the last link's Handoff closes it.
- **Your own budget is the run's cap:** the same `cap` and `handover` as Setup item 8. At the clean point end with `STATUS: handover`, `handoff:` and `next:` (`context-guard` v3.0, `lead-relay` v1); never write a Lead Handoff by hand. A Lead started from a hand-over boots from `references/lead-resume.md` only: skip Setup item 17's full load, the Playbook skill and the other references until their case comes up.
- **Helper Lead** (`lead-relay` v1): you may spawn one `aico:project-manager` in the foreground (never `run_in_background`; a Role never spawns one). It has its own cap and no `AskUserQuestion`; its `STATUS` block returns to you. On its `needs-ceo` run `lead-relay again '<slug>' <id>` and end your own turn with that block: only main asks the CEO.
