# Skill picks (the Lead's side of `skill-recommendation` v2)

Load when the route has a `skill-researcher` or `design-researcher` Step. Contracts: `docs/contracts/skill-recommendation.md`, `skillspector-scan` v1, `skill-catalog` v1. The Role finds and vets by reading and runs no scan. You scan every pick (`vet`), and only you add skills, and only after both forms below (agentsec.M-SEC4). Copy passes `aico:writing`.

## 1. Before the dispatch
Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" skillspector detect --json`. `installed: false` → offer the SkillSpector install form from `skills/skillspector/SKILL.md` (always asked, whatever `gates.installs` says). Skip → no dispatch; the Gate summary says "no skill picks without the scanner".

## 2. Dispatch
Use the `aico:pipeline` §2 prompt, so the block carries `Language:`, `Context cap:` and `Role skills:` like every dispatch, and no name. Put the Area in the Goal block as its own line: `Area: stack | product-type | company-type | design` (one value). Read the Area-specific inputs from the Contract.

## 3. After the Handoff
1. **Vet:** `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" skill-picks vet '.company/work/<slug>/<NN>-skill-researcher.md' --json` (`<NN>-design-researcher.md` for that Role; the path from the dispatch, never typed from Role text). Progress goes to stderr. A failing lint line is dropped and named by number, never repaired. Commands use tokens from the `vet` output only. `refused: skillspector missing` → the install form of section 1; `refused: git missing` → say git is needed. Nothing is approvable then.
2. **Approve form** (never auto), whatever the Gate settings: each approvable pick with your scan in words (`no-llm scan of commit abc1234, 0 critical, 0 high, 1 medium`; `static-fallback` as "static fallback, not an LLM scan"; `refs_not_bundled > 0` as "<n> references to files outside the skill, not inspected"; a plugin skill as "plugin skill, not scanned; installed only by you with /plugin"), then the not-approvable picks with their `reject_code` (`commit-not-in-repo` is "that commit is on no branch or tag of the named repo"; a command pick is "command source: it cannot be pinned, so it cannot be approved") and the Role's rejected list with codes. Approvable means `picks[].approvable` is true; a repo pick needs a `picks[].hash`, and a plugin pick has none (its hash is null). No pick approvable → no form; the Gate summary lists each pick with its code. Options: Approve the set (Recommended) / Change / Skip. Skip writes nothing. With the approval the CEO picks the Roles of each approved pick and may change its default category (`entry.skillcategory`): category pages without `security` as in `/aico:add-skill`, Roles as multi-select pages of 3 plus Next page, from that category in `${CLAUDE_PLUGIN_ROOT}/deps/3rdpartyskills.json`, never a protected Role.
3. **License questions**, one per new entry, a repo or plugin pick whose name and commit are in neither `${CLAUDE_PLUGIN_ROOT}/deps/3rdpartyskills.json` nor `~/.mcsparrow/3rdpartyskills.json` (unsure → ask; `record` ignores the answer for an entry it already holds). Say: "The license, such as MIT. You state it; nothing checks it." Options: `picks[].stated_license`, as stated and not checked, when the pick has one (a `-` states none and is not offered); `No license, skip this skill`; `Cancel`; Other = the value. An answer holding a line break is refused and asked again before any command, since no field can hold one (`skill-catalog` v1). `Cancel` runs no `record` for any pick and stops before the Install / Skip form: say "Nothing was written."
4. **Record**, only after every license question is answered, one call per approved pick, with the Bash tool and a quoted heredoc, never on the command line:
   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" role-skills record <<'AICO_JSON'
   {"entry":<picks[].entry from vet>,"license":"<answer>","roles":["<role>"]}
   AICO_JSON
   ```
   Values are JSON-escaped and the line stays one line. `record` takes `{ entry, license, roles }`: `entry` is `picks[].entry`, changed only by the CEO's category answer. `No license, skip this skill`, or a pick that is no new entry → send no `license`. A new entry with no license writes nothing and prints `no license stated: <name>`; name each such entry in the form's result and the Gate summary. `record` writes no `vetted` and sets `approved` to today on the selections it records. An `ERROR …` line → show it; that pick is dropped and named. The Role's `approved: pending` is never copied.
5. **Install / Skip form**, only after approval and only when a `record` printed `recorded:`: the form of `aico:pipeline` §1.19 b. Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" install-skills --status`, then `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" install-skills --selected --dry-run`, and show the printed commands, which install the recorded commit, and the telemetry line; show every `WARNING:` line from the dry run to the CEO as a visibly marked warning (bold, or a warning sign) with its exact command, and say in the form text that a command shown as `manual` is not run by aico (the CEO runs it by hand, only from the home folder (tell the CEO to change to their home folder first, then run the command), never from a product folder, because a repo's own copy of the package runs otherwise, and only if they trust it), so Install covers only the runnable commands. Say that `npx skills update` would move a skill off the scanned commit. Only a user-level `gates.installs: auto` skips this form and answers it Install, and only when `settings_folder_moved` in the settings `get` output is `false` (true or absent shows the form); the `WARNING:` lines are then shown in your next message with their commands; it never answers the approve form or the stop form. An `ERROR …` line means install nothing and name that line. Install artifacts (`.agents/`, `.claude/skills/`, `skills-lock.json`) are never committed; the summary names them with the removal command. Nothing installs unless the approve form and the Install / Skip form (or `gates.installs: auto`) say yes (AC5). After the §4 checks, run §1.19 d of `aico:pipeline` again and use the new `Role skills:` lines for every later dispatch, so a Role gets the skill just installed.

## 4. Post-install scan and checks
Scan mode comes from settings (`skillspector.mode`), never from the Role. The installer runs the scan of the installed folder itself, before it stores a hash (`skill-recommendation` v2.0, side 6); you run no scan here. Check each approved repo pick that got Install (`gates.installs: auto` answers Install), after the install command ran, whatever its exit code. A pick that got Skip has no install line and no checks: it stays `degraded: missing <name>`, per `aico:pipeline` §1.19 b.
1. Read the `install-skills --selected` output for that skill: the installer compared the installed folder's hash with the scan hash at the skill's scope, then scanned the installed folder.

Go on only when the skill's line is `installed <name> (<scope>` with none of `FAILED`, `hash differs`, `scan failed` or `missing` for that skill. That skill's own lines decide, not the exit, since the exit is 1 for every pick when one fails. Go on and report that line.

Every other outcome **stops the run** (fail closed): any of those lines for that skill, or no `installed` line for that skill. The stop is a CEO form (never auto, whatever the Gate settings) that names the skill, what failed, and how to remove it, as the installer printed it. Where it printed none: a project-scope skill is removed by deleting `.agents/skills/<name>` and `.claude/skills/<name>` by hand, with no command, under the product root; for a skill whose scope is user, tell the CEO to change to their home folder first and run `npx -y skills@1.7.4 remove <name> -g -a claude-code -y` there, never from a product folder, because a repo's own copy of the package runs otherwise. What failed reads:
- `hash differs`: for a line saying `The folder stays`, "the installed files are not the files aico scanned before you approved", then the line; other `hash differs` lines: the line alone, since nothing was installed.
- `scan failed after install`: the printed reason, and "the installed folder stays until you remove it".
- anything else: the line, or "the check gave no usable result".

Options: Stop the run (Recommended) / Keep it and go on. You run no removal command (AC14); Keep is recorded in the Gate summary with what failed. The installer stores no hash for a skill that failed either check, so it stays off every `Role skills:` line.

## 5. Never
Pass Role text into a command, a path or a `source`; put a form answer on a command line; run `record` before every license question is answered; write a line the lint dropped; rank by downloads or stars; run any removal command; answer the approve form or the stop form automatically.
