# Contract: work-folder-name v2.1

v2.1 (task `P20261109.000009`, run 1; additive minor; the major v3.0 lands with the flip in run 2; rationale `docs/adr/0067-one-project-one-folder.md`): one project, one top-level folder, opt-in behind `work-folder new --layout v3`. Without the flag `new` prints v2 exactly as v2.0. With the flag it makes only v3 layouts: a project folder `.company/work/<ProjectID>/` and every run of that project (first run, later runs, sub-flows) as a sub folder in it. In v3 a run slug holds one `/`; `new` prints a `name:` that is a run slug; `--project` makes a sub folder, never a sibling `<ProjectID>-HH.MM.SS` folder. v2 names, v1.1 names and legacy slugs stay top-level runs: readable, resolved and resumed as before, never renamed or moved.

## Layout (v3, opt-in behind `--layout v3`)
- Project folder `<ProjectID>` (the bare ID, `isProjectId`). It holds `00-project.md` and run folders only. `00-project.md`: line 1 the description (`checkDescription`), line 2 empty, optional line 3 `Siblings: <ProjectID> ...` (sorted, own ID left out).
- Run folder `<NN>-<playbook>`: `NN` 2-3 digits, `01`-`999`, never `00`; `playbook` passes the Playbook id rule. `NN` is 1 plus the highest `NN` among the run folders of that project folder (`readdirSync`, links and non-folders skipped), else `01`. Non-recursive `mkdir`; `EEXIST` or an `NN` past 999 is `refused: too many runs`, nothing else written. Each run folder holds `00-summary.md` in the v2 shape (line 1 description copied from `00-project.md`, line 3 `Run: <kind> <playbook>`, no line 4), so `summaryDescription` and `runOf` are unchanged.
- Run slug `<ProjectID>/<NN>-<playbook>`, always `/` (never `\`), at most 80 characters. `parseRun(slug)` returns `{ id, nn, playbook }` or null. `isRunSlug(text)`: a v3 run slug or `isWorkFolder(text)` (v2, v1.1, legacy). `isWorkFolder` is unchanged: top-level names only, so a consumer not yet moved refuses a v3 slug (`bad slug`, fail closed).
- `workParts(slug)`: `[id, '<NN>-<playbook>']` for a v3 slug, `[slug]` otherwise, null for neither. Consumers pass it to `exactWorkPath` and join it under `.company/work`; the real path must equal `join(realpath(.company/work), ...parts)` and every part is `lstat`-checked (no link).
- `runKey(slug)`: a flat file-name key, `<ProjectID>~<NN>-<playbook>` for a v3 slug, the slug itself otherwise. Every file named after a run outside its run folder (ledger, run records, caches) uses it.
- `projectIdOf(slug)` and `branchId(slug)` return the ID for a v3 slug or project folder name too. Branch `aico/<ProjectID>` for every run of a project.
- `nextProjectId` also counts bare project folder names (in `.company/work`, `.company/archive` and its direct subfolders).
- Ticket IDs `<ProjectID>-T<n>`, numbered per project across the plans of its v3 run folders and its v2 folders.

## CLI (v3, opt-in behind `--layout v3`)
- `work-folder new --layout v3 --playbook '<id>' --topic file|none` (`--layout` once, value `v3` only, else `refused: usage`): Topic file steps 1-7 as v2.0 (description). Makes `<nextProjectId>/` (`EEXIST` → next ID, at most 9 tries), writes `00-project.md` (`wx`), makes run `01-<id>` with `Run: first <id>`. Prints `id: <ProjectID>`, `name: <run slug>`, `branch: aico/<ProjectID>`.
- `work-folder new --layout v3 --playbook '<id>' --project '<ProjectID>'`: a later run or sub-flow run (`Run: later <id>`). A v3 project → next run folder. A project with only v2 folders → makes `<ProjectID>/` with `00-project.md` lines copied from its v2 folders as `makeRun` v2.0 did, then run `01-<id>`; the v2 folders stay. No folder of that ID → `refused: unknown project`. Same three lines printed.
- `draft-input` (`draft`) and `ticket-approval` (`build`) make their run through the same `makeRun` in the parent's project folder for a v3 parent; for a v2 parent as `--project` above.
- `work-folder siblings` writes line 3 of `00-project.md` for a v3 project, line 4 of each `00-summary.md` for a v2 one.
- `work-folder branch '<slug>'` accepts a run slug or a project folder name.
- Refusals add `too many runs`; all others as v2.0. `helperName` for a v3 parent is not used (draft and build are runs).
- Sessions: a sub-flow run may start while its parent run of the same project is open (one session, sequential). Two sessions on one project at once are not supported (accepted limit).

## v2.0 (default until run 2)
v2.0 stays the default layout of `new` until run 2 flips it; v3 slugs are read through `isRunSlug`/`workParts`/`runKey`/`parseRun` only. v2.0 (task `2026-11-08 22.25 - Project Id Naming`; major, CEO approved; rationale `docs/adr/0066-project-id-work-folders.md`): every new work folder belongs to a project with one project ID. `work-folder new` makes only v2 names; v1.1 names and legacy slugs stay readable, resolve and resume as before and are never renamed. Breaking: `new` no longer makes `YYYY-MM-DD HH.MM - Topic` names, the Topic file carries a description instead of a Topic, `new` prints an `id:` line first, and in a v2 folder a ticket ID is `<ProjectID>-T<n>` (a bare `T<n>` is refused there).

## Project ID (v2.0)
- Shape `P<yyyymmdd>.<n>`: capital `P`, a real calendar date, one dot, `<n>` decimal digits, at least 6, at most 9, zero-padded to 6 (`000001`), never all zeros; more than 6 digits only without a leading zero (`1000000`). So `p20261108.000001`, `P20261108.1`, `P20261108.000000`, `P20261108.0000001`, `P20261308.000001`, `P20261108.000001.1` fail. `isProjectId(text)`; every input is length-capped (19) before a pattern runs.
- Counter: per local day, per repo. `nextProjectId(date, names)`: 1 plus the highest `<n>` among the v2 names of that day, else `000001`. `names` are the entries of `.company/work`, of `.company/archive` and of each direct subfolder of `.company/archive` (`readdirSync` only, a link or non-folder is skipped, never followed), so an archived project never frees its ID. No counter file, no cross-day state. The Lead makes a new project's branch with `git switch -c aico/<ProjectID>`, which fails on an existing branch: the run stops there (fail closed).
- Folder name `<ProjectID>-HH.MM.SS` (local start time of the run, 24h, `HH` 00-23, `MM` 00-59, `SS` 00-59). `parseProject(name)` returns `{ id, day, n, time }` (`time` is `HH.MM.SS`) or null. A run of a project at the exact `HH.MM.SS` of an existing folder of that project (any day) is refused (rare), never retried. One project has one folder per run (draft, build, fix); all share the ID.
- `isWorkFolder(name)` is true for a v2 name, a v1.1 name or a legacy slug. `projectIdOf(name)` is the ID of a v2 name, else null.
- Branch: `branchId(v2 name)` is the project ID, so every run of a project uses `aico/<ProjectID>`. v1.1 and legacy branch ids are unchanged. `isBranchId(text)` is true for a project ID or `^[a-z0-9][a-z0-9-]{0,127}$`; consumers use it instead of their own copy. A v2 branch id is never a collision between runs of one project. One active run per project: a later run starts only after the project's earlier run finished or stopped (the runs share the branch).
- Description: `checkDescription(text)`: one line, 1-120 characters, not only spaces, no character of category Cc, Cf, Zl or Zp, no Default_Ignorable_Code_Point (such as U+3164, U+034F, U+115F or U+FE0F), and none of U+180E, U+2065 or U+E0000-U+E007F (the `LICENSE_BAD_RE` set of `scripts/skill-catalog.mjs`, held as a literal in the home file). `00-summary.md` of every v2 folder starts with it: line 1 the description, line 2 empty, line 3 `Run: <kind> <playbook id>` (kind `first` from `new`, `later` from `--project`, `build` from ticket-approval, `draft` from draft-input; playbook id by the Playbook id rule), optional line 4 `Siblings: <ProjectID> ...` (space-separated, sorted, own ID left out), later lines free (the Finish summary). `summaryDescription(text)` returns `{ description }` or `{ error: 'missing description' | 'multi-line description' }` (line 2 not empty counts as multi-line). `runOf(text)` returns `{ kind, playbook }` or null; draft-input `--for fix` and the ledger's release filter read the run kind and Playbook from it, never from the name.
- Ticket ID: `ticketPattern(name)` returns `{ id, head, src }` for that folder. v2 folder: `<its ProjectID>-T<1-3 digits>[a-z]`; v1.1 or legacy folder: `T<1-3 digits>[a-z]` as before. `head` matches the ID at the start of a heading (followed by end, space, `:`, `.`, `)` or `-`). `isTicketHeading(title)` (no folder known, plan-check only) accepts either form. `ticketLocal(id)` is the `T<n>` part, used only as a file-name part inside the run folder (rule slices, task briefs, worktree patch and branch names). `src` escapes the dot of the ID (`P20261108X000001-T1` never matches). Ticket numbers are per project, not per run: a later run's plan numbers on from 1 plus the highest ticket number in the plans of the project's earlier folders, so one ticket ID names one piece of work and worktree refs `aico-wt/<ProjectID>/t<n>` never repeat; `plan-tasks check` refuses a reused one (plan-tasks v1.8).
- `makeRun(io, root, id, date, kind, playbook)`: the only maker of a continuation folder (CLI `--project` with kind `later` and its `--playbook`; `draft-input` with `draft` and its `--for` word; `ticket-approval` with `build` and the parent's `runOf` Playbook). The project must have a v2 folder (`refused: unknown project`); non-recursive `mkdir` of `<id>-HH.MM.SS`; it exists → `refused: too many runs this second`, nothing written, no other time tried. It writes `00-summary.md` (`wx`) with line 1 and line 4 (when it is a `Siblings:` line) copied from the project's folders, taken in name order, the first whose line passes its check (every folder of a project holds the same lines 1 and 4, so the order never changes the result); none passes → the fallback description, no line 4. Line 3 is `Run: <kind> <playbook>`. Returns the name. `draft-input` still removes its own Topic file as before; `makeRun` reads none.
- `helperName(parent, suffix, { stamp, date, isTaken })` for a v2 parent returns `<parent ID>-HH.MM.SS` (local time of the caller's `date`; `stamp` has no seconds) for both suffixes, null when taken; v1.1 and legacy parents are unchanged.

## v1.1 names (read and resume only)
The sections below still define v1.1 names and legacy slugs for reading, branch ids and helpers of those parents. Only the CLI section is replaced by v2.0.

v1.1 (task Draft Input Folder Case Draft, T1; additive, `docs/adr/0007-contract-minor-versions.md`): a work folder or file typed in another letter case than the one on disk is refused on every platform. New export `exactWorkPath(io, root, rel)`: `rel` is the list of parts under `.company/work`; it checks `.company`, `work` and each part against the directory entries (`readdirSync`), never against `realpath` output. Result `exact` (every part is listed as typed) or `missing` (a part is listed in no letter case); a part listed only in another ASCII letter case throws `WorkFolderRefusal('wrong letter case')`. The ASCII-only fold only picks these refusal words and never grants access, so U+212A and other look-alikes stay different names (`missing`). With case twins the typed spelling wins. `checkWorkDirs` runs this check for `.company` and `work`, and `realDir` and the Topic-file parent compare real paths exactly (no case fold). `work-folder branch '<name>'` prints `refused: wrong letter case` (exit 3, nothing written) for a name or `.company`/`work` folder in another case; a name missing in every case stays `refused: unknown name`. Callers run the name-shape check first, then `exactWorkPath`, then the link and escape checks. Every v1 caller and every exact spelling behaves as before.

New Contract (task idea-20261030-2242-build-draft, T3). Provider: `mods/lib/work-folder.mjs` (pure, no imports; file calls come in through an `io` object) and `scripts/work-folder.mjs` (Node built-ins only). Consumers: every script, mod and Playbook that names, parses or resumes a work folder; `draft-input` and `ticket-approval` (`helperName`, `readTopicFile`), `aico:pipeline` Setup (`work-folder new`).
Work folders are named `YYYY-MM-DD HH.MM - Topic` in local start time. One shared module holds the allow-lists; no other file repeats the pattern. Legacy slugs stay readable and are never renamed.

## Names
- Topic (`checkTopic`): ASCII, `^[A-Z0-9][A-Za-z0-9]*([ -][A-Z0-9][A-Za-z0-9]*)*$`, at most 60 characters, at most 5 space-separated words. The last word that is not all digits is not a suffix word (`Build`, `Draft`, compared without case). So `Fix-login`, `Fix Login Build` and `Fix Draft 2` fail; `Release 2` and `Build Pipeline Fix` pass.
- New name: `YYYY-MM-DD HH.MM - <stem>[ <Suffix>[ <n>]]`, a real calendar date, `HH` 00-23, `MM` 00-59, at most 120 characters. The dot of `HH.MM` is the only dot, so `..`, `/`, `\`, quotes, `$`, backtick and a trailing dot fail by shape.
- `parseName(name)` returns `{ stamp, stem, suffix, number }` or null. The words after ` - ` are split: a final ` Draft` or ` Draft <2-9>` gives suffix `Draft` and its number; a final ` Build` gives suffix `Build`; otherwise the name is a primary run (`suffix` null) whose stem is its Topic plus an optional collision number. The stem, or the stem minus one trailing ` <2-9>`, must pass `checkTopic`. A name ending ` Build <n>` returns null: a `Build` helper never takes a number.
- `isWorkFolder(name)` is true for a parsed new name or a legacy slug `^[a-z0-9][a-z0-9-]{0,63}$`.
- Suffix list is closed: `Build`, `Draft`. A new word needs a minor bump of this Contract. Suffix and number sit outside the Topic cap.
- `candidates(stamp, topic)` lists the plain name then ` 2` to ` 9`; `newName(stamp, topic, isTaken)` returns the first not taken, or null. `stampOf(date)` formats local time.

## Helper names (`helperName(parent, suffix, { stamp, fallback, isTaken })`)
- Stem is the parent's stem: the words after ` - ` minus only the parent's own final suffix and its number. A primary parent's collision number and a Topic's number word stay.
- `Build`: the parent's date-time, no number, `isTaken` is not asked. `2026-10-30 22.42 - Login Idea` gives `... - Login Idea Build`; `... - Login Idea 2` gives `... - Login Idea 2 Build`.
- `Draft`: the caller's own `stamp`, then ` 2` to ` 9` while `isTaken`. `2026-10-30 23.10 - Login Idea Draft`, then `... Draft 2`.
- Legacy parent: `Build` keeps `<slug>-build`. `Draft` is a new name: the slug minus a final `-build` or `-draft` (and an optional `-<2-9>`), hyphen words capitalised and joined by spaces, checked as a stem. If that fails, the stem becomes `fallback` (a `--for` word with each hyphen part capitalised, such as `Fix`, `To-Spec`) and the suffix stays: `2026-10-30 23.10 - Fix Draft`.
- null: a bad parent, suffix or stamp, a missing fallback when one is needed, or every Draft number taken (the caller prints `refused: too many runs this minute`).

## Branch id
`branchId(name)` is `YYYY-MM-DD-HHMM-` plus every word after ` - ` (Topic, suffix, number) lowercased and joined by `-`; Topic hyphens stay. `2026-10-30 23.45 - Fix Login Draft 2` gives `2026-10-30-2345-fix-login-draft-2`. A legacy name maps to itself. A new name whose branch id equals an existing folder's counts as a collision.

## Playbook id
`--playbook '<id>'` passes only `^[a-z0-9]+(-[a-z0-9]+)*$`, at most 64 characters, and that check runs before any file call (else `refused: bad playbook`). Then `skills/<id>/SKILL.md` under the plugin root must be a regular file (`lstat`, no link). The fallback Topic is the id with each hyphen part capitalised; one that fails `checkTopic` is `refused: bad playbook`. `clear` checks only the id shape.

## Topic file and `readTopicFile(io, root, id, mode)`
The Lead writes the Topic as one line to `.company/work-folder-topic-<id>.txt` and never reads it back. No Topic text sits on a shell line. `io` is `{ fs, path, platform }` (the caller passes `node:fs` and `node:path`). Steps, each only after the one before passed:
1. Shapes: the id above; `--topic file|none`.
2. `.company` and `.company/work` are real folders (`lstat`, no link) whose real path is inside the real root, else `refused: bad topic path`, nothing read or removed.
3. The path is built from the passing id only; its real parent equals the real `.company`.
4. `lstat` of the entry. None: `refused: no topic file` with `file`, the fallback with `none`.
5. Read only a regular file with one link, at most 4096 bytes, `fstat` `dev` and `ino` equal to the `lstat`, `O_NOFOLLOW` where defined, fatal UTF-8 with the BOM kept, no character of category Cc, Cf, Zl or Zp except one final LF. A link, other entry type, hard-linked or oversized entry is not read and counts as a failed Topic. CR is Cc, so a CRLF file falls back.
6. The entry is removed with `unlink`, which never follows a link, whether or not it was read, and never before steps 1-3 passed. An entry that cannot be unlinked (a folder) is `refused: bad topic path`.
7. `checkTopic` on the text minus its one final LF, no other trimming. Fail: the fallback (no repair).
Returns `{ topic }` (the checked text) or `{ topic: null }` (fallback). Output never echoes rejected text. `mode none` skips step 5 and removes a stale entry. Accepted limit: the path is per id, so two concurrent runs of one Playbook in one repo can take each other's Topic; the other gets `refused: no topic file` or a checked Topic, never unchecked text.

## CLI (v2.0)
- `work-folder new --playbook '<id>' --topic file|none` starts a new project: the Topic file (steps 1-6 above, unchanged) now holds the description, checked by `checkDescription` instead of `checkTopic` in step 7; a failed or absent description falls back to `fallbackTopic(<id>)`. It makes `.company/work/<nextProjectId>-HH.MM.SS` with a non-recursive `mkdir` (`EEXIST` takes the next `<n>` at the same `HH.MM.SS`, at most 9 tries, then `refused: too many runs this second`), writes `00-summary.md` (`wx`) with the description and `Run: first <id>`, and prints `id: <ProjectID>`, `name: <name>`, `branch: aico/<ProjectID>`.
- `work-folder new --playbook '<id>' --project '<ProjectID>'` starts a later run of that project through `makeRun` (no Topic file read) and prints the same three lines. A bad ID is `refused: bad project`.
- `work-folder siblings '<ProjectID>' '<ProjectID>' ...` (2-20 distinct IDs, each with a v2 folder, else `refused: bad project` or `unknown project`, nothing written) sets line 4 of `00-summary.md` in every folder of each listed project to `Siblings: <the other IDs>` (replaced when line 4 is a `Siblings:` line, inserted otherwise) and prints `linked: <folders>`. Used after the CEO confirms a split; the first task keeps its ID.
- `work-folder clear --playbook '<id>'` runs steps 1-3 and 6, prints `cleared` or `no topic file`, creates nothing.
- `work-folder branch '<name>'` prints `branch: aico/<branch id>` for an existing new or legacy folder (a real folder, no link) and writes nothing. A name that is not a work folder is `refused: bad name`; a missing folder `refused: unknown name`.
- Every refusal (`bad playbook`, `bad topic path`, `no topic file`, `too many runs this minute` (v1.1 and legacy helpers), `too many runs this second` (v2), `bad name`, `unknown name`, `bad project`, `unknown project`, `wrong letter case`, `usage`) prints `refused: <reason>`, exits 3 and creates nothing. Exit 0 otherwise. Skills pass a name only single-quoted.
