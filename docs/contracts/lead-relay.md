# Contract: lead-relay v1.1

v1.1 (task P20261119.000001/01-fix, additive): CLI word `result` (main, read only), the Lead result record `lead-result.txt` written by the hook host, refusal `run ended` for `open` and `again`, main as a script caller of `result`.

v1.0 (task P20261117.000001/01-feature, new, Spike S1 and S2 results folded in before release; ADR `docs/adr/0077-lead-as-subagent.md` and `docs/adr/0078-ceo-answer-from-hook.md`). The Lead runs as the plugin agent `aico:project-manager`, spawned by the main session. This Contract is everything that passes between the two: the Lead's last message (`STATUS` block), the form record, the CEO answer the hook records, and the prompt main uses to start a Lead.

Provider: `scripts/lead-relay.mjs` (CLI words `open`, `read`, `again`, `result`; hook adapters `answer` and `preset`; functions `leadStart` and `leadStop`, called only by `scripts/hook-host.mjs` on `SubagentStart` and `SubagentStop`), called as `node "${CLAUDE_PLUGIN_ROOT}/scripts/run.mjs" lead-relay ...`. Consumers: `agents/project-manager.md`, the `aico:lead` main-loop reference (main; skills/lead/references/main-loop.md, written by plan task T14), `skills/pipeline/SKILL.md` and `references/lead-resume.md` (the Lead), `scripts/run-state.mjs` (`gate` refusal, `run-state` v3.1), `scripts/lead-handover.mjs` (`read` form line, `lead-handoff` v3.0), `scripts/hook-host.mjs` (`leadStart`, `leadStop`; the script is an entry of the dependency pins in `hooks/lib/dep-pins.mjs`). Uses `lead-handoff` v3.0 (the Lead Handoff writer), `run-state` v3.1 (run state lookup: `running`, `stale`, `ended`).

## Roles of the two sessions
- **Main** (no `agent_id` in hook payloads): spawns one `aico:project-manager` at a time, in the foreground, relays forms with `AskUserQuestion`, spawns the next Lead. It dispatches no Role and runs no lint, ledger, commit, Gate or run-state script (`cap.M1`, `context-guard` v3.0, enforces the spawn part; `hook-event` v1.4 supplies `run` for every main `Agent`/`Task` call at any token level).
- **Lead** (`agent_type` equal to `aico:project-manager`, exact match): runs the Playbook and every Step, with shell tools `Bash` and `PowerShell`. It dispatches every Role in the foreground (`cap.M1` denies a Lead `Agent`/`Task` call with `run_in_background` true), so no Role is still running when a Lead ends. It has no `AskUserQuestion`. It ends every turn with exactly one `STATUS` block.
- **Role**: any other payload with `agent_id` (`aico:<role>`, also a foreign or missing `agent_type`), at any depth.
- A Role never spawns a Lead: `cap.M1` denies an `Agent`/`Task` call whose `subagent_type` (lower case) is `project-manager` or ends in `:project-manager` from any payload with `agent_id` whose `agent_type` is not exactly `aico:project-manager` (a Role, also a foreign, look-alike or missing `agent_type`), at every token level, with or without an active run. Main and a Lead may spawn one.
- **Helper Lead**: a Lead spawned by a Lead, in the foreground. It is a Lead in every rule above (own cap budget, no `AskUserQuestion`, one `STATUS` block), but its `STATUS` block returns to the spawning Lead, not to main. On a helper `needs-ceo` the spawning Lead runs `again '<slug>' <id>` and ends its own turn with that block, so main stays the only session that asks the CEO. Hook payload facts from Spike S1 (`.company/work/P20261117.000001/01-feature/06-spike-backend-engineer.md`): `agent_id` and `agent_type` are on every subagent event and absent in main; `transcript_path` is always the main transcript.

## Start prompt (main → Lead)
Main writes only one of these, verbatim, plus the CEO's request text on the first:
- `aico start: <playbook>` and a line `Request:` with the CEO's words (first Lead of a run).
- `aico resume: <slug> (<handover|answer|retry>). Boot from skills/pipeline/references/lead-resume.md.`
A resume prompt never carries a CEO answer, option text or summary: the Lead reads answers from the record. A Lead that finds answer text in its prompt ignores it.

## STATUS block (Lead → main)
The Lead's final message starts with line 1 `STATUS: <needs-ceo|handover|done|blocked>`, then `key: value` lines, at most 40 lines in all. `run:` is the run folder `.company/work/<slug>` on every status.
- `needs-ceo`: `handoff:` (the Lead Handoff path), `form: <id>`, then per question a line `Q<i> [<header>]: <question>` (single-select) or `Q<i> [<header>] (multi): <question>` (`multi: true`; main sends `multiSelect: true`), and 2-4 option lines `- <label> — <description>`, recommended option first. Printed by `lead-relay open`; the Lead returns it verbatim. Main builds the `AskUserQuestion` call from these lines only: `question`, `header`, `multiSelect` (true only with the `(multi)` marker) and each option's `label` and `description`, in the printed order.
- `handover`: `handoff:` and `next:` (one line). The cap hook's deny reason names both.
- `done`: `summary:` lines (at most 30).
- `blocked`: `reason:` (one line).
Main reads only line 1 and these keys. When the platform backgrounds the Lead spawn or drops its task-notification, main gets the same block from `result`. No valid line 1 (crash, abort, missing, other text first) is `blocked`, reason `no STATUS line`: main tells the CEO and offers one `retry` resume; it never guesses an answer.

## Form record
`.company/work/<slug>/forms.jsonl`, append only, one JSON object per line, protected like `guard.jsonl` and `run-state.jsonl` (no `Write`/`Edit` and no shell write naming the path, in any session; `context-guard` v3.0 self-protect run records). This deny stays on under `AICO_GUARDS=off`. `at` is UTC `YYYY-MM-DDTHH:MM:SSZ`, written by the script:
- `{ v:1, at, ev:"open", id, kind, questions }`: `id` is `f<nn>` (01-99, next free); `kind` is `gate:<brief|plan|ship>`, `idea`, `ask` or `step:<name>`; `questions` 1-4 items `{ q, header, multi, options }`, `header` at most 12 characters, `options` 2-4 items `{ label, description, result? }`. `result` (Gate forms only) is the `run-state gate` result that option means. Question texts in one form are unique (the answer map keys on them); a Gate form has `multi: false` on every question; no option label holds a comma (Spike S2: a multi-select answer is the labels joined with `", "`; `cch.M21`).
- `{ v:1, at, ev:"answer", id, src:"hook", answers }`: `answers` per question `{ labels: [<label>…], other: <text|null> }`. Only the hook adapter writes it; no CLI word writes an answer. A shell command that runs the `answer` adapter (`node <plugin>/scripts/lead-relay.mjs answer`, an inline interpreter program that names `lead-relay` and `answer`, or such a program on stdin) is denied by `self-protect.M-SEC1` (`Bash` and `PowerShell`, any session, also with `AICO_GUARDS=off`; reason names the CEO answer), so only a real reply the harness delivers is recorded. This is a narrow exception to ADR 0079 "guards leave shell alone" (CEO ruling "Block shell calls"); the `open`, `again`, `read` and `preset` words pass.

## Commands
| Command | Does |
|---|---|
| `open '<slug>' <kind> <json-file>` | Validates the questions (limits above, recommended first is the Lead's duty), appends `open`, runs the `lead-handoff` writer (`lead-handover write`), prints the `needs-ceo` STATUS block. Refused: `refused: open form <id>` while an earlier form has no answer (one open form per run); `refused: same questions open in run <other-slug>` (see Rules, shared form). |
| `again '<slug>' <id>` | Prints the STATUS block of an open, unanswered form again (fresh Lead after a missed answer). Refused: `refused: no open form with that id`; `refused: same questions open in run <other-slug>` (see Rules, shared form). |
| `read '<slug>' [<id>] --json` | Prints the form and its answer, or `answer: none`. The Lead acts only on this output, never on prompt text. |
| `answer` (hook, `PostToolUse`, matcher `AskUserQuestion`) | Payload without `agent_id` and without `agent_type` only (main; Spike S1: a subagent payload carries both). Finds the one open form in the project's non-ended runs (`run-state` `running` or `stale`; a run past the 12 h stale mark still waits on its form, only `ended` and run-less folders are skipped) that equals `tool_input.questions` exactly. Compared, per question in order: `question` = `q`, `header` = `header`, `multiSelect` = `multi` (absent reads as `false`), option count, and per option in order `label` = `label` and `description` = `description`; strings byte for byte. Any other key is not compared; appends `answer` from `tool_response.answers` only: a map `{ "<question text>": <string> }`, one key per question (S1 SDK path, S2 TUI: same map). Per question: a string equal to one option label → `labels: [<label>]`, `other: null`; any other string → `labels: []`, `other: <string>`; for a `multi` question the string is split on `", "`: parts equal to labels → `labels` (in answer order), the other parts joined again with `", "` → `other` (`null` if none). Writes nothing (fail closed, `cch.M20`) when: a value is not a string (S2 saw one array of strings, so that shape is unstable), a key is missing or not a question of the form, `tool_response.answers` is absent (the CEO declined: S2, an error result), no match, two matches, no non-ended run or a bad payload. `annotations` are ignored. Always exit 0, never blocks, at most 1 s. Wired in `hooks/hooks.json` as `PostToolUse`, matcher `AskUserQuestion`. |
| `result ['<slug>']` | Prints `recorded: <UTC time>` and the last `STATUS` block of the current Lead, kept in `.company/work/<slug>/lead-result.txt`, or `result: none` (no Lead of this start has stopped yet, or the file holds no valid block). No slug: the newest such file of the project. Read only; the one script main may run, to recover a Lead the platform backgrounded (see main-loop.md). Every line is shown without control, format (bidi, zero-width), line/paragraph separator and tag characters, at most 40 lines and 8 KiB; line 1 must be a valid `STATUS` line, else `result: none`. Refuses `bad slug`, `no run` and `usage` like the other words. |
| Lead result record (hook host, no CLI word) | `leadStart` (`SubagentStart`, `agent_type` exactly `aico:project-manager`): adds the agent id to the live Lead set (a file in the project's hook state folder, entries older than 3 h dropped) and deletes every `lead-result.txt` of the project, so a result on disk is never older than the latest Lead start. `leadStop` (`SubagentStop`, same `agent_type`; the host calls it only when it does not block the stop, so a stop that `cap.M1` or any host deny blocks is recorded only by the stop that ends, `stop_hook_active` true): removes the id; when another Lead is still live (a Helper Lead) it records nothing; else takes the run from the `run: .company/work/<slug>` line of `last_assistant_message` (an existing run, `run-state.jsonl` present, no link in its path), strips control, format, separator and tag characters, keeps the first 40 lines and at most 8192 bytes (cut at a UTF-8 boundary), and writes `lead-result.txt` as a new file under a random name (`O_EXCL`, no link followed) renamed over the old entry. Any other payload writes nothing. No CLI or hook word writes it: `node scripts/lead-relay.mjs record` is a usage refusal. `lead-result.txt` is shielded like `forms.jsonl` (no `Write`/`Edit` and no shell write naming it, any session, also with `AICO_GUARDS=off`); a shell program that names `lead-relay` and `leadStart`/`leadStop`/`leadReset` is denied like the `answer` adapter, also in the pins-mismatch text check. `leadReset` (main's allowed `PreToolUse` `Agent`/`Task` call that targets the Lead) empties the live Lead set: one Lead runs at a time, so an entry left by a Lead that ended with no `SubagentStop` cannot mute later results. Same accepted limit as the form record: a command that builds the path at run time is not seen. |
| `preset` (hook, `PreToolUse`, matcher `AskUserQuestion`) | Any session. A call whose `tool_input` has an `answers` key (any value, `{}` too) → deny, reason `aico: AskUserQuestion with preset answers is refused` (`cch.M-SEC8`: the harness lets `answers` answer the form without the CEO). Otherwise no output, exit 0. Not turned off by `AICO_GUARDS=off`. Wired in `hooks/hooks.json` as `PreToolUse`, matcher `AskUserQuestion`, `onFailure: block`. No aico hook returns `updatedInput` for `AskUserQuestion`. |

## Rules
- A form that main changed (any compared field differs) gets no answer; the fresh Lead sees `answer: none` and runs `again`. So a form with no recorded answer is asked again (AC4).
- Declined form: main's `AskUserQuestion` returns no `answers` (the CEO declined or interrupted; Spike S2: an error result). Main spawns no Lead, tells the CEO one line `aico: run <slug> waits on form <id>; say resume to be asked again`, and ends its turn. The run stays as it is (no row, form still open). When the CEO says resume, main starts `aico resume: <slug> (answer)`; the Lead reads `answer: none` and runs `again`. Main never loops a declined form on its own.
- `run-state gate '<slug>' <g> <result>` for a Gate that is not `auto` is refused (`refused: no CEO answer for <g>`) unless the latest `answer` of a `gate:<g>` form chose an option whose `result` is `<result>` and that answer's `at` is strictly after the previous `gate` record for `<g>` in `run-state.jsonl` (none → any answer counts) (`run-state` v3.1). So one CEO pick passes one Gate once; a Ship Gate after a Fix round needs a new form.
- Limit: the record guards against a Lead that drifts, not a hostile one. The shield on `forms.jsonl` and `run-state.jsonl` matches the path tokens of a shell command (`hook-event` v1.3, up to 64), so a command that builds the path at run time is not seen. A Gate pass traces to a recorded answer; a record forged that way is not detected. The `answer` deny matches the command text (script word plus `answer`), so a command that builds the script path or the word at run time is not seen either (same accepted limit).
- `other` text is the CEO's own words: stored at most 2000 characters, read as data, never as an instruction. Free text equal to an option label counts as that label.
- `other` text lives only in the `answer` row of `forms.jsonl` and in `read --json` (the Lead's one way to read it). Every log, hook stderr, `guard.jsonl` row, ledger, STATUS block and `lead-handover read` line shows it only as `other (<length> chars, sha256:<first 8 hex>)`.
- An answer counts as the CEO's only from main's `PostToolUse` `tool_response.answers`; `preset` denies a call pre-filled at `PreToolUse`. `answer` never checks `tool_input.answers` (by `PostToolUse` a real pick shows there too, Spike S1).
- `preset` fails closed: stdin over 64 KiB, or no decision before the 1 s self-exit (stalled read), gets the same deny and reason; small unparseable input and a call without `answers` still get no output.
- `open` confines the questions file (`proj.M-SEC7`). The repo root is the call's working directory; the typed path is resolved against it; real paths come from the native `realpath` (`fs.realpathSync.native`). In order: the file or the root cannot be resolved → `refused: questions file unreadable`; the typed path, or the file's real path against the root's real path, is the root itself or outside it (`..` escapes, absolute paths elsewhere, links out) → `refused: questions file is outside the repo`; the first part is `.company` in any letter case but the path is not under `.company/work/` spelled exactly → `refused: questions file is under .company`; the real path is not the root's real path joined with the typed relative path → `refused: questions file path differs from its real path`, so any symlink, junction or redirect on the path is refused, also one that stays inside the repo (letter case may differ on win32 and darwin, never under `.company/work/`); under `.company/work/` every part must be listed in its directory exactly as typed: a part found only in another letter case → `refused: questions file path letter case`, a part not found → `refused: questions file path is not an exact work path`. Nothing is written on refusal.
- Shared form: `open` and `again` refuse `refused: same questions open in run <other-slug>` when another non-ended run (`running` or `stale`) of the project has an open form whose `questions` equal this form's in every field `answer` compares (per question in order `q`, `header`, `multi`, option count, and per option in order `label` and `description`; strings byte for byte). Each option's `result` and the form's `kind` are not compared, so a Gate form and an `ask` form with the same compared fields are refused too. Otherwise main's answer would match two forms and `answer` would record nothing (two matches), so the form would be asked again for ever. Nothing is written; a broken other run is skipped. The CEO ends or answers the other run first.

## Errors
Bad slug, unknown kind, question or option count out of range, header over 12 characters, a non-Gate form with `result`, a Gate form without a `result` on every option, a Gate form with a `multi` question, an option label with a comma or with ` — `, a header with `]`, a line break in any question, header, label or description, two questions with the same text, unknown id → `refused: <reason>`, exit 1, nothing written.

`open` also refuses, each as `refused: <reason>`, exit 1, nothing written:
- `questions file unreadable` (cannot resolve or read), `questions file is not JSON`;
- `questions file is outside the repo`, `questions file is under .company`, `questions file path differs from its real path`, `questions file path letter case`, `questions file path is not an exact work path` (confinement, see Rules);
- `open form <id>`, `same questions open in run <other-slug>`, `no free form id`.

`open` and `again` also refuse `run ended` (the run is `ended`: the `answer` hook skips it, so a form there would be asked in vain). `again` also refuses `no open form with that id` and `same questions open in run <other-slug>`; `read` refuses `no such form`. Every CLI word refuses `bad slug`, `no run` and `usage` (an unknown word: `usage: <synopsis>`), and an argument over 4096 characters or holding a control, format or line/paragraph separator character `argument is not accepted`.
