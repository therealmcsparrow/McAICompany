New Contract. Provider: `scripts/lead-handover.mjs` (Node built-ins only). Mechanism: ADR 0049 (PreCompact and SessionStart hooks, a script-written Handoff), since v1.7 `docs/adr/0056-hard-handover-outside-agent.md` for the hand-over point. Writers of the record: the script only, through its hooks, its CLI and (v1.7) `contextHandover`. Consumers: the Lead (`read`, the injected Handoff), the Ship Gate summary and (v1.7) `context-guard` and `lead-session-mcp`. Uses `run-state` v1.6 (exported `active` and `show`, plus a read-only parse of the run's `ask` and `gate` lines under the same lstat and 64 KiB limits), `idea-flow` v1.1 (`state`) and `tier-sets` v1.2 (`readTierPath`, read-only).

## Constants
v1.7: no setup. The hand-over point is enforced by `context-guard`, not by the Claude Code compaction point, so `CLAUDE_CODE_AUTO_COMPACT_WINDOW` is no longer needed. Left set, a blocked compaction attempt prints one stderr line per turn; nothing else changes. Constants, exported by the script:
- `CAP = 95000` (the fixed Context cap), `HANDOVER_AT = 85500`. `AUTO_COMPACT_WINDOW` and `COMPACT_RESERVE` are removed.

## Where it lives
- Lead Handoff: `.company/work/<slug>/lead-handoff-<n>.md`, `<slug>` a work folder name (v1.4: new name or legacy slug `^[a-z0-9][a-z0-9-]{0,63}$`). `<n>` is 1 + the highest number among existing `lead-handoff-<n>.md` files and `handover` events. Exclusive create (`O_CREAT|O_EXCL`), at most 8 KiB, LF only.
- Record: `.company/work/<slug>/lead-handover.jsonl`. Append-only, one JSON object per line, at most 1000 lines of at most 512 bytes. Created once with exclusive create; every later open is an append that checks the file is a regular file with one link and the same `dev` and `ino` as its `lstat`; `O_NOFOLLOW` is ORed in only where it exists (never on win32). Every folder on the path is checked with `lstat` (no link, a directory).
- Active run: `active(root)` from run-state; else the 200 newest by modification time of the `.company/work/*/idea-flow.jsonl` files modified within 12 hours (all folders are listed first, at most 20000, so the cap never drops a newer flow) whose `state` form is not `ended`. None: the hooks do nothing.

## Record events
Keys in this order: `v` (1), `n` (line number), `at` (UTC time to the second), `ev`, then:
- `begin`: `playbook`.
- `base`: `base` (a full object id, 40 or 64 lowercase hex, not all zeros). At most one per record; written only by the Lead's `base` command, never from a Role file.
- `handover`: `file` (`lead-handoff-<n>.md`), `tokens` (integer or null), `window` (integer or null), `trigger` (`auto` | `manual` | v1.7 `context`); for trigger `context` only, then `session` (first 12 hex of the SHA-256 of the session id; the session id is never stored in clear). `auto` is no longer written during a run; old records stay valid.
- `resume`: `of` (the `<n>` of an earlier handover), `via` (`hook` when that handover's trigger was `auto`, `ceo` when `manual` or `context`).
Any other key, type or value breaks the record.

## Lead Handoff file
Frontmatter, derived and validated by the script only, in this order: `slug`; `playbook` (last `begin`, else the idea-flow kind, else `unknown`); `step` (`<NN> <role>` of the newest Step file, else `none`); `round`; `base-commit` (the `base` of the tier-path record, hex 7 to 40 and not all zeros; else the record's `base` event; else `unknown`; `unknown` when the tier-path record is unreadable; never read from a Role-written file); `risk-tier` (the tier-path record's current tier; `high` when that record is unreadable; with no record, the highest tier the run's files show); `tier-path` (`none`, `broken`, or `<feature|fix> <short|full>`); `tier-set` (an inline list of the record's current route entries, empty without a record); `gate` (`none`, `<brief|plan|ship> open` for an `ask` with no later `gate`, else `<gate> <passed|changed|stopped>`); `form` (`none`, `pending gate-<g>`, `pending idea-<grill|routes|tickets>`, `pending step-<idea step>`); `records` (an inline list of the existing files among `run-state.jsonl`, `idea-flow.jsonl`, `tickets.jsonl`, and always `lead-handover.jsonl`, which this write creates); `running: none` (a clean point); `tokens-at-handover` (integer or `unknown`); `window` (integer or `unknown`; `unknown` for trigger `context`); `trigger`. Then `## Next`: fixed template lines per state; v1.7, trigger `context` only, one more fixed line last: `- New session command: <command>`, `<command>` as `newSessionCommand` below. No file text, transcript text or model text is copied into it. An answer is a record event, so a form still open is `pending` and is asked again.

## CLI and hooks (cwd = product root)
- `watch` (PreCompact adapter): stdin JSON at most 64 KiB, one parse, allow-listed fields (`hook_event_name`, `transcript_path`, `trigger`, `agent_id`). Not `PreCompact`, `agent_id` present (a subagent), no active run, or any error: exit 0, nothing written. Tokens = the last main-chain assistant `usage` (input + cache creation + cache read + output) in the last 1 MiB of a regular `transcript_path` whose real path lies under the real `projects` folder of the Claude config dir; otherwise unknown. Transcript text is never read as instruction, stored or echoed. v1.7, by trigger: `auto` in an active run → always exit 2, one fixed stderr line, nothing written, whatever the tokens or Step state (no compaction during a run; spike run 8 in `tests/lead-handover/evidence.md`). `manual` → never blocked: a clean point writes the Lead Handoff and the `handover` event, a Step running writes nothing; exit 0 both (a stale Step record must not trap the CEO). With `AICO_CONTEXT_GUARD=off` in the process env, `watch` follows the v1.6 rule instead: a Step running and tokens below `CAP` → exit 2; tokens at or over `CAP` or unknown → exit 0, nothing written; a clean point writes the Handoff, exit 0. The script exits by itself after 4 seconds.
- `write <slug>`: the clean-point writer, trigger `manual`. Prints `wrote lead-handoff-<n>.md`. A Step running → `refused: step running`, exit 3 (retry at the next clean point).
- `resume` (SessionStart adapter, matcher `compact`): source other than `compact` or `agent_id` present: nothing. The newest handover of the active run with no later `resume` and an `at` within 10 minutes: the file is validated again (regular file, 8 KiB, exact key order, each value against its allow-list, slug equal to the run, `## Next` lines from the fixed templates); valid → prints `hookSpecificOutput.additionalContext` = one fixed header line that marks the file as data from the run records, then the file; appends `resume`. Otherwise, with an active run: one fixed line telling the Lead to run `lead-handover read '<slug>'` first. Always exit 0. v1.7: a new session started with the command gets no hook; its first line tells it to run `read`, and no `resume` is appended for it.
- `measure` (Stop adapter, v1.6): stdin as `watch` (at most 64 KiB, one parse, allow-listed fields); not `Stop`, `agent_id` present, no active run or unknown tokens: nothing written. Tokens by the `watch` rule (same transcript checks). Writes `.company/work/<slug>/lead-context.json` = `{"v":1,"session":"<12 hex>"|null,"ctx":<int|null>,"peak":<int>,"at":"<UTC s>"}` (v1.8: `session` = first 12 hex of the SHA-256 of the payload `session_id`, null when absent; the id is never stored; a four-key v1.7 file is read as `session` null and rewritten with the key), at most 256 bytes, LF, through a temp file in the same folder and a rename; the folder checks are those of the record (`exactWorkPath`, no link, real path inside the real work folder); an existing target that is not a regular one-link file is left alone. `peak` = the larger of the old valid peak and `ctx`, across sessions (run-wide; the Ship Gate `lead peak` line). Always exit 0, silent, self-exit after 4 seconds. `hooks/hooks.json` `Stop` entry: `node "${CLAUDE_PLUGIN_ROOT}/scripts/lead-handover.mjs" measure`, timeout 5, no matcher. The write changes the run folder's modification time once per Lead turn.
- `start` (SessionStart adapter, v1.8): stdin as `watch`; `source` `startup`, `resume` or `clear` only (not `compact`: the session and its reading continue), no `agent_id`, a `session_id`, an active run: writes `lead-context.json` with `session` = the new session, `ctx` null, `peak` = the old valid peak (0 without one), through the `measure` write rules. Anything else: nothing written. Always exit 0, silent, self-exit after 4 seconds. `hooks/hooks.json` `SessionStart` entry: matcher `startup|resume|clear`, `node "${CLAUDE_PLUGIN_ROOT}/scripts/lead-handover.mjs" start`, timeout 5.
- `begin <slug> <playbook>`: playbook `^[a-z][a-z0-9-]{0,40}$` with `skills/<playbook>/SKILL.md` in the plugin. Prints `begun`. v1.7: no second line, no settings file read.
- `base <slug> <id>`: the Lead runs it once at Step 01 after resolving the base commit. The id is 40 or 64 lowercase hex, not all zeros, else `refused: bad base`; a second call → `refused: base set`. Prints `recorded`.
- `read <slug>`: prints `handovers <n>`, `resumes hook <a> ceo <b>`, `last <file|none>`, then the `gate`, `form`, `step` and `running` lines `write` would use, then `base-commit`, `risk-tier`, `tier-path` and `tier-set` (`unknown` when not recorded), then (v1.6) `lead ctx <n|unknown>` and `lead peak <n|unknown>`, each followed by ` over cap` when the number is above `CAP`. A missing, oversize or malformed `lead-context.json`, or a `ctx` of null, is `unknown`.
- `ctx <slug> --json` (v1.6): prints `{"v":1,"ctx":<int|null>,"peak":<int|null>,"at":"<UTC s>"|null}`; without `--json` it is `refused: usage`.
- Every argument is at most 4096 characters without a character of category Cc, Cf, Zl or Zp, else `refused: argument is not accepted`, exit 3.
- Refusals exit 3: `usage`, `argument is not accepted`, `bad slug`, `wrong letter case` (v1.5), `bad playbook`, `bad base`, `base set`, `no run`, `step running`. Fail loud, exit 1: `broken record`, `link`, `not a regular file`, `hard-linked`, `too large`. In the hooks every error is exit 0 and silent, except the exit 2 above.

## Exports for the guard and the MCP server (v1.7)
No CLI command. Importing the script has no side effect.
- `transcriptTokens(path, claudeDir, sidechain = false)`: the `watch` token rule; `sidechain` is a positional boolean, true reads rows with `isSidechain` true (a Step file), false the main chain. Returns an integer or null.
- `findRun(root, now)`: the active-run rule above; a name or null.
- `contextHandover(root, slug, { tokens, session, now })`: writes the Lead Handoff and the `handover` event with trigger `context` and `session`, under the rules above. Serialised by an exclusive-create lock `.company/work/<slug>/lead-freeze.lock`, removed after the event; a lock older than 30 seconds is replaced. Holding no lock, or a Step running, it writes nothing and throws.
- `newSessionCommand(slug)`: `claude "<the new-session line>"`, the slug checked with `isWorkFolder`, else null. It is text only. The new-session line: `aico lead hand-over: run lead-handover read '<name>' first, as set out in references/lead-resume.md of the skill aico:pipeline, then follow that file.` (v1.8; v1.7 named `references/lead-handover.md`) It is for an empty session in a product folder, where no plugin path resolves. The v1.4 `resume` fixed line stays as it is.
- `claudeDirOf(env)`: an absolute `CLAUDE_CONFIG_DIR`-style config dir from `env`, else `<home>/.claude`.
- `workDir(root, slug)`: the folder path when every folder on its path passes the `lstat` checks above and its real path is inside the real work folder; else null.
- `lstatOrNull(path)`: the `lstat` result, or null on any error.
- `openRegular(file, flags)`: `{ fd, size }` under the record's open checks (regular file, one link, same `dev` and `ino`); null when it is not safe; throws when the open fails. The caller closes `fd`.
- `readSmall(file, max)`: the whole file as text under those checks; null when missing, unsafe or over `max` bytes.
- `iso(ms)`: UTC time to the second, the record's `at` shape.
- `loadRecord(dir)`: the validated events of `lead-handover.jsonl` in `dir`; empty when the file is missing; throws on a broken record.
- `main(argv, root, env)`: the CLI without a process exit; returns an object with `code` and `out`. `lead-session-mcp` calls it for `read` only, and matches the `running:` line of `read`.

## Personal data and destinations
The record and the Handoff hold enums, numbers, a base commit, file names and (v1.7) a truncated session hash; no transcript text and no CEO words. Destinations: the Handoff text goes to the Claude model of the next context (inside the fixed header); token counts go to the local record only; nothing else leaves the machine and McSparrow adds no recipient. Location `.company/work/<slug>/`, git-ignored where the product ignores `.company/`; archived, never deleted early; an erasure request overrides (CEO decides). Keep only what the decision needs (GDPR Art. 5(1)(c)).

## Error cases
- Broken record → CLI exit 1, hooks silent; the Lead runs `read` and stops if it also fails (fail closed).
- Handoff fails validation on resume → the fixed line is injected instead; the Lead reads the run records.
- Open Gate or form: never taken from the Handoff's `gate` or `form` lines alone; the Lead reads `run-state` and `idea-flow options` and shows the form again.
- v1.7, stale Step record: the Lead stays unfrozen and `auto` compaction stays blocked; only manual `/compact` helps (`context-guard` v1, Limits).

## Compatibility
New Contract, v1; v1.1 to v1.6 are additive. v1.7 adds a trigger, a key and exports and keeps every record and Handoff valid, but changes `watch` and `begin` behaviour and removes two constants: flagged for the Gate. An added event, key or command needs a new version.
