# Contract: review-loop v1.1

Provider: `scripts/review-loop.mjs` (Node built-ins only; `main(args, { root, now })`, `readReviewLoop(root, slug)` exported). Writer of the record: the script, for the Lead. Consumers: the Lead (pipeline reference `review-loop`), the Ship Gate list. Uses: `handoff` v2.0 (`contests`, `parseLocations`), `work-folder-name` v1 (`isWorkFolder`, `branchId`).
v1.1: the slug is a work folder name, new or legacy; the run ref is built from its branch id. Rationale: `docs/adr/0041-review-loop-record.md`.
A reviewer that did not run is never a clean pass. A forged record can only add Gate items or end Fix rounds early; it can never mark a review clean.

## Record
`.company/work/<slug>/review-loop.jsonl` (slug a work folder name per `work-folder-name` v1: new or legacy; any other value is refused, never echoed; `readReviewLoop` throws `TypeError`): append-only, LF, a line at most 512 bytes, the file at most 64 KiB and 500 lines. Run folder and file checked with `lstat` (a plain folder; a regular file with one hard link; a link refused); the first line is written with `O_CREAT|O_EXCL`, every append re-checks the opened handle against `lstat` (regular, one link, same device and inode), as `plan-tasks` v1.

| Key | Value | On |
|---|---|---|
| `v` | `1` | all |
| `at` | UTC time `YYYY-MM-DDTHH:MM:SSZ` | all |
| `ev` | `attempt`, `notrun` or `mark` | all |
| `role` | a review Role (below) | attempt, notrun |
| `round` | integer 0-5 | all |
| `step` | string `NN`, the Step number of the first dispatch (`^\d{2,3}$`) | attempt, notrun |
| `reason` | `crash`, `no-handoff` or `lint` | attempt, notrun |
| `commit` | full object id (40 or 64 hex) | mark |

Each line has exactly the keys of its `ev`. `readReviewLoop` is fail-loud like `readParallel`: it throws `ReviewLoopRecordError` on a bad line, a size or line limit, a link, a non-UTF-8 file or a missing final LF. A missing file reads as no events.
Review Roles: `code-reviewer`, `fresh-reviewer`, `qa`, `security`, `pentester`, `vuln-scanner`, `senior-engineer`, `accessibility-tester`, `hands-on-tester`, `persona-tester`, `legal`.

## Commands
Exit 0 done, 1 unreadable record or git failure, 2 a stop the Lead must act on (churn found or unknown), 3 refused (`refused: <reason>`, nothing written). An argument with a control character or over 4096 characters → exit 3. Every `--base` and every id is an anchored full hex id of the repository's object format (`rev-parse --show-object-format`: `sha1` 40, `sha256` 64) checked before it reaches git.

- `attempt <slug> <step> <role> <round> <reason>`: the first failure of (role, round, step) appends `attempt` and prints `retry <role>`; the second appends `notrun` and prints `not run <role> round <round>`. A further call for a (role, round, step) that is already `notrun` → refused.
- `mark <slug> <round> --base <full id>`: run before the builder dispatch of Fix round `<round>`. `symbolic-ref --quiet HEAD` must print `refs/heads/aico/<branch id>` (`branchId(<slug>)`: a legacy slug maps to itself, a new name to its lowercase hyphen form); the run ref resolves to a commit; `--base` is an ancestor of it (`merge-base --is-ancestor`: exit 0 yes, exit 1 refused, anything else a git failure, exit 1). Appends `mark` with that commit. The record already holds a `mark` for `<round>` → `refused: round <round> already marked`, nothing written.
- `churn <slug> <round> --base <full id>`: hunks (`--unified=0`, new side) of the judging diff from the round's `mark` commit to `refs/heads/aico/<branch id>`; the lineages (`handoff` v2.0 `contests`) whose first holder is a code-mode reviewer Handoff (not a plan-mode `fresh-reviewer` one) with `round: <round>`. A lineage whose `parseLocations` overlap a hunk (a deletion hunk `+s,0` overlaps lines s and s+1; a whole-file location overlaps any hunk of that file; a binary file changed counts as one hunk over the whole file) prints `churn <key> <path>:<n>` (the first overlapping line), then `fixed-before <key>` for each earlier lineage (first holder in an earlier round) with a location in that path, exit 2. Otherwise `churn: none` (exit 0), plus `churn: <k> rows without a location` when `k` > 0. No `mark`, two `mark` lines for the round, a record that cannot be read, `--base` not an ancestor of the mark commit, the mark commit not an ancestor of the run ref, HEAD not on the run ref, a graft hit or any git failure → `churn: unknown`, exit 2: the Lead escalates (fail toward the CEO).
- `gate <slug> [--base <full id>]`: the Ship Gate lines. Every `notrun` prints `not run <role> round <n>`; for `security`, `pentester` and `vuln-scanner` it prints `blocking: not run <role> round <n>`. Each marked round's `churn` and `fixed-before` lines (needs `--base`; a marked round without it prints `churn: unknown`, exit 2). `single <key> <path>` per Blocking finding (state open, contested, escalated, upheld or rejected) of one of `code-reviewer` and code-mode `fresh-reviewer` that no Blocking finding of the other overlaps (a finding with no readable location prints `single <key> ?`), only when both reviewers have a Handoff in the run (a `code-reviewer` Handoff and a code-mode `fresh-reviewer` Handoff, judged from the files, not from their findings); each such Handoff is read with the record checks (the real run folder equals the real repo root joined with `.company/work/<slug>`, compared case-insensitively on win32 and darwin; the real path equals the lexical path inside it, a regular file with one hard link, at most 64 KiB, the opened handle matches `lstat`), and a miss prints `single: unknown`, exit 2; one reviewer blocking while the other is clear prints a `single` line. Nothing to report → `review-loop: nothing to report`. Exit 0, or 2 when a line is `churn: unknown` or `single: unknown`.

## Git
`execFile`-style calls with fixed argument lists, no shell, 30 s and 8 MiB per call; a signal, a timeout, a spawn error or an output over the cap is a failure, as is every non-zero exit that is not a documented "no" (git.M4). The env is `process.env` without any key that starts with `GIT_` (case-insensitive) plus only `GIT_NO_REPLACE_OBJECTS=1`, `GIT_GRAFT_FILE=<absent temp path named aico-no-grafts-<16 hex>>` and, on the judging diff only, `GIT_LITERAL_PATHSPECS=1`. `rev-parse --show-toplevel` runs once and is the cwd of every later call. Before every later call `rev-parse --git-path info/grafts` is read (with `GIT_NO_REPLACE_OBJECTS=1` and no `GIT_GRAFT_FILE`) and `lstat`ed; anything there ends the command. Every later call starts `--no-replace-objects --no-optional-locks -c core.fsmonitor=false`; the judging diff adds `--literal-pathspecs -c diff.ignoreSubmodules=none` and `diff --no-ext-diff --no-textconv --no-color --no-relative --ignore-submodules=none … --no-renames --end-of-options <mark commit> refs/heads/aico/<branch id> --`: two fixed endpoints, never `HEAD`. A path that `--numstat -z` calls binary is decided by blob content (no NUL in the first 8000 bytes of either side is text); text is re-read once with `--text`, one path, after `--name-only -z` listed exactly that path.

## Lead flow
Pipeline reference `review-loop`. A review Role's Step that crashes, writes no Handoff or fails the lint → `attempt`; `retry` → re-dispatch once; `not run` → no further dispatch, the round is not clean and the line goes on the Ship Gate list (Plan Gate for the plan reviewer). `mark` before every Fix round's builders (a refused `mark` → the Lead stops and asks the CEO); `churn` after its reviewers; any `churn` or `churn: unknown` line → stop Fix rounds and escalate in the existing escalation form with both findings. `pipeline.fix_rounds` is unchanged. A `blocking:` line is a Blocking Ship Gate line the CEO must answer (re-run that lane or block the ship), never only a list line. The second reviewer: at tier high with the setting on, `fresh-reviewer` (code mode) runs beside `code-reviewer` in round 0 and in each Fix round where it blocked; never a third reviewer.
