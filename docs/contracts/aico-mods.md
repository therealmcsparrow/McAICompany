## Shape
- One hooks module for the plugin; one file per mod: `mods/savvy.tsx`, `mods/cache-tax.tsx`, `mods/reflect.tsx`, `mods/plan-gate.ts` (v1.3), `mods/fresh-step.ts` (v1.6); shared code in `mods/shared/*.ts` (incl. `status.ts`, the status composer); pure logic (parsers, formatters, the status line builder, the cache clock, JSON guards, the Lesson text rule `lesson-text.mjs`, the progress bars `bars.mjs` (v1.1), the context rows `ctx-row.mjs` (v1.6)) in `mods/lib/*.mjs` with no `$`, no Node import and no npm package, so `npm test` covers it. The write gate is `mods/reprompt-gate.ts` with `mods/lib/reprompt-gate.mjs`; M6's logic is `mods/lib/fresh-step.mjs`.
- `types/index.d.ts` declares `interface PluginState { aico: … }`; `plugin.json` names it under `"types"`. State keys (all `Shaped<…>`, shape tag `v1`): `settings`, `run`, `agents` (a family keyed by `agentId`), `cost`, `cacheClock`, `reflect`, `ctx` (v1.6, the Savvy context counts: `lead` and `agents[{id, ctx}]`, int or null). The status parts are not a state key (see "Status line").
- No `import()`, no module-level state the views draw from (a reload loses it), no `$.fs.write`, no network. Module-level bookkeeping that no view draws from is allowed: the script caller's availability (`run-script.ts`) and the status composer's parts (`status.ts`).
- Validator rules (SP-M1, Claude Code 2.1.310): `$` is passed only to functions declared at the top level of a module file (or imported from the mod's own files), never to a closure declared inside `register`; keep `register` thin. `$.ui.invalidate('ui.render')` takes the event name and is called directly, never bound or optional-chained. `$.plugin.root` is a string property; `$.session.root()` is a call. `update` works only on an atom declared in the same file.
- Surfaces: views draw on `terminal` and `desktop`; on `vscode` and `mobile` every `ui.render` hook returns `next(e)`.
- **Proof per surface (SP-M1).** `terminal` is proven on Windows (pane, status line, toast, `$.process.run`, `$.session.root()`, `$.plugin.root`, `fs.stat` tick; also under `claude -p`, where `ui.open` answers `isPlaced: false`). `desktop` is **unverified**: no desktop app on the test machine, only `claude plugin test` mounts with `surface: 'desktop'`, and the API documents `$.process` as CLI only. So every script-sourced field must degrade: where `$.process` is missing or `process.run` rejects, the field shows `unknown` and the view still draws.

## Calling a script
- `$.process.run(['node', <$.plugin.root>/scripts/<name>.mjs, …args], { cwd: <$.session.root()>, timeoutMs })`: no shell. `timeoutMs`: 1000 for `settings.mjs get` and `run-state.mjs` (also M6's direct call); 5000 for `ledger.mjs report` and `ledger.mjs agent-ctx` (`TIMEOUT_MS.agentCtx`); 1000 for `lead-handover.mjs ctx` (`TIMEOUT_MS.leadCtx`; `run-script.ts` `ScriptName` adds `lead-handover`); 5000 for `reflect.mjs step` and `lessons.mjs accept`; 5000 for the reprompt gate's `reprompt-check.mjs arm`; 10000 for `reflect.mjs retro`.
- Spawn cost (SP-M1, Windows terminal): p50 about 31–41 ms, p95 40 ms idle and up to about 300 ms in the first seconds of a session. So **no `session.start` hook awaits a script**: it returns `next(e)`, and each field fills when its call settles (until then `unknown`). The only hooks that await a script are the reprompt gate's `agent.spawn` (`arm`, 5 s cap) and M6's `session.send` (model origin only) and `agent.spawn` (`resume` only), 1 s cap, as a direct call like the plan Gate's, not through `run-script.ts`.
- Availability: the script caller (`mods/shared/run-script.ts`) checks once per session that `$.process.run` exists, in a form `claude plugin validate` accepts; missing → every script-sourced field `unknown` for the session, no retry loop.
- Exit code ≠ 0, timeout, rejection, stdout over 256 KiB, invalid JSON or a JSON value that fails the mod's allow-list guard (`mods/lib/guard.mjs`: known keys, types, ranges) → that field shows `unknown`. Never a guessed value, never a thrown hook, never a session error (AC38). Stdout is trimmed of a trailing CR/LF before parsing (Windows prints CRLF).
- Untrusted text (Handoff lines, Role names, paths) is drawn with `Text` only, never `Markdown` or `Link`; control characters are replaced and each value is cut to its stated length.

## Refresh
- Settings: `get` at `session.start` and at every main-loop `turn.start`; a change takes effect by the next turn (AC36).
- Active run: `run-state.mjs active --json` at `session.start`, then a `$.clock.every(2000)` tick that `stat`s the sources and calls a script only when an mtime or size changed; while no run is active the tick checks `.company/work/` every 10 s at most (one `fs.list`, at most 200 entries). Views update within 5 s of a Step start (`agent.spawn`) or a Handoff write (AC40).
- The cache clock recomputes on the same tick from the stored request time; it calls no script.
- Timers start only for mods that are on; a mod switched off cancels its timers.

## Status line
One status line for the plugin, in compact form, on **one terminal row of 80 columns** (CEO: the terminal wraps at 80). The full details stay in the panes, the toast and the log. **Only `mods/shared/status.ts` calls `$.ui.status`**; no other file under `hooks/` or `mods/` does (a text test pins it). A plugin's hooks never see its own `$.ui.status` calls, so no `ui.status` hook may try to merge text.
- **API** (`mods/shared/status.ts`):
  - `setStatusPart($, key, text): Promise<void>`, `key` one of `version | savvy | cost | reflect` (`version` is set only by the shell's `session.start` hook); `text` a string, or `undefined` to remove the part. Never throws; never rejects.
  - `resetStatus(): void`: forgets every part and the last written line; writes nothing. Called by the shell's `session.start` hook before `next(e)` (next to `resetScriptCaller`).
- **Parts** (each mod owns exactly one key and only ever sets its own):
  | Key | Owner | Text | Cap (cells) |
  |---|---|---|---|
  | `version` | shell | `v<x.y.z>`, e.g. `v0.20.0`; absent when `plugin.json` is unreadable or its `version` is not `x.y.z` | 8 |
  | `savvy` | Savvy | `W<wave> S<step> <role> <elapsed>`, e.g. `W3 S12 ba-eng 14m`; role cut to two letters per leading word and three for the last (no role → left out); after `end` `ended <outcome> <elapsed>`; any other state its name (`stale`) | 17 |
  | `cost` | Cache Tax | `<n> tax <m>m\|exp\|?`, e.g. `12.4k tax 60m` (`n` is the run's cache write count, `fmtCompact`) | 13 |
  | `reflect` | Reflect | `<n> lessons` (`1 lesson`), the count of pending suggestions | 10 |
  `fmtCompact(n)` (`format.mjs`): a safe integer ≥ 0 under 1000 prints as is; above, one of `k M G T` with one decimal under 100 (`12.4k`, `98.8M`) and none from 100; at most 7 cells; anything else → `?`. The pane keeps the exact integers (AC42).
- **Line** (built by `composeStatus(parts, options?)` in `mods/lib/status.mjs`, pure): the non-empty parts in priority order `version · savvy · cost · reflect`, joined with ` · `. **No own prefix**: the host already prints `⚠ aico: ` in front of the line (SP-M1 saw `⚠ <plugin>: <text>`), so an own `aico · ` only repeats it. Each part is cleaned first (control characters and line breaks become spaces, runs of spaces collapse, trimmed; non-string values, unknown keys and own keys `__proto__`/`constructor`/`prototype` are ignored), then cut to its cap in terminal cells with `…` (`fit` from `format.mjs`). **Idle part.** `composeStatus(parts, { idle: true })` (the composer in `status.ts` always passes it) puts `aico idle` (`IDLE`, 9 cells, inside the `savvy` cap of 17) in the first slot when no `savvy` part is set, so a session with no run shows `v0.20.0 · aico idle`. Any Savvy part (running, `ended`, `stale`) replaces it. Without the option, no part → `undefined`. The shell's `session.start` hook writes the idle line at once (`showStatus`), so the line is never empty because a mod loaded late.
- **Ready toast.** After the settings call settles, the shell's `session.start` hook shows one toast `aico <x.y.z> mods ready: Savvy, Cache Tax, Reflect` (the version words `<x.y.z> ` are left out when the version is unknown; only the mods that are on in the resolved settings; `none on` when all are off; `aico <x.y.z> mods ready (settings unknown): …` with the defaults when the call failed; `readyText` in `mods/lib/ready.mjs`). No model call; the hook does not wait for it.
- **Width budget.** The row is `STATUS_COLUMNS` = 80. The host prefix `⚠ aico: ` takes 8 cells; `HOST_RESERVE` = 10 keeps 2 spare for a glyph drawn 2 cells wide or a footer indent. So `STATUS_MAX` = 70 cells for the mod's own text, and the caps add up so that all four parts at their cap fit: 8 + 17 + 13 + 10 + 3 × 3 = 57 ≤ `STATUS_MAX`, and `STATUS_MAX + HOST_RESERVE ≤ STATUS_COLUMNS` (tests pin both sums). As a backstop only (a cap changed later, `options.max` in tests), parts are dropped from the right (reflect, cost; never the version) and then the first remaining part other than the version is cut with `…`. No terminal width is read: `bodyColumns` belongs to a pane and a docked `viewport.columns` is the transcript side (SP-M1). Priority runs left to right, so a host cut at the right edge loses the lowest part first. QA checks on a real terminal at 80 columns, with all four parts at their cap, that the line stays on one row; a wider host prefix raises `HOST_RESERVE` and lowers the caps to match.
- **AC35 summary.** Each part is its mod's one-line summary in compact form, every field within its cap, so with `pane: auto` and no dock (`isPlaced: false`, below 110 columns, `claude -p`) the Savvy and the Cache Tax summaries stand on the line together. What the compact form leaves out (slug, Fix round, Gates, Names, spend and exact counts, expiry clock time) is in the panes, the toast and the log.
- **Cadence.** The composer has no timer. `setStatusPart` stores the part, builds the line at once (synchronously, before any `await`, so the newest call always carries every part) and calls `$.ui.status` only when the line differs from the last line it wrote. Mods do not de-duplicate their own part: Savvy and Cache Tax set theirs on every tick (2 s) while on, Reflect when its pending count changes. With minute-resolution elapsed time the line changes about once a minute in a quiet run (it changed every 2 s before).
- **Failure and reset.** A rejected `$.ui.status` call is swallowed and the next `setStatusPart` writes again. After `resetStatus()` or a reload of the hooks module the first built line is always written, even `undefined`, so a stale line from before is replaced. Savvy and Cache Tax set their parts again within one tick.

## Panes
- Every state is text: `[tax]` marks cache writes, `running`, `unknown`, `warn`, `expired`; colour is never the only carrier and no colour is used when `NO_COLOR` is set (AC39).
- Panes: `aico-run` (Savvy), `aico-cost` (Cache Tax), `aico-reflect` (Reflect). Commands registered at `session.start`: `aico-run`, `aico-cost`, `aico-reflect` (each opens its pane; `{ text }` answer only when the mod is off: `<mod> is off; switch it on in /aico:settings`).
- **Width (SP-M1, 2.1.310).** A pane lays out to `e.props.bodyColumns`, never `e.viewport.columns` (docked, `viewport.columns` is the transcript side). Docked panes measured 39 (110 terminal columns) to 89 cells (200 columns); an asked pane below 110 columns draws `inline` (86 cells at 90 columns). Each view has a layout for 39 cells: values cut with `…`, no row wider than `bodyColumns`.
- **Unasked open.** `pane: auto` calls `$.ui.open` unasked only when a run becomes active; it docks only at 110 terminal columns or more (`isPlaced: false` below, and under `claude -p`). Then the compact one-line summary stays on the status line (AC35). An asked open (the command) works at any width. The `plugin-authoring` skill's "144 columns" does not hold in 2.1.310.

## M1 Savvy
- Active run (`run-state` v1) only; none → no pane content, no status part, no timer beyond discovery (AC41).
- Shows: task slug, wave, current Step and Role with Name, Gates passed (`brief, plan`), Fix round, elapsed run time; one line per running subagent: Step, Role (Name), elapsed. Current Step = the highest Step of a running subagent, else the newest Step file. After `end`: the final state with outcome and total time, until the next run starts or the session ends.
- **Context rows (v1.6).** Each running-subagent line ends with `ctx <n>` (`ctx 90.0k`: whole tokens below 1000, else thousands with one decimal), then ` near cap` past 85500 and ` over cap` past 95000 (words, never colour alone), or `ctx ?` when unknown. A `Lead ctx <n>` row (same form) is the first pane row while a run is known; `Lead ctx ?` until a reading is there. Pure text in `mods/lib/ctx-row.mjs`. A row is never cut inside the note: when a subagent line leaves under 12 cells for its label (about 35 columns and less), the label takes its own row and the elapsed time, `ctx <n>` and the note follow in rows that break only between those parts (the Lead row breaks the same way).
  - Subagents: `ledger.mjs agent-ctx <ids> --json`, ids in chunks of 8, at most 5 calls per poll, one after another (`TIMEOUT_MS.agentCtx` 5000), on its own 10 s timer apart from the 2000 ms tick, doing nothing while no subagent runs or no run is known. Its own in-flight flag: a poll still running at the next 10 s mark starts no second poll. An id is sent only if it matches `^[A-Za-z0-9_][A-Za-z0-9_-]{0,63}$` (the ledger's pattern without a leading dash, so it never reads as an option); other ids are not sent and show `ctx ?`. Ids go only into argv and are never drawn. The answer passes the allow-list `guardAgentCtx` (`{"v":1,"agents":[{"agent","ctx":<int>|null}]}`, at most 8 entries, ctx 0 to 10000000); counts are matched by id, an id not answered is `ctx ?`.
  - Lead: `lead-handover.mjs ctx '<slug>' --json` (`TIMEOUT_MS.leadCtx` 1000), in the 2000 ms tick, when the mtime or size of `.company/work/<slug>/lead-context.json` changes (a missing file reads as one state, so one call per run). Guard `guardLeadCtx` (`ctx`, `peak`, `at` present, integer or null).
  - Any failure (timeout, exit, invalid JSON, guard) draws `?` and never blocks the pane; every v1.5 row stays as it was, and the status line is unchanged except for the cap note below.
  - **Cap note in the status part (CEO, Fix round 4).** While any running subagent or the Lead is past 85500 (`near cap`) or 95000 (`over cap`), the running form of the `savvy` part is `W<wave> S<step> <note>`, e.g. `W3 S12 over cap` (`over cap` wins when both occur; role and elapsed stay in the pane). With none past 85500, or when the run is not `running`, the part is the form below, byte for byte. Unknown counts add no note. `worstNote` in `mods/lib/ctx-row.mjs`.
- Status part (`savvy`): `W<wave> S<step> <role> <elapsed>`, after `end` `ended <outcome> <elapsed>`; full details stay in the pane; elapsed in whole minutes (`0m`, `12m`, `1h05m`; the pane keeps seconds); each `unknown` field prints `?`. Widest usual running form `W3 S12 ai-da-eng 1h05m` = 22 cells.
- **Progress bars (v1.1).** Two pane rows, directly after `Elapsed` and before the subagent lines, built by `progressRows(view, width)` in `mods/lib/bars.mjs` (pure; `view` is the guarded run view or `null`):
  - Gates row: `Gates <n>/3 [<bar>] last: <last>`, e.g. `Gates 1/3 [###-----] last: brief`. `n` = how many of `brief`, `plan`, `ship` have a `passed` record in the view's `gates`; `<last>` = the gate of the latest such record; `n` = 0 → `last: none`. `changed` and `stopped` records do not count.
  - Steps row: `Steps <d>/<t> [<bar>]`, e.g. `Steps 5/8 [#####---]`. `t` = the length of the view's `steps`, `d` = those with `status: done`. `t` = 0 → `Steps 0/0` with no bar.
  - Count first (Fix round 1, accessibility): the numeric count comes right after the label, so a screen reader speaks it before any bar glyph. Bar: ASCII only, `#` for done cells and `-` for the rest, in brackets after the count. **One cell count for both rows:** cells = `min(20, width − 3 − w)`, `w` = the wider of the two rows written without a bar. Done cells = `round(cells × count / total)`, then held at `cells − 1` while `count < total` and at 1 or more while `count > 0` (8 cells: `1/3` → 3, `5/8` → 5). Fewer than 4 cells → no bar and no brackets in either row. Still too wide → drop ` last: <last>`, then shorten the labels to `G` / `S`; the numeric count is never dropped (`S 200/200` fits 10 cells). Width = the pane's `bodyColumns` (10–400, else 39, as today).
  - Ended `ship` run (`state: ended`, `outcome: ship`): both bars full, `Gates 3/3 … last: ship` and `Steps <t>/<t> …`. Ended `abort` shows the real counts.
  - Unknown: no view, `state` `none` or `unknown`, or a value that fails the guard → `Gates ?` and `Steps ?`, no bar.
  - The `Gates    <list>` row, the status part, the subagent lines and every other v1 row are unchanged. Mod off → no pane, so no bars.

## M2 Cache Tax
- One row per `report --json --live` row: Role (Name), Step, in, cache write `[tax]`, out, cache read, spend; numbers are exact integers equal to the JSON (AC42). A subagent seen in `agent.spawn` with no ledger row yet shows `running` in every count cell; `unreconciled` rows show `unknown`.
- Totals: spend, cache read, cache write and `cache write = <p>% of spend [tax]`. Status part (`cost`, only while a run is active): `<n> tax` (`n` = cache write total, `fmtCompact`; no ledger data → `?`), plus the cache clock below.
- **Cache clock (AC43 as re-scoped by the CEO; replaces keep-warm).** Shows when the main session's (the Lead's) cached prefix expires.
  - Lifetimes (SP-M3, 2.1.310): the main loop writes the 1-hour lifetime (1216 of 1217 main-loop requests), subagents write 5 minutes (2705 of 2705). Main-loop reuse held up to 60 min and broke after (62–70 min: floor only).
  - Expiry = time of the last main-loop request (newest `turn.step` without `agentId`, else `turn.start`) + its lifetime. Every main-loop request restarts it. Lifetime per request: from the event's usage split (`cache_creation.ephemeral_1h_input_tokens` / `ephemeral_5m_input_tokens`) when the installed API types carry it; otherwise the constant 60 min in `mods/lib/cache-clock.mjs`, labelled `1 h (measured)`. The M9 builder checks the types and implements exactly one of the two, named in its Handoff.
  - **Lifetime source (v1.9).** The turn events carry no split (build 2.1.322 types). While a run is active, Cache Tax reads `ttl` from `lead-handover.mjs ctx '<slug>' --json` (`lead-handoff` v2.2: the Lead transcript's split, written by the Stop adapter) when `lead-context.json` changes, through one guard: `"5m"` → 5 min, `"1h"` → 60 min, both labelled measured; `null`, a missing key, any other value, no active run or a failed call → 60 min, labelled assumed. The known lifetime stays in the `cacheClock` state (`lifetimeMs`, `source`) until a new reading or `session.start`; it applies from the last main-loop request on, so the status part and the pane line use it at once. Labels: `1 h (measured)`, `5 min (measured)`, `1 h (assumed)`. Never a script call per request, never a block.
  - Pane line (the `Lifetime: <label>` line under it as before): `Lead cache: expires <HH:MM> (in <m> min)`, `Lead cache: expired <HH:MM>; the next turn rewrites it`, or `Lead cache: unknown` (no main-loop request seen in this session yet, e.g. a mod loaded mid-session). Under it, always: `Subagent caches last 5 minutes; nothing keeps them warm.`
  - Status part, while a run is active: ` <m>m`, ` exp` or ` ?` (v1.9: minutes counted against the lifetime above; no label in the status part).
  - It never forks, pings or calls a model: SP-M3 found no evidence that a fork keeps the entry alive (a fork 55 min in did not read the main tail; the main loop's next request at 66 min read only the floor).

## M5 Plan Gate
A UX layer. It explains a refusal early; it enforces nothing. The Gate is enforced by `run-state gate <name> plan passed` and `plan-tasks begin`, `next` and `start` (`plan-check` v1.2, `run-state` v1.5, `plan-tasks` v1.2), which rescan every plan under `block` and trust no record. Always registered; no pane, no status part, no setting; "Off" does not apply.
- **Judged.** `tool.check` of the `Bash` and the `PowerShell` tools, only when the command is, character for character and with single spaces only, `node <path>/scripts/run-state.mjs gate '<name>' plan passed` or `node <path>/scripts/run.mjs run-state gate '<name>' plan passed`. `<path>` is empty or ASCII letters, digits and `_ . : / \ + @ -`, not starting with `-`; `'<name>'` is one single-quoted token with no quote inside whose content passes `isWorkFolder`; the old unquoted form with a legacy slug `^[a-z0-9][a-z0-9-]{0,63}$` is still judged; the command is at most 4096 characters. The same new name unquoted or double-quoted, a quoted name that fails `isWorkFolder` (`..`, `/`, `\`, a quote, `$`, a backtick, a trailing dot), a second quoted token, a chained, redirected, env-prefixed, multi-line, other-script, other-gate or otherwise differently shaped command is not judged: `next(e)`. No shell is evaluated and only the path and slug tokens meet a linear-time pattern.
- **Verdict.** `node <plugin>/scripts/plan-check.mjs verify <slug> --json` (5 s cap, no shell). Policy, state and count come only from its exit code and its `--json` object (`v` 1, `policy`, `state`, `count`, each checked against an allow-list; stdout at most 64 KiB, not truncated). No record file is read.
  - exit 2 (`block` with open decisions) → `deny`, reason `aico plan gate: <n> open decision(s); answer or settle them in the plan`;
  - exit 1, or any failure (timeout, rejection, bad JSON, other exit code): policy `block` → `deny`, reason `aico plan gate: plan-check error; fix the plan check, then retry`; otherwise a toast `plan-check error` and `next(e)`;
  - exit 0 with open decisions under `warn` → toast `aico plan gate: <n> open decision(s) (warn)` and `next(e)`; exit 0 otherwise → `next(e)`.
  - The policy used for a failure with no readable answer is the policy of the last answer this session (bookkeeping only; it never allows anything). A failure before any answer is not `block` to the mod: the scripts still refuse.
- **Records.** `tool.check` of `Write`, `Edit`, `MultiEdit` and `NotebookEdit` whose path (either slash form, case-insensitive, trailing dots or spaces and a stream suffix included) is `.company/work/<name>/run-state.jsonl` with a `<name>` that passes `isWorkFolder` → `deny` when the policy is `block` (read from `verify` for that slug), reason `aico plan gate: the run record is written by the run-state script only`; otherwise `next(e)`. A path that may reach a record but names no slug is judged fail-closed (`deny` with the same reason when the last policy this session is `block`, otherwise `next(e)`): a `.`, `..` or empty segment; an NTFS `:` stream suffix (a stream part never holds `/`); a `\\.\` or `\\?\` device root; a trailing dot or space on a segment; an 8.3 short-name segment (holding `~`) directly followed by `work`. Ordinary product files outside `.company` pass: `next(e)`.
- **Own failure.** The hook's `.catch`: a judged command or record path while the last policy is `block` → `deny` (`aico plan gate failed; refused`); otherwise `next(e)`.
- Deny and toast text hold counts and fixed words only, never plan text.
- Tests: `mods/test/plan-gate.test.tsx` (both tools, both surfaces, both command forms, mocked `plan-check` exit codes and output) and `scripts/plan-gate-lib.test.mjs` (`npm test`, hostile cases first).

## M6 Fresh Step
Steps are never resumed (pipeline §2, `docs/adr/0054-steps-never-resumed-hook.md`). Always on; no pane, no status part, no setting; "Off" does not apply.
- **Refused.** `session.send` with `origin.kind` `model` while a run is active → `{ isDelivered: false, reason }`; `agent.spawn` with `resume` while a run is active → `{ deny: reason }`. `reason` is `aico: Steps are never resumed; dispatch a fresh Step (next NN) with the old Handoff as input (pipeline §2)`. A failed run-state call appends ` (run state unreadable)`. The message text and agent ids are never logged or drawn.
- **Order** (fail closed, ADR 0017):
  1. Any other origin (plugin, another kind, absent, not an object), or a spawn without `resume` → `next(e)` at once, no call.
  2. No `.company/work` (`$.fs.stat` of `<session root>/.company/work`) → `next(e)`.
  3. M6's own run-state call throws a synchronous `TypeError` (no `$.process`, e.g. desktop) → `next(e)`.
  4. Own call, not through `run-script.ts`, `node <plugin>/scripts/run-state.mjs active --json`, 1000 ms and a 500 ms grace deadline: `ok` with `slug: null` → `next(e)`; `ok` with a slug → refuse; every failure refuses (timeout, rejection including a `TypeError` rejection, non-zero exit, stdout over the cap, invalid JSON, guard fail, a throw from `$.session.root()`).
- **Shared state.** M6 has none: the give-up state of `run-script.ts` (three failures with no success) belongs to the other mods and never reaches M6, so failures elsewhere cannot lock or unlock it. Each judged event spawns one run-state process.
- "A run is active" is `run-state active`, which keeps an unended run active for 12 h after its last activity; `run-state end` clears it.
- The model sees a refusal wrapped by the engine: `Not sent: a plugin hook refused it (<reason>).` for a send, `a plugin declined the resume: <reason>` for a resume. Hook reasons stay unwrapped.
- Tests: `mods/test/fresh-step.test.tsx` (both surfaces, every step of the order, every failure) and `scripts/fresh-step-lib.test.mjs` (`npm test`, hostile cases first, the registration order). Step 3 (the synchronous `TypeError` at the call) is tested by calling the exported `runStateVerdict` with a fake `$` that has no `process` key.

## Tokens (AC37)
No mod adds a system-prompt section, a context block, a `$.session.append` row, a `$.prompt.submit` or a dispatch. The only model call is Reflect `model` mode (off by default, user level only), ledgered.

## Off
A mod that is off registers its hooks but each returns `next(e)` at once, draws nothing, runs no timer and calls no script; its options stay in settings (AC36). It removes its own status part once (`setStatusPart($, <key>, undefined)`) and sets none after; it never touches another mod's part.
