## Shape
- One hooks module for the plugin; one file per mod: `mods/savvy.tsx`, `mods/cache-tax.tsx`, `mods/reflect.tsx`, `mods/blast-radius.ts`, `mods/plan-gate.ts` (v1.3), `mods/fresh-step.ts` (v1.6); shared code in `mods/shared/*.ts` (incl. `status.ts`, the status composer); pure logic (parsers, formatters, the status line builder, the git-commit detector, the cache clock, JSON guards, the Lesson text rule `lesson-text.mjs`, the progress bars `bars.mjs` (v1.1), the context rows `ctx-row.mjs` (v1.6)) in `mods/lib/*.mjs` with no `$`, no Node import and no npm package, so `npm test` covers it. The write gate is `mods/reprompt-gate.ts` with `mods/lib/reprompt-gate.mjs`; M6's logic is `mods/lib/fresh-step.mjs`.
- `types/index.d.ts` declares `interface PluginState { aico: … }`; `plugin.json` names it under `"types"`. State keys (all `Shaped<…>`, shape tag `v1`): `settings`, `run`, `agents` (a family keyed by `agentId`), `cost`, `cacheClock`, `reflect`, `blast`. The status parts are not a state key (see "Status line").
- No `import()`, no module-level state the views draw from (a reload loses it), no `$.fs.write`, no network. Module-level bookkeeping that no view draws from is allowed: the script caller's availability (`run-script.ts`) and the status composer's parts (`status.ts`).
- Validator rules (SP-M1, Claude Code 2.1.310): `$` is passed only to functions declared at the top level of a module file (or imported from the mod's own files), never to a closure declared inside `register`; keep `register` thin. `$.ui.invalidate('ui.render')` takes the event name and is called directly, never bound or optional-chained. `$.plugin.root` is a string property; `$.session.root()` is a call. `update` works only on an atom declared in the same file.
- Surfaces: views draw on `terminal` and `desktop`; on `vscode` and `mobile` every `ui.render` hook returns `next(e)`. The Blast Radius gate is not a view and acts on every surface.
- **Proof per surface (SP-M1).** `terminal` is proven on Windows (pane, status line, toast, `$.process.run`, `$.session.root()`, `$.plugin.root`, `fs.stat` tick; also under `claude -p`, where `ui.open` answers `isPlaced: false`). `desktop` is **unverified**: no desktop app on the test machine, only `claude plugin test` mounts with `surface: 'desktop'`, and the API documents `$.process` as CLI only. So every script-sourced field must degrade: where `$.process` is missing or `process.run` rejects, the field shows `unknown` and the view still draws. On such a surface Blast Radius counts the failed `review-depth` call as a security hit and asks (or denies with no approver).

## Calling a script
- `$.process.run(['node', <$.plugin.root>/scripts/<name>.mjs, …args], { cwd: <$.session.root()>, timeoutMs })`: no shell. `timeoutMs`: 1000 for `settings.mjs get` and `run-state.mjs` (also M6's direct call); 5000 for `ledger.mjs report` and `ledger.mjs agent-ctx` (`TIMEOUT_MS.agentCtx`); 1000 for `lead-handover.mjs ctx` (`TIMEOUT_MS.leadCtx`; `run-script.ts` `ScriptName` adds `lead-handover`); 5000 for `reflect.mjs step`, `lessons.mjs accept` and the pre-review `review-depth`; 5000 for the reprompt gate's `reprompt-check.mjs arm`; 10000 for the commit gate's `review-depth` and `reflect.mjs retro`.
- Spawn cost (SP-M1, Windows terminal): p50 about 31–41 ms, p95 40 ms idle and up to about 300 ms in the first seconds of a session. So **no `session.start` hook awaits a script**: it returns `next(e)`, and each field fills when its call settles (until then `unknown`). The only hooks that await a script are Blast Radius's `tool.check` (commit gate), its pre-review `agent.spawn` (5 s cap), the reprompt gate's `agent.spawn` (`arm`, 5 s cap) and M6's `session.send` (model origin only) and `agent.spawn` (`resume` only), 1 s cap, as a direct call like the plan Gate's, not through `run-script.ts`.
- Availability: the script caller (`mods/shared/run-script.ts`) checks once per session that `$.process.run` exists, in a form `claude plugin validate` accepts; missing → every script-sourced field `unknown` for the session, no retry loop.
- Exit code ≠ 0, timeout, rejection, stdout over 256 KiB, invalid JSON or a JSON value that fails the mod's allow-list guard (`mods/lib/guard.mjs`: known keys, types, ranges) → that field shows `unknown`. Never a guessed value, never a thrown hook, never a session error (AC38). Stdout is trimmed of a trailing CR/LF before parsing (Windows prints CRLF).
- Untrusted text (Handoff lines, Role names, paths) is drawn with `Text` only, never `Markdown` or `Link`; control characters are replaced and each value is cut to its stated length.

## Refresh
- Settings: `get` at `session.start` and at every main-loop `turn.start`; a change takes effect by the next turn (AC36).
- Active run: `run-state.mjs active --json` at `session.start`, then a `$.clock.every(2000)` tick that `stat`s the sources and calls a script only when an mtime or size changed; while no run is active the tick checks `.company/work/` every 10 s at most (one `fs.list`, at most 200 entries). Views update within 5 s of a Step start (`agent.spawn`) or a Handoff write (AC40).
- The cache clock recomputes on the same tick from the stored request time; it calls no script.
- Timers start only for mods that are on; a mod switched off cancels its timers.

## Status line
One status line for the plugin, in compact form, on **one terminal row of 80 columns** (CEO: the terminal wraps at 80). The full details stay in the panes, the toast and the log. **Only `mods/shared/status.ts` calls `$.ui.status`**; no other file under `hooks/` or `mods/` does (a text test pins it). A plugin's hooks never see its own `$.ui.status` calls, so no `ui.status` hook may try to merge text.
- **API** (`mods/shared/status.ts`):
  - `setStatusPart($, key, text): Promise<void>`, `key` one of `version | savvy | blast | cost | reflect` (`version` is set only by the shell's `session.start` hook); `text` a string, or `undefined` to remove the part. Never throws; never rejects.
  - `resetStatus(): void`: forgets every part and the last written line; writes nothing. Called by the shell's `session.start` hook before `next(e)` (next to `resetScriptCaller`).
- **Parts** (each mod owns exactly one key and only ever sets its own):
  | Key | Owner | Text | Cap (cells) |
  |---|---|---|---|
  | `version` | shell | `v<x.y.z>`, e.g. `v0.20.0`; absent when `plugin.json` is unreadable or its `version` is not `x.y.z` | 9 |
  | `savvy` | Savvy | `W<wave> S<step> <role> <elapsed>`, e.g. `W3 S12 ba-eng 14m`; role cut to two letters per leading word and three for the last (no role → left out); after `end` `ended <outcome> <elapsed>`; any other state its name (`stale`) | 17 |
  | `blast` | Blast Radius | `⚠ <category>`, 60 s; before a review `rev <depth>` | 10 |
  | `cost` | Cache Tax | `<n> tax <m>m\|exp\|?`, e.g. `12.4k tax 60m` (`n` is the run's cache write count, `fmtCompact`) | 13 |
  | `reflect` | Reflect | `<n> lessons` (`1 lesson`), the count of pending suggestions | 9 |
  `fmtCompact(n)` (`format.mjs`): a safe integer ≥ 0 under 1000 prints as is; above, one of `k M G T` with one decimal under 100 (`12.4k`, `98.8M`) and none from 100; at most 7 cells; anything else → `?`. The pane keeps the exact integers (AC42).
- **Line** (built by `composeStatus(parts, options?)` in `mods/lib/status.mjs`, pure): the non-empty parts in priority order `version · savvy · blast · cost · reflect`, joined with ` · `. **No own prefix**: the host already prints `⚠ aico: ` in front of the line (SP-M1 saw `⚠ <plugin>: <text>`), so an own `aico · ` only repeats it. Each part is cleaned first (control characters and line breaks become spaces, runs of spaces collapse, trimmed; non-string values, unknown keys and own keys `__proto__`/`constructor`/`prototype` are ignored), then cut to its cap in terminal cells with `…` (`fit` from `format.mjs`). **Idle part.** `composeStatus(parts, { idle: true })` (the composer in `status.ts` always passes it) puts `aico idle` (`IDLE`, 9 cells, inside the `savvy` cap of 17) in the first slot when no `savvy` part is set, so a session with no run shows `v0.20.0 · aico idle` and a Blast Radius warning shows `v0.20.0 · aico idle · ⚠ core`. Any Savvy part (running, `ended`, `stale`) replaces it. Without the option, no part → `undefined`. The shell's `session.start` hook writes the idle line at once (`showStatus`), so the line is never empty because a mod loaded late.
- **Ready toast.** After the settings call settles, the shell's `session.start` hook shows one toast `aico <x.y.z> mods ready: Savvy, Cache Tax, Reflect, Blast Radius` (the version words `<x.y.z> ` are left out when the version is unknown; only the mods that are on in the resolved settings; `none on` when all are off; `aico <x.y.z> mods ready (settings unknown): …` with the defaults when the call failed; `readyText` in `mods/lib/ready.mjs`). No model call; the hook does not wait for it.
- **Width budget.** The row is `STATUS_COLUMNS` = 80. The host prefix `⚠ aico: ` takes 8 cells; `HOST_RESERVE` = 10 keeps 2 spare for a glyph drawn 2 cells wide or a footer indent. So `STATUS_MAX` = 70 cells for the mod's own text, and the caps add up so that all five parts at their cap fit: 9 + 17 + 10 + 13 + 9 + 4 × 3 = 70 ≤ `STATUS_MAX`, and `STATUS_MAX + HOST_RESERVE ≤ STATUS_COLUMNS` (tests pin both sums). As a backstop only (a cap changed later, `options.max` in tests), parts are dropped from the right (reflect, cost, blast; never the version) and then the first remaining part other than the version is cut with `…`. No terminal width is read: `bodyColumns` belongs to a pane and a docked `viewport.columns` is the transcript side (SP-M1). Priority runs left to right, so a host cut at the right edge loses the lowest part first. QA checks on a real terminal at 80 columns, with all five parts at their cap, that the line stays on one row; a wider host prefix raises `HOST_RESERVE` and lowers the caps to match.
- **AC35 summary.** Each part is its mod's one-line summary in compact form, every field within its cap, so with `pane: auto` and no dock (`isPlaced: false`, below 110 columns, `claude -p`) the Savvy and the Cache Tax summaries stand on the line together, with or without a Blast Radius warning. What the compact form leaves out (slug, Fix round, Gates, Names, spend and exact counts, expiry clock time, blast paths) is in the panes, the toast and the log.
- **Cadence.** The composer has no timer. `setStatusPart` stores the part, builds the line at once (synchronously, before any `await`, so the newest call always carries every part) and calls `$.ui.status` only when the line differs from the last line it wrote. Mods do not de-duplicate their own part: Savvy and Cache Tax set theirs on every tick (2 s) while on, Blast Radius at a warning and at its expiry, Reflect when its pending count changes. With minute-resolution elapsed time the line changes about once a minute in a quiet run (it changed every 2 s before).
- **Failure and reset.** A rejected `$.ui.status` call is swallowed and the next `setStatusPart` writes again. After `resetStatus()` or a reload of the hooks module the first built line is always written, even `undefined`, so a stale line from before is replaced. A Blast Radius warning shown before a reload is lost (its toast and log stand); Savvy and Cache Tax set their parts again within one tick.

## Panes
- Every state is text: `[tax]` marks cache writes, `running`, `unknown`, `warn`, `asked`, `refused`, `expired`; colour is never the only carrier and no colour is used when `NO_COLOR` is set (AC39).
- Panes: `aico-run` (Savvy), `aico-cost` (Cache Tax), `aico-reflect` (Reflect). Commands registered at `session.start`: `aico-run`, `aico-cost`, `aico-reflect` (each opens its pane; `{ text }` answer only when the mod is off: `<mod> is off; switch it on in /aico:settings`).
- **Width (SP-M1, 2.1.310).** A pane lays out to `e.props.bodyColumns`, never `e.viewport.columns` (docked, `viewport.columns` is the transcript side). Docked panes measured 39 (110 terminal columns) to 89 cells (200 columns); an asked pane below 110 columns draws `inline` (86 cells at 90 columns). Each view has a layout for 39 cells: values cut with `…`, no row wider than `bodyColumns`.
- **Unasked open.** `pane: auto` calls `$.ui.open` unasked only when a run becomes active; it docks only at 110 terminal columns or more (`isPlaced: false` below, and under `claude -p`). Then the compact one-line summary stays on the status line (AC35). An asked open (the command) works at any width. The `plugin-authoring` skill's "144 columns" does not hold in 2.1.310.

## M1 Savvy
- Active run (`run-state` v1) only; none → no pane content, no status part, no timer beyond discovery (AC41).
- Shows: task slug, wave, current Step and Role with Name, Gates passed (`brief, plan`), Fix round, elapsed run time; one line per running subagent: Step, Role (Name), elapsed. Current Step = the highest Step of a running subagent, else the newest Step file. After `end`: the final state with outcome and total time, until the next run starts or the session ends.
- **Context rows (v1.6).** Each running-subagent line ends with `ctx <n>` (`ctx 90.0k`: whole tokens below 1000, else thousands with one decimal), then ` near cap` past 85500 and ` over cap` past 95000 (words, never colour alone), or `ctx ?` when unknown. A `Lead ctx <n>` row (same form) is the first pane row while a run is known; `Lead ctx ?` until a reading is there. Pure text in `mods/lib/ctx-row.mjs`.
  - Subagents: `ledger.mjs agent-ctx <ids> --json`, ids in chunks of 8, at most 5 calls per poll, one after another (`TIMEOUT_MS.agentCtx` 5000), on its own 10 s timer apart from the 2000 ms tick, doing nothing while no subagent runs or no run is known. Its own in-flight flag: a poll still running at the next 10 s mark starts no second poll. An id is sent only if it matches `^[A-Za-z0-9_][A-Za-z0-9_-]{0,63}$` (the ledger's pattern without a leading dash, so it never reads as an option); other ids are not sent and show `ctx ?`. Ids go only into argv and are never drawn. The answer passes the allow-list `guardAgentCtx` (`{"v":1,"agents":[{"agent","ctx":<int>|null}]}`, at most 8 entries, ctx 0 to 10000000); counts are matched by id, an id not answered is `ctx ?`.
  - Lead: `lead-handover.mjs ctx '<slug>' --json` (`TIMEOUT_MS.leadCtx` 1000), in the 2000 ms tick, when the mtime or size of `.company/work/<slug>/lead-context.json` changes (a missing file reads as one state, so one call per run). Guard `guardLeadCtx` (`ctx`, `peak`, `at` present, integer or null).
  - Any failure (timeout, exit, invalid JSON, guard) draws `?` and never blocks the pane; the status line and every v1.5 row stay as they were.
- Status part (`savvy`): `W<wave> S<step> <role> <elapsed>`, after `end` `ended <outcome> <elapsed>`; full details stay in the pane; elapsed in whole minutes (`0m`, `12m`, `1h05m`; the pane keeps seconds); each `unknown` field prints `?`. Widest usual running form `W3 S12 ai-da-eng 1h05m` = 22 cells.
- **Progress bars (v1.1).** Two pane rows, directly after `Elapsed` and before the subagent lines, built by `progressRows(view, width)` in `mods/lib/bars.mjs` (pure; `view` is the guarded run view or `null`):
  - Gates row: `Gates <n>/3 [<bar>] last: <last>`, e.g. `Gates 1/3 [###-----] last: brief`. `n` = how many of `brief`, `plan`, `ship` have a `passed` record in the view's `gates`; `<last>` = the gate of the latest such record; `n` = 0 → `last: none`. `changed` and `stopped` records do not count.
  - Steps row: `Steps <d>/<t> [<bar>]`, e.g. `Steps 5/8 [#####---]`. `t` = the length of the view's `steps`, `d` = those with `status: done`. `t` = 0 → `Steps 0/0` with no bar.
  - Count first (Fix round 1, accessibility): the numeric count comes right after the label, so a screen reader speaks it before any bar glyph. Bar: ASCII only, `#` for done cells and `-` for the rest, in brackets after the count. **One cell count for both rows:** cells = `min(20, width − 3 − w)`, `w` = the wider of the two rows written without a bar. Done cells = `round(cells × count / total)`, then held at `cells − 1` while `count < total` and at 1 or more while `count > 0` (8 cells: `1/3` → 3, `5/8` → 5). Fewer than 4 cells → no bar and no brackets in either row. Still too wide → drop ` last: <last>`, then shorten the labels to `G` / `S`; the numeric count is never dropped (`S 200/200` fits 10 cells). Width = the pane's `bodyColumns` (10–400, else 39, as today).
  - Ended `ship` run (`state: ended`, `outcome: ship`): both bars full, `Gates 3/3 … last: ship` and `Steps <t>/<t> …`. Ended `abort` shows the real counts.
  - Unknown: no view, `state` `none` or `unknown`, or a value that fails the guard → `Gates ?` and `Steps ?`, no bar.
  - The `Gates    <list>` row, the status part, the subagent lines and every other v1 row are unchanged. Mod off → no pane, so no bars.

## M2 Cache Tax
- One row per `report --json --live` row: Role (Name), Step, in, cache write `[tax]`, out, cache read, spend; numbers are exact integers equal to the JSON (AC42). A subagent seen in `agent.spawn` with no ledger row yet shows `running` in every count cell; `unreconciled` rows show `unknown`.
- Totals: spend, cache read, cache write and `cache write = <p>% of spend [tax]`. Status part (`cost`, only while a run is active): `<n> tax` (`n` = cache write total, `fmtCompact`; no ledger data → `?`), plus the cache clock below.
- **Cache clock (AC43 as re-scoped by the CEO; replaces keep-warm).** Shows when the main session's (the Lead's) cached prefix expires.

## M4 Blast Radius
- **Commit gate** on `tool.check` for the shell tools **`Bash` and `PowerShell`** (filter on `e.tool`; SP-M2: on Windows without Git Bash the engine's shell tool is `PowerShell`, and a `Bash`-only matcher never fires):
  1. `mods/lib/git-commit.mjs` `commitIntent(command, shell)` (total, never throws; `shell` is `bash` or `powershell`) → `{ isCommit, repo, unknown }`. There is no scope: every commit is scored on worktree + staged + untracked files (step 2). `unknown: true` means the repository or index may not be the one the gate reads. **Allow-list: a command is not a commit only when every statement is cleared below; anything else counts as a commit and the gate asks.**
     - *Names git* / *names commit*: the word `git` / `commit` in any case, not inside a longer run of letters and digits (`gitcommit` names neither; `git.exe`, `commit-tree`, `--git-dir` do).
     - *History words*: `merge pull cherry-pick revert am rebase stash reset update-ref commit-tree`. Each one can put work on a branch, or makes the commit object that another command then puts there. A command *names* one when its text holds it in any case, not inside a longer run of letters and digits. A hyphen ends a word, so `merge-base` and `--merge` name `merge`, `merges` and `--no-merges` name nothing, and `cherry-pick` must appear whole. *Names a commit word*: names `commit` or a history word.
     - Parse: statements split on `;`, `&&`, `||`, `|`, `&`, newlines, `(`, `)`, `{`, `}` (PowerShell: a backtick line continuation joins lines; a leading call operator `&` is skipped). Quotes and escapes resolve as in the shell. Skipped at a statement's start: `if then else elif do while until ! time nohup command builtin exec`, `NAME=value` prefixes (bash) and `$env:NAME=…` (PowerShell).
     - A token is **literal** unless it is `.` or `&` or holds one of `$ @ * ? [ ] % ! < >` or a backtick (variables, `$'…'`, arrays and splatting, wildcards, redirection, the PowerShell dot-source or a call operator left over).
     - *Program position*: the first token of a statement after the skipped words and prefixes above. A statement that only assigns (`NAME=value` alone, `$env:NAME = …`) has none. Every other token is outside it, including `NAME=value` prefixes, the arguments of harmless programs and git's own options and arguments.
     - *Nested git*: a token outside the program position holds a nested git when, after quote resolution, one of its pieces has the base name `git` or `git.exe` in any case. Pieces split at whitespace and at `= ; & | ( ) { } < > ' "` and backticks. The base name is the text after the last `/` or `\`. Hold one: `--upload-pack=git stash …`, `GIT_EXTERNAL_DIFF=/usr/bin/git …`, a `diff.external` value `git stash …`, `cd git`, `echo git`. Hold none: `https://h/x.git`, `--git-dir=x`, `GIT_PAGER=cat`, `--upload-pack=git-upload-pack`. Two git statements side by side (`git fetch origin && git status`) are not nested: each `git` sits in its own program position.
     - *Strict*: the command names a commit word or holds a nested git. Rule (c) applies only to a strict command.
     - **Program not literal** (`$g commit`, `& $g commit`, `& (Get-Command git) commit`, `. git commit`, `/usr/bin/gi? commit`, `"${a[@]}"`, `g=gi""t; $g merge x`) → a commit when the command text contains `git` or `commit` anywhere, also inside a longer word, or names a history word.
     - **cd** (`cd chdir set-location sl pushd push-location`; `-Path`/`-LiteralPath` read): moves the repo for later statements.
     - **Harmless** programs are cleared even when their text names git and commit (they only print, search, list or set shell state): `echo printf write-output write-host write-error write-warning write-verbose write-information grep egrep fgrep select-string sls cat type get-content gc ls dir gci get-childitem head tail wc sort uniq pwd true false fi done esac test sleep which where date get-date mkdir touch export unset exit set`. `rg` is **not** on the list: `rg --pre <cmd>` runs `<cmd>` for each file it searches, so `rg` is an other program (below). `export`, `set` and `printf -v` are cleared as statements but count as setting the environment under rule (c).
     - **git** (`git`, `git.exe`) is cleared only when all of these hold:
       - (a) every global option before the subcommand is `-C <dir>`, `--namespace <x>`, `--super-prefix <x>`, `--attr-source <x>`, or one of `-p --paginate -P --no-pager --no-replace-objects --bare --literal-pathspecs --glob-pathspecs --noglob-pathspecs --icase-pathspecs --no-optional-locks --no-advice --version --help -h -v`. `-c` or `--config-env` with **any** key (`alias.*`, `core.fsmonitor`, `diff.external`, `core.sshCommand`, …), any other option, or `--git-dir`/`--work-tree` make it a commit;
       - (b) the subcommand is absent, or literal and in `ALLOWED`;
       - (c) when the command is strict, all of these hold too. Git accepts any unambiguous prefix of a long option and clusters short options, so the rule never relies on exact option spelling:
         - the subcommand is none of `config clone fetch push ls-remote archive grep`, whatever its options. These run a program from their options or from config they read (`--upload-pack`, `--receive-pack`, `--exec`, `-O`, `clone -u`, `clone -c`/`--config`/`--template`, abbreviated as `--u=`, `--e=` or clustered as `-iO…`), or write that config (`config`), so none of them is cleared in a strict command;
         - nothing in the command sets an environment variable, also in an earlier cleared statement: a `NAME=value` prefix, `$env:`, an `export` or `set` statement with any argument (bare `export NAME`, `export -n`, `set -a`, `set -o allexport`, `set -- x` all count), or a `printf` statement with an argument that starts with `-v` (`printf -v NAME …`, `printf -vNAME …`);
         - the statement carries no option that runs a command: `--ext-diff`, `--exec`, `--upload-pack`, `--receive-pack`, `--open-files-in-pager`; any long option whose name before `=` is a prefix of one of these and at least 3 characters long, the two dashes included (`--e`, `--ex`, `--ext`, `--up`, `--r`, `--o`; `--` alone is not an option); or a short option token that starts with `-O`.
     - `ALLOWED` (frozen in `git-commit.mjs`; a test pins the exact set): `status log diff show add stage fetch push branch tag remote ls-files ls-tree ls-remote rev-parse rev-list blame annotate grep describe config init clone checkout switch restore reset stash mv rm clean shortlog whatchanged show-ref show-branch cat-file diff-tree diff-index diff-files for-each-ref merge-base name-rev version help worktree gc fsck count-objects reflog archive format-patch symbolic-ref check-ignore check-attr var commit-graph range-diff verify-commit verify-tag apply sparse-checkout maintenance prune pack-refs repack`. `config clone fetch push ls-remote archive grep` stay in the set and are cleared only when the command is not strict (rule c). `stash` and `worktree` create no commit on a branch themselves; a stash commit that a ref move then puts on a branch is leftover risk (below). Not in it, so a commit: `commit`, `commit-tree`, `merge`, `pull`, `rebase`, `cherry-pick`, `revert`, `am`, `notes`, `update-ref`, `submodule`, `bisect`, `filter-branch`, `difftool`, `mergetool`, any alias (git never lets an alias shadow a builtin) and any unknown word.
     - A program whose name starts with `git.` or `git-` (`git.cmd`, `git-commit-tree`) → a commit.
     - **Any other program** (`node`, `find`, `xargs`, `stdbuf`, `bash`, `sudo`, `env`, `rg`, `Invoke-Expression`, `Start-Process`, …) → a commit when the whole command names git and names a commit word (`node -e "…git commit…"`, `find . -exec git commit -m x \;`, `stdbuf -o0 git commit`, `bash -c "git commit"`, `bash -c "git merge x"`, `echo commit | xargs git`, `echo am | xargs git`, `rg --pre git x commit`). A nested git alone does not make an other program a commit: `bash -c "git status"` and `npm run git-hooks` stay not a commit.
     - Over 64 KiB, an unterminated quote, a command substitution (`$(`, a bash backtick) or a parser failure → a commit when the command names git and names a commit word.
     - `unknown: true` when the command is a commit and:
       - holds `--git-dir`, `--work-tree`, `core.worktree`, `GIT_DIR`, `GIT_WORK_TREE` or `GIT_INDEX_FILE` (any case); or
       - is a doubt commit and holds `-C`; or
       - holds a `git add` or `git stage` statement that forces: `-f`, a short option cluster holding `f` (`-fA`, `-Af`), or a long option whose name is a non-empty prefix of `--force` (`--f`, `--fo`, `--force`). Reason: `--worktree` lists untracked files with `--exclude-standard`, so a path ignored by a rule git does not track (`.git/info/exclude`) and force-added in the same command is not scored. A forced add in an earlier command needs no rule: the file is then staged, and the staged diff carries it.
     - `repo` = the cwd from the `cd`s before the first committing statement, joined with its `-C` values (`null` = the session root), cut to 4096 characters.
     Not a commit → `next(e)` unchanged.
  2. `unknown: true` → the hits are one `unknown` hit in category `security`, no script call. Otherwise `review-depth.mjs --worktree --json [--risk <run tier>] [--repo <dir>]`: worktree + staged + untracked (`review-depth` v1). The gate never uses `--staged`: `tool.check` runs before the command, so a `git add` earlier in the same command has staged nothing yet. Hits = paths whose categories include `core`, `contract` or `security`. Script failure or no `$.process` → one hit `unknown` in category `security`.

  - Leftover risk (ADR 0017). Text gating cannot see:
