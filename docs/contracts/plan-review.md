# Contract: plan-review v1.2

Provider: `scripts/plan-review.mjs` (Node built-ins only; cwd = product root; `main(args, { root, now })` exported by `scripts/plan-review.mjs`; runs no git and no shell). Consumers: the Lead of `aico:pipeline` (`lines`, `gate`), the eval run before a release (`score`), `release` v1.1 (reads the eval records). Uses: `contract-index` v1 (`buildIndex`), `plan-tasks` v1 (path rule `normalizePath`), `handoff` v2.0 (`parseLocations`), `work-folder-name` v1.1 (`isWorkFolder`, `exactWorkPath`).
v1.1: the slug is a work folder name, new or legacy; case names keep their own pattern.
v1.2 (additive): `lines` and `gate` check the spelling of `.company`, `work`, the slug and each named plan or Handoff file against the directory entries before any read or write. A name that exists only in another ASCII letter case → `refused: wrong letter case` (exit 3), nothing written; a name missing in every case keeps its old refusal. The real-path compare is exact on every platform (no case fold).
Exit codes: 0 done, 1 unreadable plan or record, 3 refused (`refused: <reason>`, nothing written). Arguments are checked values only: slug a work folder name (`isWorkFolder`: a new `YYYY-MM-DD HH.MM - <Topic>` name or a legacy `^[a-z0-9][a-z0-9-]{0,63}$` slug; any other value → `refused: bad slug`, never echoed), plan name by the `plan-check` v1 rule (`^(\d{2,3}-)?(architect-)?plan(-[a-z0-9]+)?\.md$`), Handoff file names `^\d{2,3}-[a-z][a-z0-9-]{0,40}\.md$`; an argument with a control character (Cc, Cf, Zl, Zp) or over 4096 characters, an unknown flag or a repeated flag → exit 3.

## Real-path read rule
Every file the script reads (plan, `--after` files, Contract files, code files, case files, results, the eval record) must have a native real path equal to its lexical path under the real product root (so no link or junction on it), be a regular file with one hard link, and the opened handle must be that file (same device and inode). No lexical fallback. No `O_NOFOLLOW` is assumed on win32. A Contract or code path that fails the rule is dropped; a plan or `--after` file that fails it → exit 3. A code path is also dropped when its key (case, trailing dot or space folded) starts with `.company/` or `docs/contracts/`, or when its real path lies under `<real root>/.company/`.

## `lines <slug> <plan> --mode plan|code --after <file>[,<file>…]`
- The plan is `.company/work/<slug>/<plan>`: at most 256 KiB, UTF-8. Missing, too large or not UTF-8 → exit 1.
- `--after`: 1 to 20 distinct names, each a plain file in the run folder and not a plan name; plan mode needs at least one `NN-architect.md`. Any failure → exit 3.
- **Contracts** (both modes): each `docs/contracts/<name>.md` token and each cite `<name> v<x>[.<y>]` whose name is in `buildIndex`, as the Contract file; an unreadable file is dropped; first appearance order, duplicates removed, at most 40.
- **Code** (plan mode only): every backticked token and every `files:` item outside code fences that passes the `plan-tasks` v1 path rule, is not a folder, and passes the real-path read rule; plan order, duplicates by key removed, at most 200. At most 5000 candidate tokens are examined. Over a cap → the first N and one `warning: inputs capped <kind> <N>` line, `kind` `contracts` or `code`, `N` the cap (40 or 200).
- Writes `.company/work/<slug>/plan-review/inputs.md` (folder and file must be plain; the file is created `O_CREAT|O_EXCL` or, when present, opened after an `lstat` and handle check, and truncated): `## Plan`, `## Contracts`, `## Code` (code mode: `## Diff` with the one line `judging diff: rule git.M-SEC4`), one path per line, no plan text, LF only.
- Prints exactly `Input Handoffs: none: plan review`, `Review inputs: .company/work/<slug>/plan-review/inputs.md`, `After first pass: <paths joined by ", ">`, then any warning lines.

## `gate <slug> <handoff>`
The handoff is a `fresh-reviewer` Handoff (frontmatter `role`) of the run folder, at most 64 KiB, read by the real-path rule. Read-only. Prints `paraphrase:`, then the `## Paraphrase` text, then `first pass: <k> findings` (the `- R-<n> …` bullets of `## First pass`), then one `comprehension <NN>-<role>:R-<n>` line per `[comprehension]` row of `## Blocking`. The text is capped at 1200 characters (code points, blank lines dropped), then every Cc character except LF, and every Cf, Zl and Zp character, prints as `\u{<hex>}`, and each line is prefixed `> `, so model text cannot imitate a Gate line. Headings inside code fences are not sections. Another Role, no `## Paraphrase`, a plan name, or a file that fails the read rule → exit 3.

## `score <cases dir> <results dir> [--tag] [--record <x.y.z> [--kind plan|code]]`
- Both folders are plain folders inside the product root. Cases: `<cases>/<case>/plan.md` (a plain file) and `expected.json` (at most 16 KiB): `{ "v": 1, "file": "<path>", "lines": [a, b], "tag": "contract|spec|security|test|comprehension" }` with exactly those keys (`file` passes the path rule, `1 <= a <= b <= 1000000`), or exactly `{ "v": 1, "control": true }`. Case names `^[a-z0-9][a-z0-9-]{0,63}$`, at most 100; a bad case → exit 3.
- Result `<results>/<case>.md` is a `fresh-reviewer` or `code-reviewer` Handoff. Caught = a `## Blocking` row whose `parseLocations` overlap `file` (same path key) and `lines` (a whole-file location overlaps). `--tag`: the row's leading `[tag]` must also equal `expected.json` `tag`. A missing result, another Role or an unreadable result counts as missed.
- Prints `case <case> caught|missed` per case, then `caught <k> of <n>`. A control is not counted in `n` and prints `control <case> <k> blocking` (its `## Blocking` row count, `none` rows excluded) in case order. A control with no result file prints `control <case> missing`, is not counted, and sets no `control` key in the record.
- `--record <x.y.z>` (`^\d{1,4}\.\d{1,4}\.\d{1,4}$`) appends `{ "v": 1, "aico": "<x.y.z>", "at": "<UTC>", "caught": k, "total": n }` (plus `"control": <sum of k>` when the run has a control) and a line feed to the fixed file chosen by `--kind`: `plan` (default) the file eval.jsonl in the folder tests/plan-review, `code` the file eval.jsonl in the folder tests/code-review. `--kind` without `--record`, or any other value, → exit 3 and nothing written. The record folders must be plain folders; the file is created `O_CREAT|O_EXCL` or appended after an `lstat` (one hard link) and handle check; the file is at most 64 KiB and 500 lines, and an existing file that is a link, has two hard links or does not end in a line feed → exit 1.

## Code-review cases
Each case folder `<case>` under the folder tests/code-review holds `plan.md`, `diff.patch` (unified diff of the seeded change) and `expected.json`, where `file` is the repo path inside the diff and `lines` are new-side lines. The Lead's eval run uses `score <cases dir> <results> --tag --record <x.y.z> --kind code`.
