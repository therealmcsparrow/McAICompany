# ADR 0074: The frozen Lead is replaced in place by typing /clear and the hand-over prompt into its own terminal

Date: 2026-11-15. Status: proposed (fix run P20261115.000001/01-fix). Supersedes the "starts nothing" clause of `docs/adr/0056-hard-handover-outside-agent.md` and `lead-session-mcp` v1.x; the rest of ADR 0056 stands.

`lead_new_session` (`lead-session-mcp` v2.0) now starts one detached helper (`scripts/lead-replace.mjs`) that waits until every background task of the session has ended and the frozen turn is over, then types `/clear` and the fixed hand-over prompt into the session's own terminal, so the old context ends and the new Lead starts there with no CEO keystroke (CEO decisions 1-3, request of P20261109.000004). Killing the claude process and spawning a new one does not work: the parent shell takes the terminal back on exit (POSIX job control, Windows console sharing), and a wrapper launcher was declined by the CEO. Typing into the terminal needs one OS-specific step (Windows `WriteConsoleInputW`, macOS/Linux `TIOCSTI` where the kernel allows it); where it is unavailable or fails, the old route stands: the freeze reason shows the command. Hard to reverse because the tool now starts a process, a security surface that each later version must keep reviewed.
