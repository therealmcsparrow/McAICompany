# Every dashboard request carries a per-start path token, in loopback and LAN mode

Status: proposed (Plan Gate, task 2026-11-04 01.19 - Skillset Dashboard Draft). Decided: CEO, 2026-11-04, for webapp.M-SEC8, a per-start token over an exception or dropping `--lan`; applying it on loopback too is the Architect's call. Contract: `docs/contracts/dashboard.md` (Server access).

Each `serve` start makes a 32-byte `crypto.randomBytes` token (base64url, 43 characters), kept only in server memory and printed only inside the URL lines, and every request, page and assets included, must carry it as `/t/<token>/` (checked with `crypto.timingSafeEqual` after a length check, else a fixed 404), because webapp.M-SEC8 requires a server-side access check on every request and a loopback port is reachable by every local user and process, so one code path covers both modes. The page uses only relative URLs, so it never reads or stores the token, and a restart makes every old link dead. This is hard to reverse because every link, the page's URL rules and the docs assume the prefix. Residuals: under `--lan` the link travels as plain HTTP, so anyone who can read that network traffic can use it until the server stops; the printed URL sits in the session transcript, so anyone who can read the transcript can use it while the server runs.
