# The four mods ship inside the aico plugin as thin views over the existing scripts

The mods must be on by default after a normal install, so they ship as the aico plugin's own hooks module (`hooks/hooks.json`), not as four separate plugins; one plugin also means one status line, which the mods share. Every count, tier, depth, run state and Lesson comes from a Node script the rest of aico already trusts (`ledger.mjs`, `review-depth.mjs`, `settings.mjs`, `run-state.mjs`, `reflect.mjs`, `lessons.mjs`), called with `$.process.run` and read as JSON, so a mod can never drift from the ledger or from `review-depth` and its logic stays under `npm test` with Node built-ins only; the hooks modules hold drawing and event wiring alone. This is hard to reverse because the scripts' JSON outputs become Contracts the mods depend on, and moving logic into the hooks modules later would split each rule across two languages and two test runners.
