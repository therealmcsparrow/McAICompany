# 0027: The Lead trusts a direct-route triage line only through a plugin-written record

A triage line in a request is low-entropy text that anyone can copy or forge, and "this session approved this request" was a model comparison, so the Lead now skips triage only when `run-state.mjs triage check` finds a record that triage's Approve branch wrote under a nonce only the main session holds (`k` = SHA-256 of the nonce), bound to the exact request by `h` = HMAC-SHA256 keyed by that nonce over the request after a fixed normalization (NFC, line endings to LF, trailing spaces and tabs off each line, ends trimmed, one enclosing pair of `"` dropped; a spike showed the main session's Write does not keep exact bytes), used once and live for 30 minutes, and the Lead checks only the nonce of the `triage issue` triage ran for that request, once (`run-state` v1.2, `company-type` v1.3). The HMAC matters because the record file is writable by any agent: with a plain hash of the request, an agent could point an old record at another request; with the nonce as key it can at most re-enable the exact request the CEO approved, which the Lead's check-once rule closes. We extend `run-state.mjs` instead of adding a script because it already has the lstat, append and size-limit code, and only the direct route is recorded because no other Playbook skips anything for a triage line; hard to reverse, since trust now depends on `.company/triage/` and the nonce rule, and a later move to a hook-held secret no agent can read (the durable fix, as the nonce also sits in the session transcript) would change both.
