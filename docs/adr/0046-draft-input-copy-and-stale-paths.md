# Draft inputs pass through an argument file, are copied once before any Role reads them, and a draft plan's paths are checked against HEAD at the Plan Gate

The CEO's raw argument goes to a one-shot argument file written with the Write tool, so no shell ever parses it, and a file input is read once by the real-path rule and copied byte for byte to `input-<for>.md`, so Roles read a copy that no link swap between check and read can change. A plan drafted by to-tickets records its base commit, and when a feature run takes it, `draft-input stale` compares each `files:` path at that base and at HEAD by object id with hardened git calls: a path gone or newly present is a Blocking item the architect must answer in the run's own plan, and a path that could not be checked is Blocking too. This is hard to reverse because every pre-build command, the feature intake and the Plan Gate rely on the copy, the slug rule that never reuses earlier work, and the `Base commit:` line in to-tickets plans.
