# The model floor is a frozen per-Role table in company/model-floor.json, ranked haiku < sonnet < opus

A Role's floor is its v0.16 model, so it cannot be read from the agent frontmatter once a default moves down (tech-researcher is `sonnet` in its frontmatter and `opus` in the table). The table, plus the fixed protected list, lives in one plugin data file that `scripts/check.mjs` validates in CI (one entry per agent, protected Roles never below their floor in frontmatter) and `scripts/settings.mjs` reads at run time, so the floor and the "downgraded" set (frontmatter below floor) have one source; an unreadable file fails closed (every Role protected, floor `opus`). Only `haiku`, `sonnet` and `opus` are ranked: `fable` and anything else never count as at or above a floor until their rank is documented. This is hard to reverse because the verdict, the dispatch rule and every later model change compare against this table; a later model change edits the table only with a new `release` and a CEO decision.
