# Blast Radius asks through the permission check and refuses when nobody can answer

Blast Radius answers the engine's `tool.check` for a `git commit` in either shell tool (`Bash` or `PowerShell`) with `ask` (the engine's own question, with every hit in its reason) when a person or host can answer, and with `deny` when none can (`claude -p`, a background loop); it never answers `allow`, so it can only tighten what the session's rules decide, and its error handler refuses the commit too. Doubt also fails toward asking: a command the parser cannot place but that names `git` and `commit` counts as a commit, and a failed `review-depth` call (or a surface without `$.process`) counts as a security hit. SP-M2 confirmed the engine honours a plugin `ask` in every permission mode and over allow rules, and turns it into a deny when no approver exists. This is hard to reverse because headless runs that commit Core or security paths now stop unless the CEO sets that category to `warn` at the user level (Contracts default to `warn`, CEO), and docs and Playbooks will describe that behaviour.

Revised after review (Step 97): commit detection is an allow-list (only `cd`, print-and-search programs and `git` with a literal subcommand from a fixed set that never commits pass; everything else asks), and every commit is scored on worktree, staged and untracked files, because the gate runs before an earlier `git add` in the same command. Leftover risk, accepted: text gating cannot see a commit made inside a script or tool (`bash c.sh`, `npm run`, `make`, a repo hook) or behind a program name built from pieces; unknown non-git programs do not ask under `claude -p`, because that would refuse nearly every command, so the Code Reviewer's diff and the Gates stay the check for those paths.

Revised after review (Step 109, CEO): git accepts abbreviated long options and clustered short ones, so matching option spellings kept missing real commits. When a command names `commit`, the gate therefore no longer clears `clone`, `fetch`, `push`, `ls-remote`, `archive` or `grep`, whatever their options. It also counts `export`, `set` and `printf -v` without `=` as setting the environment, drops `rg` from the harmless programs (`rg --pre` runs a program), and treats a forced `git add` as an unknown security hit, because an ignored path is not scored. The leftover risk accepted by the CEO is unchanged in kind. It covers a payload built from pieces so the command never names `commit`, a commit made by a script file, tool, hook or earlier-written config, and a harmless program's own option that runs another program (`sort --compress-program`). The Code Reviewer's diff and the Gates stay the check for these.
