# Blast Radius asks through the permission check and refuses when nobody can answer

Blast Radius answers the engine's `tool.check` for a `git commit` with `ask` (the engine's own question, with every hit in its reason) when a person or host can answer, and with `deny` when none can (`claude -p`, a background loop); it never answers `allow`, so it can only tighten what the session's rules decide, and its error handler refuses the commit too. Doubt also fails toward asking: a command the parser cannot place but that names `git` and `commit` counts as a commit, and a failed `review-depth` call counts as a security hit. This is hard to reverse because headless runs that commit Core, Contract or security paths now stop unless the CEO sets that category to `warn` at the user level, and docs and Playbooks will describe that behaviour.
