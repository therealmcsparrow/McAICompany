# ADR 0077: The Lead runs as a subagent; main only relays

Date: 2026-11-17. Status: proposed (feature run P20261117.000001/01-feature). Contracts: `docs/contracts/lead-relay.md` v1, `context-guard` v3.0, `hook-event` v1.4, `lead-handoff` v3.0; retires `lead-session-mcp` v2.1.

Every aico Playbook now runs in one plugin agent `aico:project-manager` spawned by the main session, which only spawns Leads, relays CEO forms and spawns the next Lead on `needs-ceo` or `handover`; the Lead-in-main-chat mode is removed (CEO D3, one path) and the `lead_new_session` MCP tool, its helper `scripts/lead-replace.mjs`, the Windows typer and the `bg` and `turn` records are deleted (CEO D1), because a main session that only relays never nears its cap, so a frozen session, `/clear` typing and an MCP server have nothing left to do. Hooks tell the Lead from a Role by the harness field `agent_type` (`aico:project-manager`), never by model text. Hard to reverse because the guard, the hook event and the Lead records all change their idea of "Lead session" from the main chat to one agent per Lead, and bringing the MCP path back would re-add its security surface.

Decided: proceed on the prototype `## Answer` (`.company/work/P20261117.000001/01-feature/03-prototype-backend-engineer.md`) that transcripts of nested agents sit flat in `<main-session>/subagents/agent-<id>.jsonl` and that `agent_type` tells the Lead apart, with Spike S1 to prove hooks fire for nested Roles before any hook task starts.
