# The plan check keeps its own record in the run folder, and Fix rounds are the recorded value, cross-checked

The open-decision check needs a per-run marker (on or off) so Fix rounds can be split by check, but adding it as a ledger key would change `token-ledger` v1.1 records and the scorecard. So the check writes its own fail-loud `plan-check` v1 record, `.company/work/<slug>/plan-check.jsonl`, next to the run's Handoffs, and a separate read-only verdict joins it with each run's Fix rounds. A run's Fix rounds are the ledger `ship` record's `fix_rounds` (read only), and the run counts only when that equals the highest `round:` in its Handoffs up to the first Ship Gate answer; Spike S1 showed the Handoffs alone over-count rounds after a changed Ship Gate and in phased runs, so both sides of the verdict use this one rule and doubtful runs drop out instead of skewing a median. This is hard to reverse because every later verdict compares runs through this record and this measure; the scan exits 2 on `block` so the later hook-run Gate can reuse it unchanged.
