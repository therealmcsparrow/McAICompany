# The plan check keeps its own record in the run folder, and Fix rounds come from the Handoffs

The open-decision check needs a per-run marker (on or off) so Fix rounds can be split by check, but adding it as a ledger key would change `token-ledger` v1.1 records and the scorecard. So the check writes its own fail-loud `plan-check` v1 record, `.company/work/<slug>/plan-check.jsonl`, next to the run's Handoffs, and a separate read-only verdict joins it with each run's Fix rounds. Fix rounds are measured the same way on both sides, as the highest `round:` in the run's recorded Handoffs (`run-state` v1.3 `show`), so the backfilled baseline and the check-on runs use one definition and the ledger is never read or written. This is hard to reverse because every later verdict compares runs through this record and this measure; the scan exits 2 on `block` so the later hook-run Gate can reuse it unchanged.
