# aico:feature and aico:fix run without a Brief Gate and a Plan Gate

The CEO removed the Brief and Plan Gate from `aico:feature` and `aico:fix` in every run, direct calls included (2026-10-30); fix also loses its Core or Contract Plan Gate pause. The Ship Gate always runs, and what the two Gates showed (Core and Contract changes, Art direction, plan-tasks waves, the plan-check result, the plan review block, spike results, the prototype answer, stale-path lines) moves into the Ship Gate summary. A decision that waited for a Gate becomes one form when it arises: a `needs-ceo` Handoff, a rejected ruleset rule, a plan-check `block` or `plan-tasks` refusal (Fix / Stop), the prototype question, the GLOSSARY and ADR drafts. A script refusal is never bypassed. Other Playbooks keep their Gates.

The `cc.S2` exception (ADR 0026) listed the Brief, Plan and Ship Gates of each Playbook as a compensating control for model-startable Playbooks. Feature and fix stay model-invocable, so an injected or unasked start now builds up to the Ship Gate with no earlier CEO stop. The senior engineer asked the CEO; the CEO chose to accept this and re-approve `cc.S2` on 2026-10-30 with the shorter control list: the Ship Gate, the security review lane and the CEO-only Playbook start rule. This is hard to reverse because the flow Playbooks (idea, bug, tickets) start feature and fix with the Skill tool and assume no stop before the build.
