# Reprompt asks once for a limit pick instead of refusing a big tree

A large plugin cache made every `snap` refuse with `tree too large`, so an over-limit `snap` now exits 4 and the Lead asks the CEO once per session for Walk less (watch only the plugin versions `installed_plugins.json` loads) or Raise the limit, a fixed 2x ceiling that no setting, env var or argument can change, so the check is never unbounded (`docs/contracts/reprompt.md` v2.2). The pick and the Walk less roots are stored in the hashed `.tree.json`, so `reply` compares against the watch set the snapshot used; `reply` also stops listing the run's own `run-state.jsonl`, which the write gate alone now guards (security verdict `gate sufficient`, `scripts/reprompt-gate-runlog.test.mjs`). This is hard to reverse because baselines, the Playbook's form and session pick, and the gate-only guard of the run log all build on it, and dropping the skip would flag every reply round again.
