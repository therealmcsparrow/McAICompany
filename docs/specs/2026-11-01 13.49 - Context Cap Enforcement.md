## Problem
Steps ran past the fixed 95000 context cap. One v0.25.0 run had 22 Steps over 100k, with a peak of 191k. Quality drops past the cap, and the causes were the Lead resuming finished agents and giving one Step too much work. The cap was only a written rule: nothing refused a resume, the ledger stored a Step's final context without comparing it to the cap, and the CEO could not see a Step's context while it ran.

## Solution
The plugin now checks the cap itself, so it no longer depends on the Lead's judgment. The numbers stay as they were: cap 95000, handover point 85500.
- No resume. While a run is active, a message from the model to an agent and an agent start that resumes one are both refused. The reason reads: aico: Steps are never resumed; dispatch a fresh Step (next NN) with the old Handoff as input (pipeline §2). This is always on and has no setting. A failed lint, a CEO answer and a follow-up all go to a fresh Step of the same Role, with the old Handoff as input.
- Smaller Steps. For a large review or a Fix round, a script prints area groups and the Lead dispatches one Step per group. Each Step's dispatch names its group. A review closes when every group's Handoff is done.
- Over-cap check. A ledger add with a final context above 95000 still writes the record, prints the over-cap line and exits 4. The Lead commits the Step's files, acts on none of its lines and dispatches one fresh check Step of the same Role, not a Fix round. An over-cap reviewer Handoff never closes a review.
- Ledger report. The text report prints a line with the number of over-cap Steps and the highest value, only when at least one Step went over.
- Live context in the overview pane. Each running agent row shows its current context, refreshed every 10 seconds, and a Lead row comes first. A row past 85500 says near cap and a row past 95000 says over cap. Unknown shows a question mark.
- Cap notes in the status line. While any running agent or the Lead is past 85500, the running status part names the wave, the Step and the note, for example W3 S12 over cap. Over cap wins when both occur.
- Lead context. A hook measures the Lead's context each time it finishes a turn. The Lead hand-over read prints the current value and the peak, each marked over cap above 95000. The Ship Gate shows the peak and the over-cap line, and neither blocks the Gate. Hand-over itself stays on the existing compaction path.
- Setup warning. A run start prints one warning when CLAUDE_CODE_AUTO_COMPACT_WINDOW=98500 is found neither in the environment nor in the user settings, then continues.

## User stories
- As the CEO, I can trust that no Step is resumed during a run, because the plugin refuses the resume and names the fresh-Step rule.
- As the CEO, I can watch each running agent's context and the Lead's in the overview pane, without opening a transcript.
- As the CEO, I can see from the status line alone that a Step or the Lead is near or over the cap, even when the pane is closed.
- As the CEO, I can read at the Ship Gate how many Steps went over the cap, the highest value and the Lead's peak.
- As the CEO, I get told at the start of a run when the compaction setting the Lead hand-over needs is missing, with the value to set.
- As the Lead, I get a printed exit code and printed groups, so I do not have to judge whether a Step went over or how to split the work.
- As Ravi, who uses a screen reader at high zoom, I get near cap and over cap as words, never colour alone, and a narrow pane does not cut a row inside its note.

## Decisions
- Risk tier high: the work changes Contracts and the Core pipeline skill. The CEO approves the Core edit at the Ship Gate (brief Decisions).
- The Lead cap is measured and shown, on the existing compaction path. The option of a hook that stops the Lead and asks the CEO to compact was rejected (CEO, brief option A).
- No over-cap line at 0: the report prints nothing when no Step went over (CEO, AC7 amended).
- Cap notes go in the status line, in a short form that keeps the row within 80 columns. Role and elapsed time stay in the pane. With no row past 85500, or when the run is not running, the status part is unchanged (CEO, Fix round 4).
- The overview pane shows live per-agent context (CEO, AC9).
- The no-resume refusal has no setting and no off switch (ADR 0054).
- An over-cap Step is treated as a failed Step: its work is checked by a fresh Step and it opens no Fix round (AC6).
- A context of 0 in the ledger means unknown and never counts as over cap (AC5).
- Live reads take only the four usage counts, never message text, and agent ids are never drawn (GDPR data minimisation, AC11).
- A file that cannot be read, a timeout or a bad answer shows a question mark and never blocks the pane (AC11).
- Split limits for a review group: 1200 changed lines and 25 files. For a Fix group: 8 blocker rows. When the script has no full file list, it refuses and the Lead dispatches one unsplit review (step-split v1).
- Plan-text blockers go to the Architect, never into a builder group (step-split v1).
- All Contract changes are additive: token-ledger, aico-mods, lead-handoff and dispatch-prompt bump, and step-split v1 is new.

## Testing decisions
- The tier is high, so each of AC1 to AC14 keeps its full test and none is covered lightly.
- The refusal, the over-cap line, exit 4, the report line, the group output and the setup warning are script or hook outputs, so tests pin them directly. Pipeline text that routes on them is pinned by text tests (AC2, AC4).
- Boundaries: a final context of exactly 95000 and of 0 is not over cap (AC5); a report with no over-cap Step prints no line (AC7).
- The pane is tested for words next to the numbers, and for rows that never break inside a note (AC10).
- Live reads are tested with a missing, oversized or locked transcript, which all show a question mark (AC11).
- Symlink inputs are refused, and refusals do not echo the values they refuse.
- The Contract bumps must pass the drift check, and the full suite must pass (AC12).
- Success metric: Steps with a final context above 95000 per run, read from the ledger report line at each Ship Gate. Baseline 22 (v0.25.0 run). Target 0 over the next 3 feature runs. Secondary: Lead peak at or below 95000 in those runs.

## Out of scope
- Changing the 95000 and 85500 numbers.
- Role-side handover rules in the Handoff skill.
- Cost or spend views.
- Claude Code settings the plugin cannot set; the CEO sets the compaction window himself.
- A hook that stops the Lead and asks the CEO to compact.
- Blocking the Ship Gate on an over-cap count or the Lead peak.
- Per-Role context history and trends in the scorecard (later).
