## Problem
The CEO cannot see aico runs at a glance. Run state, Step status, Gates, rounds, tokens and the roadmap sit spread across many records in the company folder, and reading them by hand is slow while a run is live. The user served is the CEO, watching their own runs on their own machine.

## Solution
A read-only local web dashboard that the CEO starts with the aico dashboard command. Only the CEO starts it; no other command and no Lead starts it. It shows a board of all runs, a drawer per run and the roadmap, and it refreshes by itself while open.

- Start: one local server, no Roles, no Gates, no branch or commit. It prints one full link with a random access token and listens on this computer only. The OS picks the port; a port flag (1024 to 65535) pins one.
- Access link: each start makes a new 43-character random token, held only in server memory and checked on every request. A link from an earlier start never works again.
- Board: eight columns in this order: Intake, Brief, Plan, Build, Review, Ship Gate, Needs CEO, Done. Each run sits in exactly one column. Ended runs go to Done, runs waiting on the CEO to Needs CEO, then the recorded stage, else a column derived from the Gates the run passed, marked "stage not recorded".
- Intake lane: one card per intake request held as needs-info or rejected.
- Run card: title, state (running, ended, stale, none or unreadable), started, ended or elapsed time, a live marker, risk tier, round, a needs-CEO flag, tokens (spend and cache read) labelled "tokens, not cost", and USD only where the cost source records it.
- Drawer per run: each Step with role, status, round and a plain-text summary of the first three lines of its Did section; round chips with the gate and reviewer verdict, or "verdict not recorded"; reviewer routing in first-seen order; PR and issue links, looked up only when the drawer opens and never stored.
- Active run extras: Gates with CEO wait time, waves, time per Role, Steps over the context cap and the Fix round count. A footer counts Steps in flight.
- Live updates: a change to the active run shows within 5 seconds; any other change, a new run included, within 35 seconds. Updates never replace the focused element. A "Pause updates" button stops and resumes polling. After three failed polls the page says the server stopped and how to get a new link.
- Stop: stop the background task, or the server ends itself after 60 idle minutes.
- LAN flag: also listens on every IPv4 network interface. The server prints a warning and the page shows a banner: no login beyond the link, the link travels unencrypted, names in Handoffs are readable, stop the server to end access.
- The server answers only from the JSON of aico's own scripts. Stage per run and intake outcomes each have their own record script and Contract; PR and issue links come from a lookup script that stores nothing.

## User stories
- As the CEO, I run one command and get a link that shows every run, its phase and the roadmap.
- As the CEO, I see a Step finish or a Gate open on the active run within 5 seconds, without reloading and without losing my keyboard place.
- As the CEO, I see which runs wait on me in the Needs CEO column.
- As the CEO, I open a run and read what each Step did and how each round's Gate and review went.
- As the CEO, I jump from a run to its PR or issue when one exists.
- As the CEO, I see intake requests that were held for more information or rejected.
- As the CEO, I see where time went in the active run: CEO wait at Gates, waves, Role times, over-cap Steps and Fix rounds.
- As the CEO, I pause updates while I read, and resume them with one press.
- As the CEO, I choose to open the board on another device on my network, and I am told plainly what that exposes.
- As a keyboard-only or screen reader user, or at 400% zoom, I can reach and read every view, the drawer included.

## Decisions
- Board columns are the aico phases plus an Intake lane; the zazencodes columns have no aico match.
- A per-start random token in the link guards every request in both modes; it is never written to disk, logged or sent back in a response. This replaces "no authentication" from the draft spec; full login stays later work.
- Requests are refused in a fixed order: unknown Host header (421), a method other than GET or HEAD (405), any query string or a wrong or missing token (404). Error bodies are fixed and echo nothing from the request.
- Every response carries a strict content security policy, no-sniff, no-referrer and no-store headers. The page writes text only as plain text; Handoff text never renders as HTML.
- PR and issue links are read live at drawer open and cached 60 seconds in memory; nothing about PR or issue state is stored.
- The dashboard works without the structured gate and verdict fields; until Handoffs carry them, every round chip says "verdict not recorded".
- Tokens are shown as tokens, never as cost; context-end values are never summed. USD appears only from the cost source.
- One bad source never fails the board: an unreadable run marks only its own card, a failed reader leaves only its part empty, a failed summary shows none.
- Personal data: Handoffs may name people. Without the LAN flag, run data stays on the computer, except the PR lookup that calls GitHub when a drawer opens. With the LAN flag the user, or the client for a client run, is responsible for that exposure; user docs say to check the client contract first.
- Rebuilt from the idea only: no zazencodes code or text (GPLv3). No new dependency.
- Status is shown with text and an icon, never colour alone.

## Testing decisions
- Risk tier high: every acceptance criterion has its own test.
- Server tests cover default local bind and printed link, the LAN flag lines and warning, Host, method, query and token refusals, fixed error bodies and the security headers, in both modes.
- Escaping test: Handoff text holding HTML or script renders as plain text.
- Live update tests: active-run changes within 5 seconds, others within 35, focus never moved, pause and resume, the stopped message after three failed polls.
- Record script tests: stage and intake-outcome scripts cover read, write and missing record; the PR lookup covers found, none and the GitHub tool missing, signed out or offline, with nothing written.
- Board, card and drawer tests cover the column rule, every listed field, the tokens label, cost only from the cost source, and unreadable or not recorded cards.
- Security tests cover safe file reads: no links or hard links followed, identity checked on the opened handle with 64-bit file IDs, and capped reads.
- Accessibility: an automated in-repo WCAG 2.2 AA check over board and drawer with no violations (names, roles, landmarks, headings, text-plus-icon status, focus order, contrast, target size).
- Change set check: no added dependency, no zazencodes text, user docs cover start, stop, the token link, the LAN flag and its warning.
- The CEO's hands-on pass passed.
- Known gap: the manual screen reader (NVDA), forced-colors and reduced-motion pass was skipped by the CEO; only the automated check and keyboard behaviour stand behind those.

## Out of scope
- Any write or action from the page.
- Full authentication beyond the per-start link token (later).
- Views across several projects (later).
- A Claude Code pane mod or a published artifact.
- Transcript-based cost.
- Copied zazencodes code or text.
- New dependencies.
- Serving raw record files.
- Storing PR or issue state, or any run data on disk.
- LAN access by default, and IPv6 listening.
