## Problem
aico runs spent too many Steps and redid work in Fix rounds, and CI ran the full matrix on every push. Every Role and gate worked out the same change facts again, UI Roles and the a11y job ran on diffs with no UI change, and a Fix round re-dispatched Steps whose inputs had not changed. Serves the CEO running aico runs, who waits less per shipped change when runs have fewer Steps and fewer redos, without any check getting weaker on tags or at the Ship Gate.

## Solution
- Faster CI on pull requests: a new push cancels the older run on the same branch; a tag run is never cancelled and a red run stays red. A PR runs the Windows tests; the Linux and macOS steps are skipped one by one so the required check names still report success. A docs-only PR skips the test steps the same way, so no required check stays pending. Node setup uses the npm cache; a cache miss is normal.
- Cold runs in CI: tags run cold on the full OS matrix (Linux, macOS, Windows); a nightly run on main runs cold on Linux and Windows. A red nightly is reported and never retried.
- Diff facts (new Contract diff-facts v1.0): a finished Step's change is classified once (paths touched, ui_changed, contract_changed, strings_changed) and saved in the run folder. Triage, the merge test, the a11y job and CI read that file and never work it out again. ui_changed is false only when every path is docs or tests; locale, theme, token, CSS, config, rename-only, binary and unknown paths count as UI. A show command prints the same facts for two commits. Needs git 2.40 or later; older git refuses every command.
- Route (new Contract route v1.0): triage writes the Steps of a feature or fix run, with merges and skips and a one-line reason each, to the run's route ledger. The pipeline runs that list and nothing else. A dry run previews which Roles a diff would skip and sets no skip and no Gate. A Role with no trigger entry, a path of unknown kind or missing facts always runs; QA, security and protected Roles are never skipped. With ui_changed false on a PR the a11y job and UI Roles are skipped; tags, the nightly run and cold runs run the a11y job regardless.
- Step budget lint: the check script fails a route that is over its Playbook's Step budget and names the Playbook, the budget and the count. The only merge is the size S QA check plus the review into one code-reviewer Step; it splits back into two Steps when a Contract changed or an earlier Handoff is needs-ceo. A merged Step is one Step under the same context cap.
- stepKey (new Contract step-key v1.0): a versioned key per Step from the dispatch prompt, model, content hashes of every declared input (untracked run files included), Node version, OS, lockfiles, the check script hash, and names plus salted hashes of the env vars it reads. In a Fix round a Handoff is reused only on a full key hit: same key as the newest live entry of that Step, entry Handoff done with no Blocking and unchanged on disk. Any doubt, error, missing or undeclared input is a miss or uncacheable, never a hit, and every result with its reason is logged. A stats command shows how many Steps were reused.
- Cold switch: a cold flag on the check script, or AICO_COLD set, reads and writes no cache and refuses reuse; setting the env var alone is the rollback. The Ship Gate always runs cold: its input Steps run in verify mode and never hit. When a cold and a cached result differ, cold wins, the entry is purged and both results are logged.
- A11y smoke job: a static check of tracked HTML pages for a few markup barriers, with no browser; it fails on a barrier or an unreadable file.
- Contracts: diff-facts v1.0, route v1.0 and step-key v1.0 new; test-run v1.2. ADRs 0075 (fail-safe ui_changed) and 0076 (cold wins).

## User stories
- As the CEO, I want PR CI to cancel stale runs, run one OS and skip docs-only test steps, while tags stay full and cold, so feedback comes faster with no weaker release check (AC1-AC4, AC18).
- As the CEO, I want the change facts worked out once and read by every gate, with a fail-safe UI flag, so no gate disagrees and no UI barrier slips through on a wrong false (AC5-AC7).
- As the CEO, I want the route of a run written down with a reason for each skip and merge, and a lint on each Playbook's Step budget, so runs have fewer Steps and I can see why (AC8-AC11, AC17).
- As the CEO, I want a Fix round to reuse a Handoff only when nothing it depends on changed, with one switch to turn reuse off, so redos drop without a cache ever turning red into green (AC12-AC15).
- As the CEO, I want no env value or secret in any ledger or key row (AC16).

## Decisions
- Fewer Steps first, then fewer redos; the CEO set that order at the brainstorm.
- Reuse is on in v1.0: the CEO chose reuse at the Plan Gate, although the prototype measured only an upper bound of would-be hits. In return every doubt is a miss, the Ship Gate never takes a reused Handoff, and entries never cross runs.
- Fail-safe defaults: unknown path means UI and the Role runs; missing input means a miss. A wrong true costs one job, a wrong false ships a barrier.
- Merged Steps keep the Step cap and one task per agent; only the S QA plus review pair may merge (CEO, Brief Gate).
- Nightly cold run on main and an in-job skip for docs-only PRs instead of workflow path filters, so no PR waits on a pending check (CEO, Brief Gate).
- A key change that can only add misses is a minor bump; anything that can add hits needs a major bump and the CEO.
- Risk tier high: three new Contracts and Core edits to the check script and the pipeline skill. No acceptance criterion was lightened.
- Laws: CRA (release integrity: tags keep the full cold matrix, no weaker release check). GDPR: no personal data; env values stay out of every row. AI Act, EAA, VAT not applicable (internal dev tooling).

## Testing decisions
- QA first: red tests for each acceptance criterion before each build task.
- The ui_changed fixture table covers empty, rename-only, CSS-only, binary, locale, theme-token-only, config and mixed diffs, and asserts plain non-UI diffs give false.
- Each key column changed alone gives a miss; an undeclared input makes the Step uncacheable; a fixture forces a cold-cached mismatch and checks cold wins and the purge.
- PR CI replays the key table fixtures, so a broken key fails the PR.
- CI workflow tests pin triggers, cancellation, the skipped-success checks and that no test or check step retries or hides a red result.
- The route tests cover skips, never-skipped Roles, the budget lint, the merge rule and that only real Role Handoff files count.
- The Lead runs the full suite once before the Ship Gate. That run is the pass record.
- Success metric: median Steps per run per Playbook from step times, last 10 feature and fix runs before ship against the next 10 of each, target 20% fewer, reported in a feedback run. Guard: cold-cached disagreements found at tags stay at 0.

## Out of scope
- A plugin split of the check script and a cached check result in PR CI.
- Localizer batching, a changed-file-to-test map and a rollback-check script.
- Later, as separate projects: a pseudo-locale build in place of per-language runs, and a scripted Tab-through in the a11y job with zoom and reflow checks.
- Never: reuse across runs, a reused Handoff at the Ship Gate, a cancelled tag run, a retried red run.
