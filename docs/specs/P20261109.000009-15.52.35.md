## Problem
One CEO request still breaks into many projects: run 1 built the nested one-project-one-folder layout behind an opt-in flag, but nothing read it and no Playbook joined a project, so every sub-flow (bug, grill, reprompt, fix and the rest) still minted its own project ID and top-level work folder. The CEO, finding, resuming and reviewing one piece of work, has to chase it across folders. This run (run 2 of 2) wires the layout in and makes it the default.

## Solution
- Nested layout is the default: `work-folder new` makes only a project folder per project ID, with a project file holding its description, and each run as a numbered sub folder `<NN>-<playbook>`. The run slug is `<ProjectID>/<NN>-<playbook>`. `--project <ProjectID>` adds the next run. `--layout` is refused as a usage error, non-zero exit, nothing written. `work-folder siblings` writes the Siblings line into the project file; `work-folder branch` accepts a run slug and prints the one project branch `aico/<ProjectID>`.
- Old folders stay put: v2 (including sibling timed run folders), v1.1 and legacy folders are never moved or renamed and list, resume and read byte-identical to before.
- Hand-over project line: a Playbook that hands over to the next one ends the argument with a last line `project: <ProjectID>`. The receiver joins that project with no form when run state lists the ID as active. The line is never part of the request text. For Playbooks whose argument goes through draft-input, the script cuts and checks the line, prints `project: <ProjectID>` only on a join, and `take` accepts `--project <ProjectID>`. An unknown, malformed or inactive ID is cut and ignored, and a new project starts, the same as today's split; output is then byte-identical to the argument without the line.
- Join form: a Playbook started by hand while a project is active shows one form first, join (recommended, up to 3 active projects) or start new. No active project means no form. With no CEO to answer (AFK, headless) the run starts new and the first Gate summary notes `join: start new (no CEO; active <ProjectID>)`.
- Wired Playbooks: pipeline Setup, bug, idea and its routes, reprompt, research, grill, grill loop, grill-me, grill-with-docs, to-spec, to-tickets, review, planning, fix and feature intake. Reprompt names the project line as its only addition to the CEO's prompt.
- Run state sees nested runs: `run-state list` and `active` include runs inside a project folder with their nested slug; old runs appear as before.
- Dashboard project cards: a nested project shows as one card with its description and its runs; a run opens from the card's drawer and never has its own card. Old runs keep their own cards. A run URL with an encoded nested slug returns that run; a slug outside the work folder or malformed is refused and never read.
- Every reader converted: hooks and handoff lint, token ledger, release, reflect, PR links, the plan family, review and worktrees, draft and build runs, flows and checks all accept a nested slug. Per-run files use a flat run key with no slash, so two runs in one project never share a file. Worktree refs carry the project ID and ticket only. Ticket numbers are unique across a project.
- Contracts: work-folder-name v3.0, run-state v2.0 and dashboard v2.0 (majors), draft-input v1.7 and many other minors for nested slugs. ADR 0067 is accepted.

## User stories
- As the CEO, a request that runs bug, grill, reprompt, bug, grill and fix leaves one project folder and one branch.
- As the CEO, typing a Playbook while a project is active asks me once to join it or start new; with nothing active I am not asked.
- As the CEO, a Playbook handing over to the next joins the same project without asking me.
- As the CEO, the dashboard shows each project as one card and its runs in the card's drawer.
- As the CEO, my old folders and runs still list, resume and show as before.

## Decisions
- The nested layout is the only layout for new projects; the flag that made it optional is refused, so no Playbook can fall back silently. The flip shipped last, after every reader was converted and the sweep found no reader using the old name check alone.
- Three majors (work-folder-name, run-state, dashboard), CEO approved at the Plan Gate; every other change is an additive minor.
- The draft-input script handles the project line, not each receiver: the cut is deterministic and testable, the Lead never edits typed text, and the ID check fails closed in one place.
- An invalid or inactive project ID is ignored, not refused: a refusal stops the run again, which is the defect being fixed; ignoring gives today's split.
- `project:` is printed only on a join, so output without the line stays byte-identical.
- AFK and headless runs start new: a wrong join mixes work and cannot be undone, a wrong split is today's behaviour.
- A v2 parent keeps sibling draft and build runs; old folders are never migrated.
- Ticket numbers run project-wide; worktree refs carry no run part.
- Success metric: new top-level work entries per CEO request; target 1 for 10 of the next 10 multi-sub-flow runs, measured at the first aico feedback run after this ships.
- Laws: none apply. Local plugin files, no personal data, no sale, no AI output change.

## Testing decisions
Risk tier high: every criterion has its own test, none covered lightly. Tests drive the CLIs, hooks and dashboard API with nested and old-style fixtures and assert Playbook text.

- AC1, AC10, AC11: Given a hand-over ending `project: <ProjectID>` of an active project, When the child starts, Then it joins with no form; an inactive or unknown ID starts new.
- AC2, AC3, AC5, AC9: Given a nested project, When later runs need files, Then each gets its own numbered sub folder, never a sibling timed folder; a sub-flow with no files makes none.
- AC4: Given the chain bug, grill, reprompt twice, bug, grill, fix, When it ends, Then one top-level entry and one branch exist.
- AC6, AC24: Given the in-scope Playbooks, When their text is checked, Then each Folder paragraph cites the join rule and each hand-over ends with the project line.
- AC7: Given old v2, v1.1, legacy and sibling timed folders, When any converted reader lists or resumes them, Then output is unchanged and nothing moves.
- AC8, AC16: Given runs inside a project, When the board loads, Then the project shows one card with its runs in its drawer; a nested run URL returns the run, an outside or malformed slug is refused.
- AC12: Given any bumped reader, When it gets a nested slug, Then it resolves it; old names give byte-identical output. `work-folder new` makes nested only and refuses `--layout`.
- AC13: the project line reaches a child Playbook both through the Skill tool argument and the slash-command fallback; proved by recorded evidence, not a node test.
- AC14: run-state list and active show nested runs. AC15: hooks and lint attribute a nested Handoff to its run. AC17: per-run ledger and report files use a flat run key. AC18: ticket numbers stay unique across a project. AC19: worktree refs and review scripts accept nested slugs. AC20: draft, ticket and intake records are found by slug. AC21: flows resolve, guard and stage nested slugs. AC22: checks give the same output as for old slugs. AC23: a sweep finds no reader using the old name check alone.
- AC25: Given an AFK start with an active project, When no form can be answered, Then a new project starts and the first Gate summary notes the skipped join.

## Out of scope
- Renaming, moving or merging old folders.
- Changing the project ID shape; project IDs across repos.
- A dashboard redesign beyond project cards and the drawer.
- Later: a CEO command to attach a stray project to another one.
- Known limit, routed separately: a draft run that starts a new project without a join (for example a grill from a typed idea) still gets an old-style top-level folder; joined runs nest.
