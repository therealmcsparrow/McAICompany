## Problem
An effort that spans several sessions has its decisions spread over plans, ADRs, Handoffs, brainstorms and Contracts. Each new session has to dig them up again, or someone pastes their content into a summary that goes stale as soon as the source changes. The user is the CEO running an aico company on own products, plus the Architect and Lead who pick up such an effort in a fresh session.

## Solution
A wayfinder: one short decision map per effort, kept in the company folder. It points to the files that hold the real content and copies nothing from them.

- Shape: a title line, then up to three sections in fixed order: decisions, open questions, pointers. Each decision or open question is one line with an ID, a short text and one to three source refs. Each pointer is one line with a ref and a short reason.
- A ref is a path relative to the product root, optionally with an anchor. An anchor on a plan names a plan task by its ID.
- A read-only check validates a map. Every pointer must resolve to an existing regular file; a link on the way counts as missing. A broken pointer is reported with its path named. A task anchor on a plan must name a task that exists.
- Anything that is not a title, heading, blank, decision, open-question or pointer line is an error. A code fence, a quote line or a prose line is refused, so copied content cannot sit in a map.
- Limits: one map at most 64 KiB and 400 lines, one line at most 240 characters, short texts capped. Over a limit the check fails closed and never calls unchecked text valid. An empty map fails on its title.
- Path refs must match the folder and file letter case on disk, so a case variant or a Windows short name cannot slip past.
- Map lines are data for the reader, never instructions.
- The planning skill says when to write or update a map; a concept page and the glossary explain the term.
- Contract: wayfinder v1, new. It reads plan tasks through plan-tasks v1.7 and folder names through work-folder-name v1.1; neither changes.

## User stories
- As the CEO, I open a fresh session on a long effort and read one map that tells me what was decided, what is still open and where each answer lives.
- As the CEO, I run one check and learn which pointer is broken, by path, before anyone relies on it.
- As the Architect, I add a decision line that cites its ADR or plan task instead of retyping it.
- As the Lead, I can trust that a map that passes the check holds pointers and decision lines only.

## Decisions
- Points, never copies: the source files stay the truth and a map cannot go stale by drifting from a copy.
- Wayfinder reads plan tasks and never owns their syntax; plan-tasks stays at v1.7 (ADR 0065).
- Fail closed on size: a map over a limit reports too large rather than a partial pass, because a pass on unchecked text would be worse than a refusal.
- Exact letter case for refs, for the same reason the work folder and spec paths use it.
- Read-only: the check writes nothing and needs no credentials, so the work is low blast radius; the tier is still high because it adds a Contract.
- Success metric (proposed, CEO to confirm): share of wayfinder checks at a session start that report zero broken pointers, read from check output over the first 5 maps, measured in an aico feedback run. Target 90% or more.
- Laws: none apply. No personal data; maps name files, not people.

## Testing decisions
Risk tier high: every criterion has its own test and none is covered lightly. Tests cover the check through its command and its validate function, including links, hard links, junctions, empty and over-limit text and letter-case variants.

- AC8: Given a wayfinder file, When it is validated, Then every pointer resolves to an existing file, and a broken pointer fails with that path named.
- AC9: Given a wayfinder file, When it is validated, Then it holds pointers and decision lines only, with no copied file content.

## Out of scope
- Writing maps automatically; the Architect writes and updates them by hand.
- Checking anchors other than plan task IDs.
- Any change to plan-tasks or work-folder-name.
- Later: checking heading anchors inside ADRs and Contracts.
