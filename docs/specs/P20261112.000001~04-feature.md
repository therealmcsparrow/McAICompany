## Problem
The Blast Radius mod asked, warned or refused on every git commit that touched Core, a Contract or a security path. The CEO no longer wants it: it slowed every commit, it needed four settings and two locks, and the same guard fits better in review. Serves the CEO as sole operator, and anyone using the settings console, which gets fewer controls.

## Solution
- The Blast Radius mod is gone: no hook answers a git commit from Bash or PowerShell, no state key, no status part (also the old review-depth text in it), no entry in the ready toast. The unused commit detector the mod relied on is removed too, and so are the leftovers only it used: the review-depth guard, two review-depth timeouts and the review-depth script name in the mods runner.
- Session start lists three mods: Savvy, Cache Tax and Reflect. The status line keeps its order version, savvy, cost, reflect, with unchanged caps, and fits one 80-column row with room to spare.
- Settings lose the four keys under mods.blast_radius (enabled, core, contract, security), their two locks and their fail-closed hold. Lock 1 (Reflect model) stays. The security unlock stays, because it still guards the security and compliance review lanes.
- Leftover keys in user or project settings never break a setup. On read the key is dropped (any value, also invalid ones) with one plain warning line naming the ignored key, the level it came from and the release that removed it; no stored value is echoed. Other settings resolve as before, and a leftover no longer marks a project layer broken. The first save of any other setting cleans the file. Any attempt to write the key is refused as an unknown key and nothing is written.
- The settings console has no Blast Radius section, control, lock note or "Loosen the commit gate" dialog; the remaining lock dialogs work as before.
- The guard now lives in review. aico:review, aico:contracts and aico:security-check carry one identical rule: a diff that changes a Core item, a Contract file or a security-relevant file is Blocking unless the plan names that change. Security-relevant means code or config for auth, permissions, secrets, payments, personal data or crypto; hook, sandbox and permission settings; CI and release workflows; dependency manifests and lockfiles. No new setting.
- Contracts aico-mods and aico-settings move to v2.0 (breaking: a state key, status key, hook answer, settings keys and locks disappear). review-depth and run-state keep their versions; only their consumer lists change. ADR 0068 records the removal, ADR 0017 is marked superseded, ADR 0016 gets one amended line.
- The 0.37.0 changelog states under Removed that a security guard is gone, what is no longer checked, that the guard now runs in review, that old keys are ignored and refused on save, that a repo git hook is the option for a commit-time guard, and both Contract majors. README, glossary, product spec and user docs say three mods.

## User stories
- As the CEO, I want commits to go through with no aico question, so commit time is not slowed by a gate I no longer want (AC1).
- As the CEO, I want no trace of the mod outside history, so docs, settings and tests do not describe a feature that is gone (AC2, AC8, AC9).
- As someone with old settings, I want my setup to keep working and saving, with at most one plain warning (AC3, AC4).
- As the CEO, I want the removed keys refused like any unknown key, so they cannot creep back in (AC5).
- As a settings console user, I want no dead controls, and the page to stay accessible (AC6).
- As the CEO, I want a short ready toast and a status line that fits one row (AC7).
- As the CEO, I want surprise changes to Core, Contracts or security files still caught, now as a Blocking review item (AC10).

## Decisions
- AC1 met: a mods test shows no hook asks, warns, denies or sets a status part on such a commit; a sweep test pins the commit detector removal and that nothing imports it.
- AC2 met: the removal sweep allows hits only in changelog history and the removal note, the settings read rule, the two Contract header blocks, ADRs 0016, 0017 and 0068, the three new QA test files, dated specs and the generic product-manager phrase. Removed files are absent on disk. The allowed list was widened by the CEO ("Widen it") plus the Contract-header amendment shown at the Plan Gate.
- AC3, AC4 and AC5 met: retired-key tests cover any value, both levels, save with a leftover, and refusal on the server write path and the settings writer with byte-identical files after refusal. There is no CLI write command, so the CLI keeps its usage refusal. Security found no prototype pollution: only the exact own key is dropped, a letter-case variant stays an unknown key.
- AC6 met: retired-key test for no Blast Radius text on the page plus the existing accessibility test file pass.
- AC7 met: status and shell tests show the three-mod toast and the 80-column fit.
- AC8 met: sweep and settings-docs tests; both Contracts read v2.0 with changelog lines, and no body line names the removed mod. Contract body lines from before the run that still cited aico-mods v1 or the two retired pane states were fixed in Fix round 1.
- AC9 met: six sweep tests on the changelog and docs; the note meets the CRA plain-disclosure duty. No vulnerability, so no CRA reporting duty.
- AC10 met: a test pins the rule text word for word, once in each of the three skills. A blind code-reviewer Step on fixed fixtures gave exactly the expected rows: Blocking for the unplanned Contract and the CI workflow change, nothing for the planned Contract change.
- Guard moved into review, not a new hook (CEO "Add rule to skills"); "unless the plan names it", because a planned Core or Contract change is normal work.
- The plan exemption is per file and covers this rule only; the spec check and the security audit still run on that file.
- Leftover keys are ignored on read and refused on write, never migrated; the stored settings version stays 1.
- Status caps were not spread out over the freed columns; no criterion asked for wider parts.
- Risk tier high: two breaking Contract majors, a settings resolution change and a security guard replaced by a review rule.
- Residual risk accepted (security, Nit): commits made outside an aico run have no guard any more; host permission prompts, the Ship Gate and the PR remain, and the changelog and ADR 0068 point to a repo git hook.
- Open Nits, not fixed this run: the exemption source is the untracked plan, which a builder could edit in a Fix round (security R-2); runs with no plan (fix, maintain, incident) will flag every security-relevant change (R-3); the security-relevant list does not name the plugin's own Gate, lock and review-rule text (R-4); the rule sits a little lower in aico:review and aico:security-check than the plan placed it (reviewer R-1, R-2); the review-depth script keeps three flags with no production caller, removing them would break review-depth (reviewer R-8, architect to decide); a few other Contracts still cite aico-mods v1; the product spec still names aico-settings v1.1 and an old status-line prefix; one mods test still names review-depth as a negative-call string.

## Testing decisions
- QA first: four QA tasks wrote red tests before the code: mods hooks, the removal sweep and pins, settings, and the review rule.
- Three new test files: the no-commit-gate mods test, the removal sweep, and the retired-key settings test; the review-rule test and its two fixtures (a plan and a diff that state no verdict).
- Existing settings, server, accessibility, docs, mods and status tests were rewritten to drop the keys; tests pinning v1.x Contract headers moved to v2.0.
- QA scoped run before Fix round 1: 619 tests, 617 pass, 1 skipped, 1 fail, which was a line-ending artefact in the local working copy only and was normalized. Mods suite 487 pass, 0 fail; project check 8 ok, 0 fail.
- Fix round 1 and 2 reruns: the five touched test files 182 pass, 0 fail; mods suite 487 pass, 0 fail after the runner cleanup.
- The rule-check node-test lane timed out at 480 seconds in review (not a test failure); the Lead's one full suite before the Ship Gate is the check.
- Success metric: zero leftover hits outside the allowed list, the rule present in all three skills, full suite green; measured by QA before the Ship Gate (met in QA's acceptance Step, full suite pending the Lead's run).

## Out of scope
- Rewriting changelog history, dated specs, or the generic phrase "blast radius" in the product-manager agent, its golden file and the Pocock spec.
- Removing the review-depth script or its pipeline use; deprecating its three unused flags is a later architect decision.
- Removing the security unlock.
- A replacement commit hook or repo git hook (later, only if the CEO asks), and any new setting for the review rule.
- Binding the plan exemption to the hash-bound plan, a stand-in for runs with no plan, and naming guardrail skill text as security-relevant (follow-up rule change, later).
- Migrating stored settings files.
