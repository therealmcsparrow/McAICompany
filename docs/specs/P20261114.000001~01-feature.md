## Problem
aico rules that a hook can enforce lived only as skill text. A Role could skip them, and the CEO paid tokens to load them in every session. The context cap, the ban on staging everything, the ban on reading secrets files, the model floor and the protection of aico's own settings were all promises, not checks. Serves the CEO running aico in Claude Code, who needs these rules enforced in the Lead and in every Step, with a few token-saving mods in the Lead session that never weaken them.

## Solution
- A hook engine runs one rule table before each tool call, in the Lead session and in every Step session. Rules are pure functions with no file, network, process or environment access; settings reach them as a snapshot taken at each Step dispatch. Three new Contracts describe it: hook-event v1 (field allow-list, names and types only), mod-hook v1 (verdicts allow, deny with rule ID, note; engine order; fixtures; latency) and mod-manifest v1 (each mod is a guard, saver or gate).
- Five guards, fail closed, locked on: cap (cap.M1), git add (git-add.M-SEC1), .env (dotenv.M-SEC1), model floor (model-floor.M1), self-protect (self-protect.M-SEC1). A refused call shows a short reason with its rule ID; the first refusal per guard shows the CEO one note, later ones are counted. Refusals go to a capped deny log and the run's guard record, with rule ID, kind, time and session only, never file text.
- The context cap moved into the handoff mod as the only enforcer. At the default cap 180000 it warns and freezes at 162000 and hands over at 180000. A threshold of 200000 or 250000 uses 90% of it. A bad value falls back to 180000 with one warning that names it. The old cap code is gone.
- Guards that cannot decide (crash, timeout, malformed payload, missing script or config, half-written settings snapshot) deny with rule ID and error. Savers in the same case pass the call through unchanged.
- Run Setup stops and names any guard that is missing, off or hash-mismatched. A mod or rule table outside the plugin path, or with a wrong hash, is not loaded and the CEO is told. A session-start drift check runs the fixtures; on a renamed hook field the CEO is warned, savers switch off and guards deny with hook-payload-changed.
- Off switch: the CEO launches Claude Code with AICO_GUARDS=off and the guards stand down in the Lead session only. Steps stay guarded. No agent tool call can set it.
- Pack savers, Lead session only, no model call and no outbound call: Cache clock (countdown, no ping), Browser screenshot note (efficient-browser-use, off by default, never shrinks hands-on-tester evidence), Switchboard (the aico-mods pane: every mod and guard built from manifests, guards shown locked on, saver switches written through aico settings only, last five refusals) and Savings (the aico-savings pane: median real tokens per Step from the ledger, no data or unmeasured instead of NaN, estimates labelled apart). No saver overrides a Role pin, the model floor or the cap.
- The rule-check and handoff-lint tools import the shared rule module with byte-identical output.
- NOTICE credits Ben AI with the upstream pack versions. The pack carries no licence, so aico's versions are written clean-room from a behaviour description.
- Contracts: context-guard v2.0, run-state v3.0 and aico-settings v3.0 (breaking, CEO approved at the Plan Gate), aico-mods v2.2, plus the three new ones. ADRs 0070 (cap in handoff mod), 0071 (one engine, one rule table), 0072 (guards before release).

## User stories
- As the CEO, I want the five rules enforced as hooks in the Lead and every Step, so no Role can skip them (AC5-AC8, AC28).
- As the CEO, I want one cap enforcer with a settable threshold and a clear warning for a bad value (AC11-AC13).
- As the CEO, I want a guard that fails to deny, and a saver that fails to stay silent, so a broken mod never opens a hole or blocks work (AC3, AC9, AC10, AC17).
- As the CEO, I want a run not to start when a guard is missing, changed or out of place, and a warning when Claude Code changes a hook field (AC14, AC18, AC19, AC29).
- As the CEO, I want guards I cannot switch off by hand-editing settings, but one off switch for my own Lead session (AC15, AC16).
- As the CEO, I want token-saving mods in the Lead session that show notes only and show real savings (AC22-AC26).
- As the architect, I want every rule pure, tested with pass and block fixtures, and shared with the existing checkers (AC1, AC2, AC4, AC20, AC21).
- As a maintainer, I want the pack credited and its licence position recorded (AC27).

## Decisions
- Guards are command hooks, one engine process per call, because the spike showed command hooks fire in Step sessions; pane savers stay function-hook mods.
- Release 1 was not blocked: the spike found a hook field for every guard (AC29).
- The cap left the per-run freeze in run state; it is read from a snapshot per Step dispatch, so a settings edit applies at the next Step (AC17).
- No settings key can switch a guard; lock beats switch (AC15). Savers switch through aico settings only; there is no separate switch file (AC23).
- Existing mods without hooks are kind gate, so every mod has a manifest without being called a saver.
- Guards stop accidents, not a determined attacker. A command crafted to get around them can succeed.
- Known limits, accepted by the CEO with no further fix round:
- R-13: the .env guard finds a PowerShell host only by its literal name. Quoted or expanded host names (split by empty quotes, a backslash or a variable) skip the leading-wildcard check and can read a secrets file. Same class as compliance R-2.
- R-26: cmd started from Bash with a quoted wildcard (type or more on star-env) can read a secrets file, because cmd wildcards match the leading dot. A regression from round 4.
- R-24 and R-25 (compliance R-1): the self-protect piped-text scan is quadratic on one crafted shape of escaped quotes and long whitespace. Near the 200000-character command cap it takes about 4 to 5.6 seconds, past the rule deadline, so the call is denied or times out. It fails closed: a false block, never a bypass.
- Compliance R-2: see R-13.
- Further Debt: no SBOM in CI yet (CRA); git add through a separate work tree; chained stdin pipes and command substitution into a shell; dotglob; PowerShell encoded commands; a Glob or Grep pattern of a bare star over-denies.
- Risk tier high: Contracts, secrets reads and session freeze. No acceptance criterion was lightened.
- Laws: CRA (guards are security features; vulnerability handling and SBOM via the release Module, SBOM still Debt), GDPR (hook schema and logs store names, types, counts and hashes only). AI Act and EAA not applicable in release 1; panes follow the art direction.

## Testing decisions
- QA first: red tests for each Acceptance criterion AC1-AC29 before each build task; every guard rule ID ships only with a pass and a block fixture (AC4).
- Edge cases pinned: cap thresholds at 161999, 162000, 179999, 180000, 180001 and the bad values listed in AC12; git add and .env evasion forms through case, backslash, relative, drive-letter, UNC and short paths, chained and quoted commands; tool output that says allow (incl. ANSI and HTML).
- Host tests run the real engine with pins and a session start; timing tests use two sizes and a ratio for every scan that had a slow-regex finding.
- A static scan proves ported pack code makes no outbound call; a parity test pins rule-check and handoff-lint output against base.
- One executable test per clash-table row proves no saver overrides a Role pin, the model floor or the cap (AC26).
- The known limits above have no passing deny test; they stay open as Debt.
- The Lead runs the full suite once before the Ship Gate. That run is the pass record.
- Success metric: zero false blocks on QA's fixed replay at the Ship Gate and over the next 5 real runs, read from the ledger's deny entries. Guardrail: median real tokens per Step at or below the median of the last 10 runs before the guards. Reported in the feedback run after 5 runs.

## Out of scope
- Release 2: the five MOD skills (version, help, settings, dashboard, language), the help and type preamble mod, the Haiku mods (input-router, model-router, effort-optimizer, research-router) and the skill text cuts.
- Fixing the known limits above in this release.
- Never: a keep-warm ping, the pack's own switch file, a built-in deny list, raw payload logging, a 250k default cap, a guard kept as skill-only text.
