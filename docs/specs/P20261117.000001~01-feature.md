## Problem
The Lead ran in the main chat. When it reached its context cap, a hand-over needed a frozen session, the lead_new_session MCP tool and typed clear commands on Windows. The CEO wanted the main session to do less: spawn a Lead, relay the CEO's forms and spawn the next Lead. The Lead itself spawns the Roles.

## Solution
- Every aico Playbook runs in one plugin agent, `aico:project-manager`: the Lead, spawned by main in the foreground. Main dispatches no Role and runs no lint, ledger, commit, Gate or run-state script. The guard enforces this.
- The Lead dispatches every Role as a nested foreground subagent. Handoffs, ledger, step-times and context-guard Step records stay the same as before. A Lead is not a Step, so step-times skips it.
- Hooks tell the Lead from a Role by the harness field `agent_type`, never by model text. Any other subagent is a Role, at any depth. A Role can never spawn a Lead.
- Every Lead turn ends with one STATUS block of at most 40 lines: `needs-ceo`, `handover`, `done` or `blocked`. Main reads only line 1 and the named keys. A missing or malformed line counts as `blocked`. Main offers one `retry` resume and never guesses an answer.
- CEO forms (lead-relay v1): the Lead opens a form in the run's form record and ends with `needs-ceo`, giving the questions and 2-4 options each, recommended first. Main asks with AskUserQuestion, using the options verbatim. A hook records the answer from the harness's tool result, never from main's text. A pre-filled answer is refused. A fresh Lead reads the answer from the record.
- Gate passes trace to a recorded CEO answer: `run-state gate` (run-state v3.1) refuses a non-auto Gate unless a newer CEO answer chose that result. One answer passes one Gate once.
- Hand-over: at its handover point with no Step running, the Lead writes a Lead Handoff (lead-handoff v3.0) and ends with `handover`. Main starts a fresh Lead that boots from the resume reference, takes the base commit and tier from records, re-runs no finished Step and loses no open form. While a Step is running, the Lead dispatches nothing new and hands over after the Step ends.
- Retired: the lead_new_session MCP tool, its registration and helper, the Windows typer, and the background and turn records (lead-session-mcp v2.1 is retired). The Lead-in-main-chat mode is gone.
- Guards go from five to four. Shell commands are checked only for secrets files and for writes to run records (ADR 0079). `AICO_GUARDS=off` covers both main and the Lead, and two checks stay on under it.
- The Ship Gate summary counts subagent Leads in `lead hand-overs` and `lead peak`.

## User stories
- As the CEO, I start a Playbook and the main chat stays small and responsive for the whole run.
- As the CEO, I answer each Gate or question once in a plain keyboard-only form, and the run continues with my exact answer.
- As the CEO, if I decline a form, the run waits. I say resume and get the form again.
- As the CEO, a long run hands over between Leads without me typing anything and without losing an open question.
- As the CEO, a crashed Lead is reported to me as blocked with one resume offer, never with a guessed answer.

## Decisions
- D1: lead_new_session retired. A main session that only relays never nears its cap (ADR 0077).
- D2: CEO answers are recorded by a hook from the harness tool result. SendMessage resumes stay banned, and subagents have no AskUserQuestion (ADR 0078).
- D3: Lead-in-main-chat mode removed, so there is one path, one set of docs and one set of tests.
- Guards stop judging shell commands except for secrets and run records. Accepted risk signed off by the CEO (ADR 0079).
- Contracts: lead-relay v1 (new), run-state v3.1, lead-handoff v3.0, step-times v1.3, context-guard v3.0, hook-event v1.4.
- One open form per run. A form whose questions match an open form in another run is refused, so an answer can never match two forms.

## Testing decisions
- Tier high: each of AC1-AC12 has its own test. None is covered lightly.
- Spike S1 proved that hooks fire with `agent_id` and `agent_type` at depth 1 and 2, and that a deny holds at depth 2. Spike S2 fixed the shapes of answers and declined forms. Tests use those payload shapes.
- Retirement tests check that no lead_new_session tool, registration or allow-list entry is left.
- Success metric: main-session peak context per run is at or under 40k tokens, with 0 lost CEO answers. It is measured at each Ship Gate over the next 3 runs and reported in the next feedback run.

## Out of scope
- New UI or dashboard work.
- SendMessage resumes of a Lead. Every resume is a fresh Lead.
- Changes to Role or Step behaviour.
- Typing on macOS or Linux.
- Per-round redesign of brainstorm or cooler.
- Later: the Lead asks the CEO itself if subagents get AskUserQuestion. Fewer respawns for chatty Playbooks.
