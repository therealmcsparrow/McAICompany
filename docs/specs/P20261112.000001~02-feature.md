## Problem
The CEO cannot see where aico run tokens go: Lead or subagents, file reads, test output or command output. Cache Tax also showed a wrong cache expiry for anyone whose Lead cache lasts 5 minutes, because its clock assumed a fixed 1 hour and labelled it measured. Serves the CEO on an API key, usage credits or a cloud provider.

## Solution
- Cache Tax clock is lifetime-aware. The Lead handover adapter reads the cache lifetime (1 h or 5 min) of the last main-loop request from the Lead transcript and serves it as a new `ttl` key in its context output (lead-handoff v2.2, minor, additive).
- Cache Tax takes that reading: with 5 min the expiry is the last main-loop request plus 5 minutes, pane line `Lifetime: 5 min (measured)`, same in the status part. With 1 h the pane and status are byte-identical to the old behaviour, label `1 h (measured)`.
- When the lifetime cannot be read (no active run, missing or bad value, failed call) the clock falls back to 60 minutes labelled `1 h (assumed)`. It never throws and never holds a request. Side effect: outside an active run the pane now says `assumed` where it used to say `measured`.
- A session start marks the clock stale; the next main-loop request or tick resets it, so the first request after a session start is kept and no later tick wipes it.
- Contract aico-mods moves to v1.9 (minor, additive): lifetime source, the three labels and a state source `assumed`. The existing two-argument request call and the clock result shape are unchanged.
- New read-only token-breakdown script (new Contract token-breakdown v1) over the last N shipped runs. Per run it shows spend per Role, the subagent total and the Lead total, or a per-item `not measurable from records` reason. Across runs it shows shares of added and carried context for file reads, test output, command output, other tool results, mixed, prompt and reply. It ends with the top sink and a yes/no line for the test-output tail hook. It prints only counts, shares, run IDs and Role names, never command text, paths or tool results. Run files are read with the real-path, single-link and handle-tie checks, and a junctioned work or company folder that leaves the repo is refused.
- One breakdown report over the last 10 shipped runs, kept in the run folder. Verdict: top sink is prompt at 38.0% of carried tokens, then command output at 29.3%; test output is 2.6% (rank 6 of 7). Do not build the test-output tail hook. The Lead total could be measured in only 1 of 10 runs (no Lead session recorded in the other 9).
- User docs: Cache Tax page lists the three labels; the token cost concept page gains a Token breakdown section; changelog Unreleased has one Changed and two New entries.

## User stories
- As the CEO on a 5 minute cache, I want Cache Tax to show the real expiry, so I don't plan around a cache that is already gone (AC4).
- As the CEO on a 1 hour cache, I want Cache Tax to look exactly as before, so nothing I rely on moves (AC5, AC7).
- As the CEO, I want an unread lifetime marked as assumed, so I never mistake a guess for a measurement (AC6).
- As the CEO, I want one report naming where run tokens go, by Role and by kind of context, so I spend effort on the biggest sink (AC1, AC2, AC3).

## Decisions
- AC1 met: the breakdown lists 10 run IDs, splits spend per Role with a subagent total, and shows the Lead total or its `not measurable` reason; per-run Role sums match the ledger report totals. Lead readable in 1 of 10 runs.
- AC2 met: shares for file reads, test output, command output and other tool results are measured from transcripts, not estimated; a request with mixed tool types counts as `mixed`, never split; a missing transcript is named `not measurable from records`.
- AC3 met: the report ends with top sink prompt 38.0% and the line "Test-output tail hook: no".
- AC4 met: 5 min reading gives expiry at last request plus 5 minutes in pane and status, label `5 min (measured)`.
- AC5 met: 1 h reading gives byte-identical pane and status output to the old clock.
- AC6 met: null, missing key, bad value, failed call and no active run all give 60 minutes labelled `1 h (assumed)`, no crash, no blocking hook.
- AC7 met: aico-mods v1.8 to v1.9 is additive; every existing Cache Tax test passes unchanged. Only three key-list pins in Lead handover tests gained `ttl`; they are not Cache Tax tests.
- Lifetime source is the Lead transcript, not the model-switch event, because that event fires only on a model switch and a 5 minute user who never switches would never get a reading.
- Breakdown is a separate read-only script, not a ledger command, so the ledger Contract stays unchanged and no estimate is stored.
- Risk tier high: two Contract minor bumps and one new Contract.
- Residual risk accepted: a directory junction swapped three times between the work-folder check and the file open could still line up. Node has no openat, the reference run-state reader has the same window, and only 12-hex session tags are kept, so impact is low.
- Open nits, not fixed this run: R-9, the breakdown run-file read reads to end of file after the size check, so a growing file can exceed the cap (fix: a bounded read like the run-state reader). R-10, the breakdown ledger reader and its safe-file helper still check by path with non-native real path and no handle tie. R-11, the symlink test cases skip on this Windows host and are unproven until they run on CI Linux or an account with symlink rights. R-19, the source comment on the stale-clock flag in the Cache Tax mod still says only the next tick resets the clock; the next request now resets it too.
- Follow-up proposed by security: one shared, exported safe reader for run files in the mods library, which would close R-9 and R-10.

## Testing decisions
- QA-first: each acceptance criterion has its own test, written red before the code.
- AC1 to AC3: fixture tests on the breakdown script for per-Role sums against report totals, run IDs and count, Lead row or reason, category shares with a missing transcript named, the ranked last line and yes/no rule, and that no command text or path is printed. Two hostile junction tests (work folder and company folder pointing outside the repo) were red before the fix and pass now. Suite result: 32 tests, 30 pass, 2 skipped (symlink rights).
- AC4 to AC6: lifetime clock tests for the 5 min expiry and label, the 1 h byte-identity, and each fallback case; plus two tests for the session-start race (mod off at start then switched on, a request inside the start-up window), red before the fix.
- AC7: the existing Cache Tax and mods library tests run unchanged.
- The full suite timed out at 480 seconds in the reviewer lane, which is a tool timeout, not a failing test; the Lead's single full run before the Ship Gate is the verdict.
- Success metric: Cache Tax expiry error for 5 minute users goes from up to 55 minutes to 0, checked by the AC4 test at Ship. Report metric: a named top sink with its share, prompt 38.0%, read once at the Ship Gate.

## Out of scope
- The test-output tail hook (report verdict: no).
- The seven skipped mods of the reviewed pack, the efficient browser mod, keep-warm, and any code or text copied from the pack.
- Estimated or saved token counts in the ledger.
- Effort or model overrides.
- Running ledger reconcile on old runs.
