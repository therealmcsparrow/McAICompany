## Problem
Replies in the main session are shaped for reading, not for acting, so a CEO with ADHD (or anyone who finds long replies hard to act on) has to dig for the next step. Serves the CEO as the one person who types commands to aico.

## Solution
- New ADHD mode skill, started only by the CEO with the aico:i-have-adhd command (optional argument help). It is an aico rewrite of the ideas in the MIT-licensed i-have-adhd skill by Ayoub Ghriss (https://github.com/ayghri/i-have-adhd), not a copy.
- The skill holds 10 rules (next action first, numbered steps, step n of m, at most 5 visible items per group without dropping any, concrete time estimates, visible wins, no preamble, recap or closers, matter-of-fact errors, one closing next action), 6 break cases (explain, destructive action confirm, debug spiral, ambiguity, task wins, harness wins) and a pre-send check.
- Turning on gives one line naming the two off phrases, then the shaped answer. "stop adhd mode" or "normal mode", any letter case, gives one confirmation line and default style resumes. The mode lasts across topic changes until switched off.
- Session only: the mode, and the fact that the CEO uses it, is never written to a file, Handoff, dispatch prompt, setting, run state or auto-memory. A new session, also a Lead hand-over session, starts in normal mode. Roles never receive the mode.
- Machine-read output stays unchanged: Handoff frontmatter and headings, Gate and ask form fields and options, Step dispatch prompts, AC IDs, English machine keys and the Language rule. Gate summaries stay in full: every line a Gate requires, verbatim quoted lines, pasted blocks and Nits, never capped, grouped, reordered or cut as recap (added in Fix round 1).
- The CEO's own tone and length instructions still apply inside the shape; on a clash the shape element stays, written tersely.
- Registered as an always-on, CEO-only command in every company type: it joins the always-on list after add-skill and before reprompt, and the CEO-only list. Contract company-type moves from v2.1 to v2.2 (minor, additive). The Lead's list of CEO-only Playbooks names it. The model cannot start it.
- The upstream MIT notice ships verbatim in a LICENSE file next to the skill, followed by a source line ("adapted for aico"). The README credits the repo, the author and MIT in the form of the existing credit lines.
- User docs: a command page, a row in the command list under Setup and help, a row in the README command table, a bullet in the product spec, a glossary entry, and one Unreleased changelog entry that names ADHD mode and keeps the settings console page line (PR #69).

## User stories
- As the CEO, I want replies to lead with the next action and number multi-step work, so I can act without reading everything (AC1, AC4).
- As the CEO, I want the mode to stay on until I end it, and to end with one plain phrase (AC2, AC3).
- As the CEO, I want only me to turn it on, never a file, Handoff or web page (AC5).
- As the CEO, I want Gates, forms and Handoffs to stay exactly as they are, so the mode never hides a line I must approve (AC6).
- As the upstream author, I want my license notice and credit kept (AC7).

## Decisions
- AC1 met: test on next action first, numbered steps, step n of m and one closing next action; eval prompts 1 to 3 pass.
- AC2 met: persistence test; eval prompt 6 (topic change) passes.
- AC3 met: both off phrases and the one confirmation line tested in the skill and on the command page; eval prompt 10 passes.
- AC4 met: one test per rule, the 6 break cases, the pre-send check, and a not-verbatim test against 10 or more distinctive upstream lines. The rule-7 test now matches rule 7's own line only (R-1, Fix round 1).
- AC5 met: the disable-model-invocation flag and the "never turns the mode on" line are tested; the registration test shows the command is CEO-only and hidden from the Skill tool.
- AC6 met: the machine-read section is tested, including a section pin for Gate summaries in full (Fix round 1, from the security audit); eval prompt 9 (Gate form) passes. Security re-check closed the finding.
- AC7 met: LICENSE is byte-equal to the upstream MIT text plus the source line; the README credit names repo, author and MIT. Legal confirmed MIT and GDPR Art. 9 duties are met (draft, not a lawyer's review).
- AC8 met by review evidence, no permanent test (plan, Fix round 1): a test pinned to the base commit would go red for good at the next release bump. The code-reviewer's Fix-round re-check found the judging diff from the base commit to the run ref touches none of the dependency folder, the package manifest, the lock file or the plugin manifest (empty output).
- AC9 met: the command appears in help in every company type (check-playbook passes in all four), on its command page and in both command lists; the project check gives 8 ok, 0 fail. The full suite is the Lead's single run before the Ship Gate.
- AC10 met: the Unreleased changelog names ADHD mode and keeps the settings console line; no settings code changed.
- No SHA pin of upstream: the text is a rewrite that is never synced, and the copy was compared by summary, not byte diff.
- Risk tier high: a Contract minor bump and a health-data angle (GDPR Art. 9), kept safe by storing nothing.
- Open nits, not fixed this run: R-4, R-5 and R-6 from the round-0 code review. R-7, the section-pin test title still says "red until F2" though F2 landed. R-8, the cut check in that pin is a bare substring that would also match a word like shortcut. Security R-5, the Gate summary clause does not name the prose before a non-Gate ask form (not exploitable; the form itself is covered). QA: the no-network half of AC8 has no automated pin; the pre-send check could say a confirmation question counts as an action. Legal: keep auto-memory wording about the feature, never the person. Existing Debt, not this run: a git call in the QA acceptance test still lacks the full git safety form.
- Follow-up proposed by security and the senior engineer: a project Must that a CEO-facing output-style mode leaves Gate summary content unchanged, next to proj.M-SEC8.

## Testing decisions
- QA-first: each acceptance criterion has its own test, written red before the code, except AC8 (review evidence, see Decisions).
- Three test files cover the skill text, the registration and the docs: 41 tests, 41 pass, 0 fail, in both the QA run and the code-reviewer re-check.
- Existing pins for the always-on and CEO-only lists were updated for company-type v2.2 (counts 10 to 11 and 34 to 35).
- Eval: 10 fixed prompts (3 multi-step, 2 errors, 1 topic change, 1 destructive action, 1 ambiguous ask, 1 Gate form, 1 normal mode), fixed before answering: 10 of 10 pass the pre-send check, target 9. Same-model grader, so it is a self-check.
- Success metric: share of mode-on replies passing the pre-send check, target at least 9 of 10. Measured by QA at the Ship Gate (10 of 10), then by the CEO on 10 real replies at the feedback run 2 weeks after release.

## Out of scope
- Storing the mode on disk or in settings; an opt-in default via settings (later, needs a health-data review first).
- Changing Roles, Handoffs, Gate forms or any Contract beyond the company-type minor bump.
- A new plugin dependency, package or network use.
- Auto-start by model, hook, file or Handoff; per-Role ADHD variants.
- Settings console work (changelog line only).
- A persona with a cognitive need in the project personas (later).
