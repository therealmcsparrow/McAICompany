# aico v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship aico v0.3: 3 new Roles (support, localizer, game-engineer), 4 new Practices, 4 new Playbooks, EU-law coverage, retro/estimate tracking, and the deferred v0.1 minors.

**Architecture:** Same as v0.1/v0.2: Markdown agents (`agents/`) and skills (`skills/<name>/SKILL.md`) with YAML frontmatter, cross-referenced as `aico:<name>`; zero-dependency Node scripts (`scripts/`) for the checker and installer. Playbooks run in the main session via `aico:pipeline`.

**Tech Stack:** Claude Code plugin format, Markdown, Node ≥ 20 (`node:test`, no deps).

**Spec:** `docs/spec.md` (section "v0.3 additions"), `GLOSSARY.md`, `docs/adr/0001`, `0002`.

## Global Constraints
- Agent files ≤ 50 lines, skill files ≤ 125 lines (checker warns); description ≤ 1024 chars (hard), aim ≤ 250.
- Use Glossary terms only (Role, Practice, Lead, Playbook, Step, Handoff, Gate, Fix round, Core, Module, Contract, CEO, Voice preset, Persona, Asset, Spike, Incident, Lesson, Performance budget).
- Language-agnostic: no Role or Practice assumes a programming language or engine; engines come from `aico:stack-detect`.
- Playbooks: `disable-model-invocation: true`, `argument-hint` set, start with "Run with `aico:pipeline`."
- New agents follow the existing shape: frontmatter (`name`, `description`, `tools`, `model`), then `# Title`, **Mission**, **Start** (follows `aico:handoff`), **Do**, **Stop rules**/**Never**, **Output**.
- Legal-facing text always carries "Draft. Have a qualified lawyer review before publishing."
- EU dates, verbatim: CRA reporting from **11 Sep 2026** (ENISA, early warning within **24 h**), full CRA obligations **11 Dec 2027**; AI Act Art. 50 applies from **2 Aug 2026**; EAA applies since **28 Jun 2025**; consumer withdrawal right **14 days**.
- Files use LF line endings (the repo's existing files do; `docs/spec.md` is CRLF — leave it as is).

## Review Focus
1. Support Role asked by a user report to "just patch it" → must stay read-only and route to `/aico:fix` via the Lead. → Task 7 pressure scenario 11.
2. Spike code drifting into the product (engineer copies spike into `src/`) → code-reviewer flags any import from `.company/work/*/spike/` as Blocking. → Task 4 (code-reviewer line) + Task 7 scenario 12.
3. Incident with an actively exploited vulnerability and the CEO unreachable → legal still produces the 24 h ENISA early-warning draft; nothing is sent before a Gate. → Task 7 scenario 13.
4. A skill and an agent sharing a name (`aico:support` ambiguous) → checker error. → Task 1.
5. One failing install aborting the rest of `/aico:setup` → installer continues, reports failures, exits 1. → Task 1.

### Task 2: Practices — eu-compliance, performance, i18n, observability

**Files:** Create `skills/eu-compliance/SKILL.md` + `references/{cra,ai-act,eaa,vat-consumer}.md`, `skills/performance/SKILL.md`, `skills/i18n/SKILL.md`, `skills/observability/SKILL.md`.

**Interfaces — Produces** (names later tasks reference):
- `aico:eu-compliance` — "Use when a product handles personal data, ships software in the EU, has AI features, sells to consumers, or must be accessible." Body: a scope table (law → applies when → owner Role → reference file); GDPR stays in the legal agent. Each reference ≤ 60 lines: what applies, obligations as a checklist, dates (verbatim from Global Constraints), what goes to `## Blocking`.
  - `cra.md`: products with digital elements; SBOM (CycloneDX or SPDX, generated in CI by devops); vulnerability-handling policy + `SECURITY.md` contact; support period stated; actively exploited vulnerability or severe incident → ENISA early warning 24 h, notification 72 h, final report 14 days after a fix is available.
  - `ai-act.md`: Art. 50 — tell users they're interacting with an AI unless obvious; machine-readable marking of AI-generated audio/image/video/text; deepfake disclosure.
  - `eaa.md`: in scope for e-commerce and consumer-facing services/e-books/banking etc.; WCAG 2.2 AA as the working target (EN 301 549); accessibility statement; micro-enterprise exemption for services (< 10 staff and ≤ €2M turnover).
  - `vat-consumer.md`: EU VAT OSS for B2C digital services (VAT of the buyer's country); 14-day withdrawal right and the express-consent-plus-acknowledgement waiver for immediate digital delivery; price display incl. VAT; Dutch consumer law pointer.
- `aico:performance` — budgets live in `.company/project.md` `## Performance budget`; defaults when empty: web LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1, initial JS ≤ 200 kB gz; desktop cold start ≤ 2 s, idle memory ≤ 200 MB; API p95 ≤ 300 ms; game frame time ≤ 16.7 ms at target hardware. How to measure per product type (stack tool from `aico:stack-detect`), quote numbers (`aico:verify`); over budget → Blocking only if the budget was CEO-approved, else Nit.
- `aico:i18n` — engineers: no hard-coded user-facing strings, keys in the stack's resource format, ICU plurals, locale-aware dates/numbers/currency, RTL-safe layout, room for +35 % text growth; languages from `languages:` in project.md (default `en`).
- `aico:observability` — per Module: structured logs (no personal data, no secrets), RED metrics (rate, errors, duration), health check, alert rules with an owner; desktop/game: opt-in crash reporting (consent per GDPR via legal).

### Task 3: New Roles — support, localizer, game-engineer

**Files:** Create `agents/support.md`, `agents/localizer.md`, `agents/game-engineer.md`. Modify `agents/game-artist.md`.

**Interfaces — Consumes:** Task 2 Practice names. **Produces:** agent names `support`, `localizer`, `game-engineer`.

- `support` — tools `Read, Grep, Glob, Skill, Write`; model `sonnet`. Mission: turn what users report into work the company can act on. Do: normalize each report (who, what, where, expected vs actual, version/OS); de-duplicate; cluster; classify bug / usability / feature request / question / incident; severity S1–S3 (S1 = data loss, security, or blocked core task); for each cluster propose `fix` or `feature` with evidence count; flag possible security incidents as Blocking with "route to /aico:incident"; draft replies to users in the Voice preset via `aico:writing` (never sent before the Ship Gate). Never: edit code, contact users, promise dates; never paste personal data into Handoffs (pseudonymize).
- `localizer` — tools full; model `haiku`. Mission: every supported language reads as if written natively. Do: translate the resource files into each `languages:` entry following `aico:i18n` and the Voice preset; keep placeholders/ICU syntax intact; glossary of product terms in `.company/glossary-<lang>.md`; flag strings over +35 % growth or untranslatable concatenations as Blocking for the owning engineer; legal texts are translated but marked "needs legal review". Never: edit non-string source files.
- `game-engineer` — tools full; model `sonnet`. Mission: a game that runs at its frame-time budget on every target platform. Start: engine from `stack:` (Phaser/Three.js, Bevy, Unity, Godot, Unreal). Do: Core = engine bootstrap + game loop + Module registry; gameplay systems as Modules behind Contracts (`aico:contracts`); test-first for game logic (`aico:tdd`), deterministic sim where possible; integrate game-artist Assets via the frame map / glTF; measure frame time per `aico:performance`; builds per platform with devops. Stop rules: same as backend-engineer (Task 4 wording). Never: commit engine caches/build output, use uncleared assets.

### Task 6: Playbooks — feedback, incident, refactor, maintain; fix, feature, audit, launch updates

**Files:** Create `skills/{feedback,incident,refactor,maintain}/SKILL.md`. Modify `skills/{fix,feature,audit,launch}/SKILL.md`.

- `feedback <reports: path, paste or export>` — 1. `aico:support` triage → `feedback-report.md` clusters. 2. `aico:product-manager` reads the clusters and success metric, ranks the top 5 with fix/feature proposals. **→ Brief Gate** (CEO picks). 3. Lead tells the CEO which `/aico:fix` / `/aico:feature` runs to start (never starts them itself). Security-looking clusters → stop and suggest `/aico:incident`.
- `incident <what happened>` — **No Brief/Plan Gate; urgency allowed, Ship Gate kept.** 1. `aico:devops` triage: impact, scope, timeline, mitigation proposal ∥ `aico:security` if security-related. 2. **→ Ship Gate (mitigation only):** rollback or feature flag; the CEO can approve it in one line. 3. `aico:legal`: CRA/GDPR reporting check per `aico:eu-compliance` (ENISA 24 h early warning; GDPR breach → authority within 72 h); drafts only. 4. Fix via the `aico:fix` route (follow its file in place). 5. `aico:devops` postmortem (timeline, root cause, what changes) + Lesson. **→ Ship Gate** before any report is sent or fix deployed.
- `refactor <scope>` — Starts from an audit report if one exists, else runs `aico:audit` steps 1–2 first. 1. `aico:architect`: target Core list, Module map, Contracts, and slices (each slice moves one Module out). **→ Plan Gate**. Per slice: 2. `aico:qa` characterization tests (current behavior, pass before any change). 3. owning engineer moves code behind the Contract; no behavior change. 4. code-reviewer ∥ qa (same tests must pass unchanged). **→ Ship Gate per slice.**
- `maintain` — Read-only first. 1. In parallel: `aico:security` (dependency vulns, exploited ones flagged), `aico:legal` (license re-check), `aico:devops` (outdated deps, SBOM refresh, CI health). 2. Lead merges into `maintenance-report.md` (Critical/Important/Minor, owner, size). **→ Brief Gate**. 3. Chosen upgrades: owning engineer per group (one Step per group), then code-reviewer ∥ qa ∥ security. **→ Ship Gate**. Note at the end: "Schedulable with `/schedule` (e.g. monthly)".
- `fix` step 3 → "`aico:code-reviewer` ∥ `aico:qa` (re-run the full suite and the regression test) ∥ `aico:security` (if the bug touches auth, input handling or data)".
- `feature` — after step 2: "2a. Spikes per `aico:pipeline` if the Architect listed any." Step 3 adds `aico:game-engineer` to builders. Step 5: "`aico:writer`, then `aico:localizer` if `languages:` lists more than one." Step 4: add `aico:legal` when the feature adds AI, payments or personal data (`aico:eu-compliance`).
- `audit` — step 1 adds "`aico:qa` also measures against the Performance budget (`aico:performance`)" and legal runs the `aico:eu-compliance` scope check; report section "Performance".
- `launch` — step 2 adds `aico:localizer` after marketer/writer if more than one language; legal also runs the EU scope check.
