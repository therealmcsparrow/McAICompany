# Settings and locks

## In short
`/aico:settings` opens a page in your browser where you change how the company works. Each setting has a plugin default, your own default and a project override. A few settings could skip a safety check, so they start locked and only you can unlock them.

## How it works
1. Run `/aico:settings`. A page opens on your own machine behind a one-time link.
2. Change what you want on the tabs and press Save. A refused Save changes nothing and links to each problem.
3. Press Done, or wait 30 minutes and the page closes by itself.
4. The changes apply from the next aico run.
5. To unlock a locked setting, use the warning on the settings page. **→ Ship Gate** An auto Ship Gate stays locked until you do.

## Technical details
### Settings
[`/aico:settings`](../commands/settings.md) opens a page in your browser where you change how the company works. It has eight tabs, in this order. Messages ("Saved.", or a refused Save) show at the top, under the page header, so you see them on every tab.

- **Roles** — name, model and effort for each Role, with a bulk change per department. Every field has a visible label.
- **Skills** — which third-party skills each Role gets, at most 5 per Role, at user level and at project level. A row lists only skills whose category fits the Role, with the skill's source, status, license and vetted date as plain words. The license reads "as stated, not checked", or "no license on record" for a baseline skill with none. The status says what was looked at: `installed` means a folder whose hash matches the scanned one, `installed (name only)` means a folder of that name and proves no version, and `missing`, `not found` and `folder not recognized` mean it is not usable yet. A status is not a safety verdict. A sixth pick for a Role is refused with "Limit reached: a Role can have 5 skills. Clear one first." A name-only skill counts as loadable only from your home folder, and not when the catalog had a read error or warning; a name found in both places reads as project. A project can select skills by name only. A name that is not in your catalog, or not allowed for that Role, is ignored and reported by its field path. Protected Roles ignore project-level skill selections and take your user-level list. Selecting a skill installs nothing: the install runs at the start of a run, after an Install form.
- **Personality** — one collapsible card per Role, grouped by department, with a User and a Project group of fields. Each group names its Role and level, for example "Ava (architect), User level". The fields are three text boxes with an "n of 80 characters" counter, and two lists for Intelligence and Creativity. Under each list you see what the Role is told for the level you pick. A blank box means "not set at this level". Above the cards, **Filter Roles** narrows them by name, Role or department, and a line says "Showing n of N Roles". The filter only hides cards: hidden cards are still saved, and the filter text is never saved. A refused Save puts "Nothing was saved. Fix n field(s):" at the top, with one link per problem. A link opens the right tab and card and puts focus on the field. Nothing is saved from a refused Save.
- **Language & profile** — the aico language and the `.company/project.md` profile fields.
- **Pipeline** — the user-level row Worktrees (`pipeline.worktrees`, `off` or `on`, default `off`), which a project file cannot set (see [Worktrees](parallel-steps.md#worktrees)), Plan review (`pipeline.plan_review`, `off` or `on`, default `off`; see [The fresh reviewer](review.md#the-fresh-reviewer)), the Fix-round limit, the reprompt Question rounds (`reprompt.question_rounds`, 0 to 3, default 1), the Plan check table (`plan_check.policy`: `off`, `warn` or `block`, default `warn`; `plan_check.runs`: 3 to 50, default 5; neither is a lock), parallel or one-at-a-time dispatch, the max context (`pipeline.context_cap`, 60000 to 250000, default 180000, handover at 90%; user level only, a project value is ignored; read when each Step starts), which optional review lanes run (security, compliance, legal, persona, hands-on and accessibility testing), and the brainstorm options: debate style (`brainstorm.debate`) and the film script (`brainstorm.film_script`).
- **Gates** — ask or auto for the Brief, Plan and Ship Gates and for installs.
- **Mods** — on or off and the options for the three [mods](../mods/README.md).
- **Skill scan** — the SkillSpector scan mode (`skillspector.mode`: `no-llm` or `claude_cli`, default `no-llm`). `no-llm` sends no skill text anywhere, but dependency names, versions and ecosystems from a skill's dependency files go to OSV.dev for a vulnerability lookup, plus the ids of any vulnerabilities found. `claude_cli` also sends skill text to Anthropic and counts only from your user settings.

Each setting has three levels, shown side by side: the **plugin** default, your **user** default (`~/.mcsparrow/config.json`) and a **project** override (`.company/settings.json`; profile fields stay in `.company/project.md`). The project wins over the user, and the user wins over the plugin. Changes apply from the next aico run. With nothing set, aico behaves exactly as before.

`inherit` as a model means "use the model of the session you run aico in".

**Settings v4.0 (a breaking change).** Three keys are retired: `pipeline.second_reviewer`, `pipeline.second_reviewer_model` and `pipeline.review_format`. So is the mod id `efficient-browser-use`. A retired key already stored in a settings file is ignored with a note. `settings set` on a retired key and `set-mod efficient-browser-use` are refused, and `settings get` no longer lists them. If a script or a settings file of yours sets one, remove it. One key is new: `pipeline.plan_review` (`off` or `on`, default `off`). Rule slices for builders and search-then-read are unchanged.

The page runs only on your own machine (127.0.0.1) behind a one-time link, and closes when you press Done or after 30 minutes idle. At the start of every run the Lead tells you which project-level overrides are active, so a cloned or client repo can't quietly change how its Roles work.

### Locks
Some settings could skip a safety check, so they start **locked**: auto for the Ship Gate, auto for installs, and switching off the security or compliance review lanes. One mod setting is locked too: Reflect `model` counts only from your user settings (see [Mods](../mods/README.md#locks)). A leftover key of the removed commit-gate mod in a settings file is ignored with a warning on the settings page and refused on save; the first save removes it. The commit guard is now a review rule in aico:review, aico:contracts and aico:security-check. You unlock the Ship Gate, install and review-lane locks on the settings page, behind a warning that says what will no longer ask you. Unlocks count **only from your user settings**: a project file can lock things again but never unlock them, so a repo you clone can't turn on auto-push or skip security review on your machine. If a project's settings file is broken, its locks hold anyway.
